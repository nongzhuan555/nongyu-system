- 不覆盖教务 / 二课代理、课表 CRUD；埋点 HTTP 联调见 [`../nongyu-rn-app/联调指南-埋点.md`](../nongyu-rn-app/联调指南-埋点.md)

### 2.2 环境变量

在 `apps/nongyu-node-server/` 复制 `.env.example` → `.env`（**勿提交真实口令**）：

| 变量                            | 联调要点                                                                                                       |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `PORT`                          | 默认 `3000`                                                                                                    |
| `MYSQL_*`                       | 指向联调库；与测试库可共用或分开                                                                               |
| `JWT_SECRET`                    | 必须足够长；更换后全部旧 Token 失效                                                                            |
| `JWT_APP_TTL` / `JWT_ADMIN_TTL` | 默认 `30d` / `7d`                                                                                              |
| `BCRYPT_COST`                   | 默认 `10`                                                                                                      |
| `BUSINESS_TZ`                   | 大屏「今日新增」等业务日，默认 `Asia/Shanghai`                                                                 |
| `INTERNAL_TOKEN`                | Track 回写在线态；≥16 字符，与 Track `NODE_INTERNAL_TOKEN` 对齐                                                |
| `TRACK_BASE_URL`                | 代理 `/api/admin/track/*`；默认 `http://127.0.0.1:8082`；Token 用 `INTERNAL_TOKEN` 对齐 Track `INTERNAL_TOKEN` |

集成测试另用 `.env.test`（同样 gitignore）。

### 2.3 迁移

首次或 schema 变更后：

```bash
# 仓库根目录
pnpm --filter nongyu-node-server migrate
```

迁移脚本读取 `.env` 并执行 `apps/nongyu-node-server/migrations/`。

### 2.4 启动服务

```bash
# 仓库根目录（watch 模式，改代码自动重启）
pnpm --filter nongyu-node-server dev
```

日志出现 `nongyu-node-server listening` 且 `port: 3000` 即就绪。

### 2.5 探活

```bash
curl -s http://127.0.0.1:3000/health
```

期望：

```json
{ "code": 0, "message": "ok", "data": { "status": "ok", "db": "up" } }
```

- `db: "down"`：检查 MySQL 连通性、库名、账号权限、安全组 / `bind-address`
- HTTP 连不上：确认进程已起、端口未被占用

### 2.6 跨局域网联调（开发期临时隧道）

同网可用局域网 IP（§3.1）。**手机与电脑不在同一局域网**时，开发环境推荐 **Cloudflare Quick Tunnel**（免费、免账号命名隧道；URL 每次重启会变）。

**前置**：本机 Node 已在 `3000` 监听（§2.4 / §2.5）。

**安装（Windows，一次即可）**：

```bash
winget install --id Cloudflare.cloudflared -e --accept-package-agreements --accept-source-agreements
```

可执行文件常见路径：`C:\Program Files (x86)\cloudflared\cloudflared.exe`（若未进 PATH，用全路径调用）。

**启动隧道**（需常驻；与 `pnpm dev` 并列开着）：

```bash
# 将本机 3000 映射为公网 HTTPS
"C:\Program Files (x86)\cloudflared\cloudflared.exe" tunnel --url http://127.0.0.1:3000
```

日志中会出现类似：

```text
https://<随机子域>.trycloudflare.com
```

探活：

```bash
curl -s https://<随机子域>.trycloudflare.com/health
```

期望与本地探活相同（`code=0`，`db=up`）。

**客户端**：

| 端             | 配置                                                                                                   |
| -------------- | ------------------------------------------------------------------------------------------------------ |
| RN             | `EXPO_PUBLIC_API_BASE_URL=https://<随机子域>.trycloudflare.com`（无尾斜杠）；改完重启 Metro / 重开 App |
| Admin / Apifox | Base URL 同上                                                                                          |

**约束（开发专用）**：

- 须同时保持 **Node** + **cloudflared** 进程；任一退出则公网不可达
- 每次重新执行 `tunnel --url` 通常会得到**新 URL**，客户端配置需同步更新
- 免费临时隧道无 SLA，仅联调；**禁止当作生产入口**
- `CORS_ORIGIN=*` 时浏览器跨域一般可用；若遇预检失败再收紧/排查 Origin

## 3. Base URL 与通用约定

### 3.1 地址

| 客户端                 | Base URL                               | 说明                                                                 |
| ---------------------- | -------------------------------------- | -------------------------------------------------------------------- |
| 本机 curl / Admin 本机 | `http://127.0.0.1:3000`                | 无尾斜杠                                                             |
| RN 模拟器 / 本机 Expo  | 默认同左；见 §7                        | `EXPO_PUBLIC_API_BASE_URL`                                           |
| 真机 / 局域网设备      | `http://<开发机局域网IP>:3000`         | 手机与电脑同网；防火墙放行                                           |
| 跨网真机 / 异地联调    | `https://<随机子域>.trycloudflare.com` | 开发期临时隧道（§2.6）；生产见 `部署与发布.md`（`https://<公网IP>`） |

路径前缀：

- 探活：`GET /health`（**无** `/api`）
- 学生端：`/api/app/...`
- 管理端：`/api/admin/...`

### 3.2 请求 / 响应

- `Content-Type: application/json; charset=utf-8`
- 响应字段 **camelCase**；时间 **ISO-8601 UTC**
- 每个响应带 `x-request-id`（可主动传入同名请求头便于追踪）

统一响应包：

```ts
type ApiResponse<T> = {
  code: number; // 0 成功；非 0 业务/校验错误
  message: string;
  data: T | null;
};
```

**重要**：业务失败**不会**统一用 HTTP 200；须同时看 **HTTP 状态码** 与 body.`code`。

### 3.3 HTTP 与业务错误码

| HTTP | code                        | 含义                               |
| ---- | --------------------------- | ---------------------------------- |
| 200  | `0`                         | 成功                               |
| 400  | `40001`                     | 参数校验失败 / 登录限流文案等      |
| 401  | `40101`                     | 未认证（缺/非法 `Authorization`）  |
| 401  | `40102`                     | Token 无效或已失效（含顶号、登出） |
| 403  | `40301`                     | 账号已禁用                         |
| 403  | `40302`                     | 需要管理员权限 / 无权操作          |
| 403  | `40303`                     | 管理员密码错误                     |
| 404  | `40401` / `40402` / `40403` | 用户 / 帖子 / 版本不存在           |
| 500  | `50000`                     | 未捕获服务端错误                   |

登录限流：`POST .../auth/login` 每 IP **15 分钟最多 60 次**；超限 HTTP 400 + `40001`。

分页：`page` 从 1；`pageSize` 默认 20，最大 **100**。

鉴权头：

```http
Authorization: Bearer <jwt>
```

## 4. 鉴权模型（联调必读）

### 4.1 App JWT

- Claims：`uid`、`studentNo`、`tokenVersion`、`typ: "app"`、`deviceId`
- **不接收教务密码**：RN 本地完成教务登录后，仅把档案 + 设备信息交给 Node
- **每次已存在用户登录成功**都会 `token_version += 1` 并更新 `current_device_id` → **同设备再次登录也会使旧 Token 失效**
- 登出同样 bump `token_version`，`is_online = 0`
- 若库中 `current_device_id` 非空，请求中的 Token `deviceId` 必须一致，否则 `40102`

### 4.2 Admin JWT

- Claims：`uid`、`studentNo`、`role: 1`、`typ: "admin"`
- **不踢号**（不依赖 `token_version`）；多端可同时有效
- 登出服务端无黑名单：客户端丢弃 Token 即可

### 4.3 App vs Admin 不可混用

用 App Token 调 `/api/admin/*`，或用 Admin Token 调需 App 鉴权的接口 → 通常 `40102`（类型不匹配）。

## 5. 测试账号与种子数据

本服务**无内置种子账号**。联调按下列方式自建。

### 5.1 学生端账号（推荐）

直接调用登录即注册（学号须 **恰好 9 位数字**）：

```bash
curl -s -X POST http://127.0.0.1:3000/api/app/auth/login \
  -H "Content-Type: application/json" \
  -d "{\"studentNo\":\"202300001\",\"name\":\"联调学生\",\"college\":\"信息工程学院\",\"gender\":1,\"deviceId\":\"dev-device-001\"}"
```

记下 `data.token`。可重复调用制造「顶号」场景。

建议联调学号段（避免与真实同学冲突）：`202399001`–`202399099`。

### 5.2 首个管理员（冷启动）

管理端升权接口本身需要 Admin JWT，因此**第一个管理员**需直接改库：

1. 先用 §5.1 注册该学号用户
2. 生成 bcrypt 哈希（cost 与 `.env` 的 `BCRYPT_COST` 一致，默认 10）：

```bash
# 在 apps/nongyu-node-server 目录
node --input-type=module -e "import bcrypt from 'bcryptjs'; console.log(await bcrypt.hash('AdminPass1', 10))"
```

3. 在 MySQL 执行（把 `<HASH>` 换成上一步输出）：

```sql
UPDATE users
SET role = 1,
    admin_password_hash = '<HASH>'
WHERE student_no = '202300001';
```

4. 管理端登录：

```bash
curl -s -X POST http://127.0.0.1:3000/api/admin/auth/login \
  -H "Content-Type: application/json" \
  -d "{\"studentNo\":\"202300001\",\"adminPassword\":\"AdminPass1\",\"loginType\":\"browser\"}"
```

### 5.3 后续管理员

已有 Admin Token 后：

1. `PATCH /api/admin/users/:id` 设 `role: 1`
2. `PUT /api/admin/users/:id/admin-password` 设密码（**≥ 8** 位）
3. 再用该学号 + 密码登录

`role` 从 `1`→`0` 会清空 `admin_password_hash`。

### 5.4 自动化测试参考数据

`apps/nongyu-node-server/tests/helpers.ts`：

| 项             | 默认值       |
| -------------- | ------------ |
| App 学号       | `202300001`  |
| 设备           | `device-a`   |
| 提升管理员密码 | `AdminPass1` |

本地跑测：`pnpm --filter nongyu-node-server test`（使用 `.env.test`，会 truncate 测试表，**勿对生产库执行**）。

### 5.5 清空联调数据（慎用）

仅在确认目标库可丢数据时：

```sql
SET FOREIGN_KEY_CHECKS = 0;
TRUNCATE TABLE post_replies;
TRUNCATE TABLE post_reads;
TRUNCATE TABLE posts;
TRUNCATE TABLE user_settings;
TRUNCATE TABLE app_versions;
TRUNCATE TABLE users;
SET FOREIGN_KEY_CHECKS = 1;
```

## 6. 推荐联调顺序与 curl 示例

下列示例假设：

- `BASE=http://127.0.0.1:3000`
- `$APP_TOKEN` / `$ADMIN_TOKEN` 已导出

PowerShell 可先：

```powershell
$BASE = "http://127.0.0.1:3000"
```

### 6.1 健康检查

```bash
curl -s "$BASE/health"
```

### 6.2 App：登录 → me → 设置

```bash
# 登录
curl -s -X POST "$BASE/api/app/auth/login" \
  -H "Content-Type: application/json" \
  -d '{"studentNo":"202399001","name":"联调A","deviceId":"rn-sim-1","college":"信息工程学院","gender":1}'

# 当前用户（把 <APP_TOKEN> 换成上一步 data.token）
curl -s "$BASE/api/app/auth/me" \
  -H "Authorization: Bearer <APP_TOKEN>"

curl -s "$BASE/api/app/settings" \
  -H "Authorization: Bearer <APP_TOKEN>"

curl -s -X PUT "$BASE/api/app/settings" \
  -H "Authorization: Bearer <APP_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{"theme":"dark","homeIsTimetable":true}'
```

### 6.3 App：广场发帖 / 列表 / 详情（计阅读）

```bash
curl -s -X POST "$BASE/api/app/posts" \
  -H "Authorization: Bearer <APP_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{"postType":"courtyard","subtype":"life","title":"联调帖","content":"hello courtyard"}'

curl -s "$BASE/api/app/posts?postType=courtyard&page=1&pageSize=20" \
  -H "Authorization: Bearer <APP_TOKEN>"

# 分类 + 可选标签 + 关键词（title/content 模糊）
curl -s "$BASE/api/app/posts?postType=courtyard&subtype=life&keyword=联调" \
  -H "Authorization: Bearer <APP_TOKEN>"

curl -s "$BASE/api/app/posts/<POST_ID>" \
  -H "Authorization: Bearer <APP_TOKEN>"
```

说明：详情成功会事务递增 `view_count`；首次阅读再增 `unique_reader_count`。App 列表/详情**不返回**阅读量。

#### 6.3.1 App：大院留言 / 反馈墙查看回复

```bash
# 大院帖下留言（仅 courtyard 可留言）
curl -s -X POST "$BASE/api/app/posts/<CY_POST_ID>/comments" \
  -H "Authorization: Bearer <APP_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{"content":"匿名留言内容"}'

# 删除自己的留言
curl -s -X DELETE "$BASE/api/app/posts/<CY_POST_ID>/comments/<COMMENT_ID>" \
  -H "Authorization: Bearer <APP_TOKEN>"

# 反馈墙详情：返回 adminReply（无则 null）
curl -s "$BASE/api/app/posts/<FB_POST_ID>" \
  -H "Authorization: Bearer <APP_TOKEN>"

# 轮询「我的新回复」（30s 一次，返回后置位 notified_author）
curl -s "$BASE/api/app/users/me/post-replies/new" \
  -H "Authorization: Bearer <APP_TOKEN>"
```

#### 6.3.2 Admin：反馈墙回复 / 删除留言

```bash
# 创建反馈墙管理员回复（一对一，已存在返回 409/40901）
curl -s -X POST "$BASE/api/admin/posts/<FB_POST_ID>/reply" \
  -H "Authorization: Bearer <ADMIN_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{"content":"管理员回复正文"}'

# 更新回复（任意管理员可改，不留痕，不重置 notified_author）
curl -s -X PATCH "$BASE/api/admin/posts/<FB_POST_ID>/reply" \
  -H "Authorization: Bearer <ADMIN_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{"content":"更新后内容"}'

# 删除管理员回复
curl -s -X DELETE "$BASE/api/admin/posts/<FB_POST_ID>/reply" \
  -H "Authorization: Bearer <ADMIN_TOKEN>"

# 管理员删除任意用户留言
curl -s -X DELETE "$BASE/api/admin/posts/<CY_POST_ID>/comments/<COMMENT_ID>" \
  -H "Authorization: Bearer <ADMIN_TOKEN>"
```

### 6.4 App：版本检查（公开，无需 Token）

```bash
curl -s "$BASE/api/app/versions/check?platform=android&versionCode=1"
```

### 6.5 Admin：登录 → 发公告 → 大屏

```bash
curl -s -X POST "$BASE/api/admin/auth/login" \
  -H "Content-Type: application/json" \
  -d '{"studentNo":"202300001","adminPassword":"AdminPass1"}'

curl -s -X POST "$BASE/api/admin/posts" \
  -H "Authorization: Bearer <ADMIN_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{"subtype":"system","title":"联调公告","content":"<p>hello</p>"}'

curl -s "$BASE/api/admin/dashboard/overview" \
  -H "Authorization: Bearer <ADMIN_TOKEN>"

curl -s "$BASE/api/admin/dashboard/user-growth?range=7d" \
  -H "Authorization: Bearer <ADMIN_TOKEN>"

curl -s "$BASE/api/admin/track/overview" \
  -H "Authorization: Bearer <ADMIN_TOKEN>"
```

### 6.6 Admin：发布 App 版本

```bash
curl -s -X POST "$BASE/api/admin/app-versions" \
  -H "Authorization: Bearer <ADMIN_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{"platform":"android","versionName":"1.0.1","versionCode":2,"releaseChannel":"native","forceUpdate":false,"isPublished":true,"changelog":"联调版本"}'
```

### 6.7 顶号 / 失效自测

1. 同一 `studentNo` + **不同** `deviceId` 再登录一次
2. 用**旧** `APP_TOKEN` 调 `/api/app/auth/me` → 期望 HTTP 401 + `40102`
3. 同设备再次登录也会 bump version，旧 Token 同样失效

## 7. RN App（`nongyu-rn-app`）对接注意点

### 7.1 Base URL

代码：`apps/nongyu-rn-app/src/config/env.ts`

```ts
process.env.EXPO_PUBLIC_API_BASE_URL || "http://localhost:3000";
```

| 运行环境                        | 建议                                                             |
| ------------------------------- | ---------------------------------------------------------------- |
| Expo Web / 本机模拟且 Node 同机 | 默认即可；或显式 `http://127.0.0.1:3000`                         |
| Android 模拟器访问本机          | 常用 `http://10.0.2.2:3000`（视模拟器而定）                      |
| 真机（同局域网）                | `http://<电脑局域网IP>:3000`，并设 `EXPO_PUBLIC_API_BASE_URL`    |
| 真机（跨网 / 无同网）           | Cloudflare 临时隧道 HTTPS（§2.6），设 `EXPO_PUBLIC_API_BASE_URL` |

重启 Metro / 重开 App 后环境变量才生效。

### 7.2 登录链路

1. RN 内完成教务校验与档案抓取（**教务密码不进 Node**）
2. 调用 `POST /api/app/auth/login`（见 `src/api/appAuth.ts`）
3. 持久化返回的 `token`；后续请求带 `Authorization: Bearer ...`

`deviceId` 优先 Android ID / iOS IDFV；失败则临时生成。联调时注意：**换设备或重新生成 deviceId 会导致旧 Token 失效**。

### 7.3 客户端错误处理建议

- 先看 HTTP status，再解析 body.`code` / `message`
- `40102`：清本地 Token，走重新登录（含教务 + Node）
- `40301`：账号禁用，提示联系管理员
- 登录接口当前实现若只判断 `response.ok`，业务错误已落在非 2xx；其它接口若有包装层，勿把 `code !== 0` 当成功

### 7.4 本版 RN 可联调主路径

| 能力                   | 接口前缀                  |
| ---------------------- | ------------------------- |
| 登录即注册 / me / 登出 | `/api/app/auth/*`         |
| 资料 / QQ              | `/api/app/users/me`       |
| 设置同步               | `/api/app/settings`       |
| 广场                   | `/api/app/posts*`         |
| 版本检查               | `/api/app/versions/check` |

不在本服务：教务业务代理、课表 CRUD。埋点走 Track（[`../nongyu-rn-app/联调指南-埋点.md`](../nongyu-rn-app/联调指南-埋点.md)）。

## 8. Web Admin（`nongyu-web-admin`）对接注意点

| 项       | 说明                                                                                          |
| -------- | --------------------------------------------------------------------------------------------- |
| Base URL | 指向同一 Node 进程，如 `http://127.0.0.1:3000`                                                |
| 登录     | `POST /api/admin/auth/login`；需用户已是 `role=1` 且已设管理员密码                            |
| Token    | 仅 Admin JWT；与 App Token 隔离存储                                                           |
| CORS     | 开发期 `.env` 中 `CORS_ORIGIN=*` 通常足够；若浏览器预检失败，检查 Origin 是否被拦             |
| 升权顺序 | 先 `PATCH` role，再 `PUT .../admin-password`（不可同一次 PATCH 设密）                         |
| 公告     | 仅 Admin 可发；App 端 `postType` 仅允许 `feedback` \| `courtyard`                             |
| 大屏     | `/api/admin/dashboard/*` 本库指标；`/api/admin/track/*` 埋点指标；业务日受 `BUSINESS_TZ` 影响 |

## 10. 常见问题排查

| 现象                    | 可能原因                                       | 处理                                          |
| ----------------------- | ---------------------------------------------- | --------------------------------------------- |
| `/health` 的 `db: down` | MySQL 不可达 / 库名错 / 账号无权限             | 查 `.env`、连通性、云库白名单                 |
| 连接被拒                | 服务未起或端口占用                             | 看终端 listening 日志；换 `PORT`              |
| App 登录 `40001` gender | 非法 gender 字符串                             | 仅用 `0                                       | 1   | 2`/`男 | 女  | 未知` 等约定值 |
| App 登录学号失败        | 非 9 位数字                                    | 补齐/修正学号                                 |
| 突然 `40102`            | 再次登录顶号、登出、换 device、改 `JWT_SECRET` | 重新登录拿新 Token                            |
| Admin 登录 `40401`      | 用户从未 App 登录过                            | 先 App 登录注册                               |
| Admin `40302`           | `role !== 1`                                   | 按 §5.2 / §5.3 升权                           |
| Admin `40303`           | 密码错或无哈希                                 | 重设 `admin_password_hash` 或走 password 接口 |
| RN 真机连不上           | 用了 `localhost`                               | 同网改局域网 IP + 防火墙；跨网用 §2.6 隧道    |
| 隧道 URL `/health` 失败 | Node 或 cloudflared 未起 / URL 已过期          | 确认双进程；重开隧道并更新客户端 Base URL     |
| 预检 CORS 失败          | Origin 未放行                                  | 开发期 `CORS_ORIGIN=*`                        |
| 登录频繁失败            | 命中限流                                       | 换 IP 或等 15 分钟窗口                        |

联调带上响应头 `x-request-id` 便于对照服务端日志。
