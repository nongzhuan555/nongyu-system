## 1. 背景与目标

### 1.1 背景

`nongyu-node-server` 为农屿单体业务后端，同时服务：

- `nongyu-rn-app`（学生端）
- `nongyu-web-admin`（管理端）

本服务**不校验教务密码**：学生端在 RN 内完成教务登录与个人信息抓取后，再调用 Node 完成「登录即注册 / 签发 Token」。管理端使用农屿管理员密码鉴权。

### 1.2 目标

- 统一双端鉴权、用户档案与设置同步
- 支撑广场（公告 / 反馈墙 / 大院）与阅读覆盖率
- 支撑 App 版本检查与管理端版本发布
- 支撑管理端用户管理与大屏「本库可算」业务指标

### 1.3 非目标（本版不提供）

| 范围                            | 说明                                       |
| ------------------------------- | ------------------------------------------ |
| 心跳 / 在线态刷新接口           | 本期不做；在线态仅在 App 登录/登出路径维护 |
| 埋点 / DAU / 行为 / 性能 / 崩溃 | 归 `nongyu-go-track-server`                |
| 课表 CRUD                       | 课表领域表后置                             |
| 教务 / 二课业务代理             | 客户端直连或后续单独接口集                 |
| Agent 会话                      | 不落本库                                   |
| 管理员登录日志落库              | `loginType` 仅请求语义，不落库             |

## 2. 通用约定

### 2.1 Base URL 与路径

- 业务前缀：`/api`
- 学生端：`/api/app/...`
- 管理端：`/api/admin/...`
- 探活：`GET /health`（无 `/api` 前缀）
- Content-Type：`application/json; charset=utf-8`
- 时间字段：响应均为 **ISO-8601 UTC**（如 `2026-08-12T01:00:00.000Z`）
- JSON 字段：**camelCase**（库表 snake_case 由服务端映射）
- 响应头：每个请求回写 `x-request-id`（可主动传入同名请求头）

### 2.2 统一响应包

```ts
type ApiResponse<T> = {
  code: number; // 0 = 成功；非 0 = 业务/校验错误
  message: string;
  data: T | null;
};
```

成功：`{ "code": 0, "message": "ok", "data": ... }`  
失败：`{ "code": <非0>, "message": "...", "data": null }`

### 2.3 HTTP 状态码（已固定）

业务失败**不**用 HTTP 200 承载；一律按下列状态码 + `code`：

| HTTP | 场景                                                  |
| ---- | ----------------------------------------------------- |
| 200  | 成功（`code === 0`）                                  |
| 400  | 参数校验失败（`40001`）；登录限流亦返回本形态         |
| 401  | 未认证 / Token 无效或已失效（`40101` / `40102`）      |
| 403  | 无权限 / 账号禁用 / 管理员密码错误（`40301`–`40303`） |
| 404  | 资源不存在（`40401`–`40403`）                         |
| 500  | 未捕获服务端错误（`50000`）                           |

### 2.4 业务错误码

| code  | 含义                                                |
| ----- | --------------------------------------------------- |
| 0     | 成功                                                |
| 40001 | 参数校验失败（含学号格式、非法 gender、限流文案等） |
| 40101 | 未认证（缺少/非法 `Authorization`）                 |
| 40102 | Token 无效或已失效（含登录顶号、登出后旧 Token）    |
| 40301 | 账号已禁用                                          |
| 40302 | 需要管理员权限 / 无权操作（含学生删非本人帖）       |
| 40303 | 管理员密码错误                                      |
| 40401 | 用户不存在                                          |
| 40402 | 帖子不存在                                          |
| 40403 | 版本记录不存在                                      |
| 50000 | 服务器内部错误                                      |

### 2.5 鉴权

```http
Authorization: Bearer <jwt>
```

#### App JWT

- Claims：`uid`、`studentNo`、`tokenVersion`、`typ: "app"`、`deviceId`
- 校验：签名有效；`typ === "app"`；`users.status === 1`；`users.token_version === tokenVersion`；若 `users.current_device_id` 非空，则须等于 `deviceId`
- **每次已存在用户 App 登录成功**都会：`token_version += 1`、更新 `current_device_id` 与设备字段 → **同设备再次登录也会使旧 Token 失效**
- 新用户首次登录：`token_version` 初始为 `1`
- 登出：`token_version += 1`，`is_online = 0`
- 默认 TTL：环境变量 `JWT_APP_TTL`（默认 `30d`）

#### Admin JWT

- Claims：`uid`、`studentNo`、`role: 1`、`typ: "admin"`
- 校验：签名有效；`typ === "admin"`；`users.role === 1`；`users.status === 1`
- **不踢号**：不依赖 `token_version`；多端可同时持有有效 Admin JWT
- 默认 TTL：`JWT_ADMIN_TTL`（默认 `7d`）

### 2.6 登录限流

`POST /api/app/auth/login` 与 `POST /api/admin/auth/login`：每 IP **15 分钟最多 60 次**。超限返回 HTTP 400，`code: 40001`，`message: 登录尝试过于频繁，请稍后再试`。

### 2.7 分页

| 参数       | 类型   | 默认 | 说明                       |
| ---------- | ------ | ---- | -------------------------- |
| `page`     | number | 1    | 从 1 开始                  |
| `pageSize` | number | 20   | 最大 **100**（超出按 100） |

```ts
type PageResult<T> = {
  list: T[];
  total: number;
  page: number;
  pageSize: number;
};
```

### 2.8 枚举与映射

| 字段                  | 值                                                              |
| --------------------- | --------------------------------------------------------------- |
| `gender`              | `0` 未知 / `1` 男 / `2` 女                                      |
| `role`                | `0` 普通用户 / `1` 管理员                                       |
| `status`              | `1` 正常 / `0` 禁用                                             |
| `postType`            | `announcement` / `feedback` / `courtyard`                       |
| `loginType`           | `browser` / `in_app`                                            |
| `platform`            | `ios` / `android` / `all`（版本检查 Query 仅 `ios`\|`android`） |
| `releaseChannel`      | `silent_ota` / `native`                                         |
| `theme`               | `sicau_green` / `sakura_pink` / `dark` / `system`               |
| `courseCardColorMode` | `distinct` / `unified`                                          |

**App 登录 `gender` 入参**：允许 `0|1|2` 或 `"0"|"1"|"2"|"男"|"女"|"未知"`。  
未传 / `null` / `""` → 落库 `0`。  
其它非法值 → **400 + 40001**（`gender 无效`），不会静默落 0。

**帖子 `subtype`**：实现侧校验为非空字符串、`≤32`；**不强制**文档历史上的枚举名单（`system`/`feedback`/`bug` 等由客户端约定即可）。

## 3. 核心业务流程

### 3.1 App 登录即注册

```text
RN 教务校验通过并抓取档案
  → POST /api/app/auth/login（档案 + 设备信息；不传教务密码）
  → 无用户则 INSERT + 默认 user_settings；有则刷新档案/设备并 bump tokenVersion
  → 签发 App JWT
```

- 未知字段（如 `role` / `status` / `adminPassword`）会被忽略（Zod strip）
- `qq`：库中已有非空值则**不覆盖**；库空时可用请求体写入
- 新用户同时创建默认 `user_settings` 行

### 3.2 管理端登录

```text
POST /api/admin/auth/login（studentNo + adminPassword [+ loginType]）
  → 用户不存在 40401
  → role !== 1 → 40302
  → status !== 1 → 40301
  → 密码不匹配 / 无哈希 → 40303
  → 签发 Admin JWT；loginType 仅回显
```

### 3.3 广场阅读量

打开 `GET /api/app/posts/:id` 成功时（事务）：

1. `posts.view_count += 1`
2. 若 `(post_id, user_id)` 首次写入 `post_reads`：再 `unique_reader_count += 1`
3. 覆盖率（管理端）= `unique_reader_count / COUNT(users)`

App 列表/详情**不返回**阅读量；「我的帖子」返回 `viewCount`。

### 5.4 广场

```ts
type PostListItem = {
  id: number;
  postType: "announcement" | "feedback" | "courtyard";
  subtype: string;
  title: string;
  contentPreview: string; // 去 HTML 标签后截断约 120 字
  publishedAt: string;
  authorDisplayName?: string | null; // feedback 固定 null；courtyard 为作者名；announcement 不返回有意义姓名
};

type PostDetail = {
  id: number;
  postType: "announcement" | "feedback" | "courtyard";
  subtype: string;
  title: string;
  content: string;
  publishedAt: string;
  authorDisplayName?: string | null;
  isMine: boolean;
};
```

#### `GET /api/app/posts`

**鉴权**：App JWT  
**Query**：`postType`（必填）、`page`/`pageSize`、`subtype?`（精确）、`keyword?`（可选，见下）  
排序：`publishedAt DESC`  
**成功 `data`**：`PageResult<PostListItem>`

**`keyword`（广场搜索）**：

- 未传 / 空白（trim 后空）：行为与无关键词列表一致
- 有值：trim 后长度 **1–64**；对 `title`、`content` 做转义后的 `LIKE %kw%`（两字段 OR），再与 `postType` / `subtype` **AND**
- 非法长度 → HTTP 400，`code: 40001`
- 软删帖永不返回；不跨分类（`postType` 仍必填）
- 规格：`docs/nongyu-node-server/specs/广场帖子搜索.md`

#### `GET /api/app/posts/announcements/latest`

**鉴权**：App JWT  
**成功 `data`**：`{ id, title, subtype, publishedAt } | null`

#### `GET /api/app/posts/:id`

**鉴权**：App JWT  
成功打开即计阅读（§3.3）；**不返回** `viewCount` / `uniqueReaderCount`  
**成功 `data`**：`PostDetail`

#### `POST /api/app/posts`

**鉴权**：App JWT  
**请求体**：

| 字段       | 必填 | 说明                         |
| ---------- | ---- | ---------------------------- |
| `postType` | 是   | 仅 `feedback` \| `courtyard` |
| `subtype`  | 是   | 1–32 字符                    |
| `title`    | 是   | 1–200                        |
| `content`  | 是   | 非空                         |

**成功 `data`**：`{ id: number }`

#### `DELETE /api/app/posts/:id`

**鉴权**：App JWT  
作者软删自己的 `feedback`/`courtyard`。  
非作者或公告 → HTTP 403，`code: 40302`，`message: 无权删除该帖子`  
**成功 `data`**：`null`

#### `GET /api/app/users/me/posts`

**鉴权**：App JWT  
**Query**：`page`/`pageSize`；可选 `postType=feedback|courtyard`（不传则两类都查，不含公告）  
**成功 `data`**：`PageResult<PostListItem & { viewCount: number }>`

## 8. 与实现相关的对接注意

1. **App 每次登录都会使旧 App JWT 失效**（含同设备重登），客户端须始终使用最新 `token`。
2. 业务错误看 **HTTP 状态 + `code`**，不要假设失败也是 200。
3. 管理端升管理员：先 `PATCH role=1`，再 `PUT .../admin-password`（密码 ≥8）。
4. 版本 `DELETE` = 下架，记录仍在列表中（`isPublished=false`）。
5. 大屏「今日」按 `BUSINESS_TZ`（默认上海）日历日统计。
