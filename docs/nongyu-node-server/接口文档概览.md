# nongyu-node-server 接口文档概览

> 状态：**待评审确认**（评审通过后作为 Node 实现契约）  
> 需求归类：基建需求  
> 依据：`数据库设计文档.md`、相关 PRD、`old-code` 登录链路对照  
> 服务：同一 Node 进程；路径前缀语义区分双端（`/api/app/*` 学生端，`/api/admin/*` 管理端）

---

## 1. 背景与目标

### 1.1 背景

`nongyu-node-server` 为农屿单体业务后端，同时服务：

- `nongyu-rn-app`（学生端）
- `nongyu-web-admin`（管理端）

本库不校验教务密码：学生端在 RN 内完成教务登录与个人信息抓取后，再调用 Node 完成「登录即注册 / 签发 Token」。管理端使用农屿管理员密码鉴权。

### 1.2 目标

- 统一双端鉴权、用户档案与设置同步
- 支撑广场（公告 / 反馈墙 / 大院）与阅读覆盖率
- 支撑 App 版本检查与管理端版本发布
- 支撑管理端用户管理与大屏「本库可算」业务指标

### 1.3 非目标（本版不提供接口）

| 范围                                | 说明                                                          |
| ----------------------------------- | ------------------------------------------------------------- |
| 心跳 / 在线态刷新                   | **本期不做**；后续由你出方案后再定（实现前再向你确认）        |
| 埋点上报 / DAU / 行为 / 性能 / 崩溃 | 归 `nongyu-go-track-server`                                   |
| 课表 CRUD                           | 课表领域表后置                                                |
| 教务 / 二课业务代理                 | 客户端直连或后续单独接口集                                    |
| Agent 会话                          | 不落本库、不提供会话接口                                      |
| 管理员登录日志落库                  | 已移除 `admin_login_logs`；`loginType` 仅请求语义区分，不落库 |

## 2. 通用约定

### 2.1 Base URL 与路径

- 建议前缀：`/api`
- 学生端：`/api/app/...`
- 管理端：`/api/admin/...`
- Content-Type：`application/json; charset=utf-8`
- 时间：请求/响应时间字段均为 **ISO-8601 UTC**（与库 `DATETIME(3)` UTC 约定一致）
- JSON 字段命名：**camelCase**（与库表 snake_case 由服务端映射）

### 2.2 统一响应包

```ts
type ApiResponse<T> = {
  code: number; // 0 = 成功；非 0 = 业务错误
  message: string; // 人类可读说明
  data: T | null;
};
```

成功示例：

```json
{ "code": 0, "message": "ok", "data": {} }
```

失败示例：

```json
{ "code": 40001, "message": "学号格式不正确", "data": null }
```

### 2.3 HTTP 状态码

| HTTP | 使用场景                                                                               |
| ---- | -------------------------------------------------------------------------------------- |
| 200  | 业务成功或可预期业务失败（看 `code`）                                                  |
| 400  | 参数校验失败（亦可 200 + 业务码，实现时二选一需固定；**推荐参数错误用 400 + 业务码**） |
| 401  | 未登录 / Token 无效 / 被踢下线                                                         |
| 403  | 已登录但无权限（非管理员、账号禁用等）                                                 |
| 404  | 资源不存在                                                                             |
| 409  | 冲突（如单设备策略相关，可选）                                                         |
| 500  | 未捕获服务端错误                                                                       |

### 2.4 业务错误码（建议）

| code  | 含义                                 |
| ----- | ------------------------------------ |
| 0     | 成功                                 |
| 40001 | 参数校验失败                         |
| 40101 | 未认证                               |
| 40102 | Token 无效或已失效（含单设备踢下线） |
| 40301 | 账号已禁用                           |
| 40302 | 需要管理员权限                       |
| 40303 | 管理员密码错误                       |
| 40401 | 用户不存在                           |
| 40402 | 帖子不存在                           |
| 40403 | 版本记录不存在                       |
| 50000 | 服务器内部错误                       |

### 2.5 鉴权

请求头：

```http
Authorization: Bearer <jwt>
```

#### App JWT（学生端）

- Claims（最低集）：`uid`（users.id）、`studentNo`、`tokenVersion`、`typ: "app"`、`deviceId`
- 校验：JWT 签名有效；`typ === "app"`；`users.status === 1`；`users.token_version === tokenVersion`；建议同时校验 `current_device_id === deviceId`
- **单设备**：新设备登录成功时 `token_version += 1` 并更新 `current_device_id`，旧 JWT 立即失效
- 登出：`token_version += 1`，`is_online = 0`

#### Admin JWT（管理端）

- Claims（最低集）：`uid`、`studentNo`、`role`、`typ: "admin"`
- 校验：JWT 签名有效；`typ === "admin"`；`users.role === 1`；`users.status === 1`
- **不踢号**：管理端可多端同时登录，不依赖 App 的 `token_version` 单设备字段
- 管理员密码仅用于签发 Admin JWT；**不存教务密码**

### 2.6 分页

列表类默认：

| 参数       | 类型   | 默认 | 说明         |
| ---------- | ------ | ---- | ------------ |
| `page`     | number | 1    | 从 1 开始    |
| `pageSize` | number | 20   | 最大建议 100 |

响应：

```ts
type PageResult<T> = {
  list: T[];
  total: number;
  page: number;
  pageSize: number;
};
```

### 2.7 枚举速查

| 字段                   | 值                                                |
| ---------------------- | ------------------------------------------------- |
| `gender`               | `0` 未知 / `1` 男 / `2` 女                        |
| `role`                 | `0` 普通用户 / `1` 管理员                         |
| `status`               | `1` 正常 / `0` 禁用                               |
| `postType`             | `announcement` / `feedback` / `courtyard`         |
| `announcement.subtype` | `system` / `activity`（可扩展）                   |
| `feedback.subtype`     | `feedback` / `suggestion` / `bug`                 |
| `courtyard.subtype`    | 自定义标签字符串（长度限制见接口）                |
| `loginType`            | `browser` / `in_app`                              |
| `platform`             | `ios` / `android` / `all`                         |
| `releaseChannel`       | `silent_ota` / `native`                           |
| `theme`                | `sicau_green` / `sakura_pink` / `dark` / `system` |

性别文本映射（App 登录入参允许传文本，服务端落库为数字）：`男`→1，`女`→2，其余→0。

## 3. 核心业务流程

### 3.1 App 登录即注册（对齐 old-code）

```text
RN: 教务登录校验通过
  → RN: 抓取教务个人信息
  → RN: POST /api/app/auth/login（携带档案 + 设备信息）
  → Node: 假设教务已验证成功（本接口不调教务、不收教务密码）
  → 无用户则 INSERT；有则刷新教务来源字段与设备，签发 App JWT
```

约束：

- 客户端**不得**传 `role` / `status` / `adminPassword`；服务端忽略此类字段
- `qq`：库中为空时可用请求体写入；库中已有值则**不覆盖**（避免冲掉用户自改）
- 新用户同时创建默认 `user_settings` 行

### 3.2 管理端登录

```text
浏览器直开管理端 → 用户输入学号 + 农屿管理员密码 → loginType 缺省 = browser
RN WebView 打开管理端 → URL 带 studentNo、adminPassword、loginType=in_app → 前端填入并登录
→ POST /api/admin/auth/login
→ 校验 role=1 且 admin_password_hash 匹配 → 签发 Admin JWT
```

`loginType`：**请求语义保留**；未传视为 `browser`；本版**不落库**，且**不改变**鉴权/踢号行为。

### 3.3 广场阅读量

打开详情成功时：

1. `posts.view_count += 1`
2. 若 `(post_id, user_id)` 首次出现于 `post_reads`：插入记录且 `unique_reader_count += 1`
3. 覆盖率（管理端展示）= `unique_reader_count / COUNT(users)`（实现时可缓存总用户数）

App 端列表/详情**不展示**阅读量；管理端可展示。

## 4. 学生端接口（`/api/app`）

### 4.1 鉴权

#### `POST /api/app/auth/login`

登录即注册并签发 App JWT。

**鉴权**：无

**请求体**：

| 字段          | 类型             | 必填 | 说明                            |
| ------------- | ---------------- | ---- | ------------------------------- |
| `studentNo`   | string           | 是   | 9 位数字                        |
| `name`        | string           | 是   | 姓名                            |
| `major`       | string           | 否   | 专业                            |
| `college`     | string           | 否   | 学院                            |
| `className`   | string           | 否   | 班级                            |
| `grade`       | string           | 否   | 年级，如 `2023级`               |
| `gender`      | number \| string | 否   | `0/1/2` 或 `男/女`              |
| `hometown`    | string           | 否   | 生源地（旧字段 `origin_place`） |
| `campus`      | string           | 否   | 校区                            |
| `qq`          | string           | 否   | 仅库空时写入                    |
| `deviceId`    | string           | 是   | 当前设备稳定标识                |
| `deviceBrand` | string           | 否   | 品牌                            |
| `deviceModel` | string           | 否   | 型号                            |
| `deviceOs`    | string           | 否   | 如 `Android 13.0.0`             |

**成功 `data`**：

```ts
{
  token: string;
  isNewUser: boolean;
  user: AppUserProfile; // 见 4.2
}
```

**失败**：学号格式错误 `40001`；账号禁用 `40301`。

---

#### `POST /api/app/auth/logout`

主动登出。

**鉴权**：App JWT

**请求体**：无

**行为**：`token_version += 1`，`is_online = 0`（心跳方案未定前，在线态仅在登录/登出路径维护）。

**成功 `data`**：`null`

---

#### `GET /api/app/auth/me`

校验 Token 并返回当前用户（等价轻量会话检查）。

**鉴权**：App JWT

**成功 `data`**：`AppUserProfile`

## 5. 管理端接口（`/api/admin`）

除特别声明外，均需 **Admin JWT**，且 `role === 1`。

### 5.1 鉴权

#### `POST /api/admin/auth/login`

**鉴权**：无

**请求体**：

| 字段            | 类型   | 必填 | 说明                                    |
| --------------- | ------ | ---- | --------------------------------------- |
| `studentNo`     | string | 是   | 9 位学号                                |
| `adminPassword` | string | 是   | 农屿管理员密码                          |
| `loginType`     | string | 否   | `browser` \| `in_app`；缺省 = `browser` |

**行为**：

1. 查用户；不存在 → `40401`（提示先在 App 登录注册）
2. `role !== 1` → `40302`
3. `status !== 1` → `40301`
4. 校验 `admin_password_hash`；失败 → `40303`
5. 签发 Admin JWT；**不写登录日志表**；`loginType` 仅回显

**成功 `data`**：

```ts
{
  token: string;
  loginType: "browser" | "in_app";
  user: {
    id: number;
    studentNo: string;
    name: string;
    role: 1;
  }
}
```

---

#### `POST /api/admin/auth/logout`

**鉴权**：Admin JWT  
**说明**：管理端无单设备踢号；登出主要为客户端丢弃 Token。服务端可做可选黑名单（本版可不实现，接口保留返回成功即可）。  
**成功 `data`**：`null`

#### `GET /api/admin/auth/me`

**鉴权**：Admin JWT  
**成功 `data`**：当前管理员基本信息

---

### 5.2 用户管理

```ts
type AdminUserListItem = {
  id: number;
  studentNo: string;
  name: string;
  college: string | null;
  grade: string | null;
  campus: string | null;
  role: 0 | 1;
  status: 0 | 1;
  isOnline: boolean;
  lastLoginAt: string | null;
  createdAt: string;
};
```

#### `GET /api/admin/users`

**Query**：`page` / `pageSize`；`keyword`（匹配学号/姓名）；可选 `role` / `status`

**成功 `data`**：`PageResult<AdminUserListItem>`

#### `GET /api/admin/users/:id`

**成功 `data`**：用户详情（含设备字段、设置摘要可选）

#### `PATCH /api/admin/users/:id`

可改：`role`、`status`（及后续扩展的非敏感档案字段，若需要）。

规则：

- 将 `role` 从 `1` 降为 `0` 时：清空 `admin_password_hash`
- 将 `role` 升为 `1` 时：须随后设置管理员密码（可同请求或调下方接口）

#### `PUT /api/admin/users/:id/admin-password`

设置 / 重置农屿管理员密码（目标用户必须 `role === 1`）。

**请求体**：`{ "adminPassword": string }`（长度与复杂度实现时约束，建议 ≥ 8）

**成功 `data`**：`null`

> 首个管理员可通过运维 bootstrap（环境变量/脚本）写入，不在本接口文档展开。

### 5.5 数据大屏（本库指标）

> DAU / 行为 / 使用时长 / 性能 / 崩溃：**本版 Node 不提供**，由 Track 后续对接。

#### `GET /api/admin/dashboard/overview`

**成功 `data`**：

```ts
{
```
