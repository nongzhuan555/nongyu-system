# Spec：广场帖子搜索（分类 / 标签 / 关键词）

> 状态：**已确认并实现**（集成测已通过）  
> 需求归类：**业务需求**  
> 服务：`nongyu-node-server`  
> 关联文档：`docs/nongyu-node-server/接口文档概览.md`、`数据库设计文档.md`  
> 日期：2026-08-14

---

## 1. 背景

广场列表已支持按 `postType`（分类）与 `subtype`（标签）精确筛选，但不支持关键词检索。RN / Admin 联调与产品需要在既定分类（及可选标签）下，用关键词对帖子标题与正文做模糊匹配。

现有数据模型：

| 产品用语    | 字段                | 说明                                      |
| ----------- | ------------------- | ----------------------------------------- |
| 分类        | `posts.post_type`   | `announcement` / `feedback` / `courtyard` |
| 标签        | `posts.subtype`     | VARCHAR(32)，精确匹配                     |
| 标题 / 正文 | `title` / `content` | 关键词模糊匹配目标                        |

本版**不新建**标签表或多标签关联。

---

## 2. 目标

- App、Admin 广场列表支持可选 `keyword`，在分类（及可选标签）约束下对 `title`、`content` 模糊搜索。
- 无 `keyword`（或空白）时行为与现网列表完全一致，保证兼容。
- 响应结构、分页、排序与现网一致，客户端以加 Query 参数为主。

---

## 3. 边界（非目标）

| 非目标                        | 说明                      |
| ----------------------------- | ------------------------- |
| 独立 `/search` 路由           | 扩展现有 list，不新增路径 |
| 新表 / 多标签体系             | 不改 schema、无 migration |
| 跨分类搜索                    | App 仍必填单一 `postType` |
| 标签模糊匹配                  | `subtype` 仅精确相等      |
| `GET /api/app/users/me/posts` | 本版不加 `keyword`        |
| 全文索引 / 分词引擎           | 本版仅用 SQL `LIKE`       |
| 教务 / 埋点 / 课表            | 无关                      |

---

## 4. 详细需求

### 4.1 接口变更

#### `GET /api/app/posts`

| Query               | 必填   | 说明                                                |
| ------------------- | ------ | --------------------------------------------------- |
| `postType`          | **是** | `announcement` \| `feedback` \| `courtyard`（不变） |
| `subtype`           | 否     | 精确匹配（不变）                                    |
| `keyword`           | 否     | 见 §4.2                                             |
| `page` / `pageSize` | 否     | 同现网分页约定                                      |

- 鉴权：App JWT（不变）
- 软删：始终排除 `deleted_at IS NOT NULL`（不变）
- 排序：`published_at DESC`（不变）
- 成功 `data`：`PageResult<PostListItem>`（字段不变）

#### `GET /api/admin/posts`

| Query               | 必填 | 说明                                      |
| ------------------- | ---- | ----------------------------------------- |
| `postType`          | 否   | 精确（不变）                              |
| `subtype`           | 否   | 精确（不变）                              |
| `keyword`           | 否   | 见 §4.2                                   |
| `includeDeleted`    | 否   | 默认 false（不变）；与 keyword 可同时生效 |
| `page` / `pageSize` | 否   | 同现网                                    |

- 鉴权：Admin JWT（不变）
- 成功 `data`：`PageResult<AdminPostItem>`（字段不变）

### 4.2 `keyword` 语义

1. **未传**、空字符串、或 trim 后为空 → 视为未使用关键词，WHERE 不增加标题/正文条件。
2. **有值**：先 `trim`，长度须在 **1–64**（字符）；否则 HTTP 400，`code: 40001`。
3. 匹配条件（与分类、标签等条件 **AND**）：

   ```text
   (title LIKE %kw% OR content LIKE %kw%)
   ```

4. `kw` 中的 SQL `LIKE` 通配符 `%`、`_` 以及转义符本身须转义，按字面量匹配，禁止用户注入通配扩大结果集。
5. 大小写：跟随库表排序规则（`utf8mb4` 常规 CI 校对下多为不区分大小写）；不额外做应用层大小写折叠。
6. `content` 为富文本原文匹配（不去 HTML）；可能匹配到标签名，本版可接受。

### 4.3 筛选组合

所有已生效条件取 **AND**：

```text
[postType?] AND [subtype?] AND [软删规则] AND [keyword 的 title|content OR?]
AND [author 等既有条件，若有]
```

Admin 未传 `postType` 时仍可仅按 `subtype` / `keyword` / 软删规则查询（与现网一致）。

### 4.4 实现约束（指导实现，非新 API）

- 在 `listPosts`（或等价 repo）增加可选 `keyword?: string`；路由层 Zod 校验后传入。
- 同步更新：`接口文档概览.md`、必要的集成测试（至少：无 keyword 回归；有 keyword 命中 title；有 keyword 命中 content；非法过长 keyword → 40001；App 软删不可见）。
- 本版不强制新增 DB 索引；若联调数据量导致明显变慢，后续再评估 `title` 前缀或全文索引（另开需求）。

## 5. 业务流程

```text
客户端打开某分类广场 / 管理端帖子列表
  → 可选选择标签 subtype
  → 可选输入 keyword
  → GET .../posts?...&keyword=...
  → 服务端：校验 → 组装 WHERE（AND）→ 分页 ORDER BY published_at DESC
  → 返回与现网相同的列表包
```

无 keyword 时路径与现网 list 相同。

## 6. 验收标准与测试方案

### 6.1 验收

| #   | 场景                               | 期望                                                                              |
| --- | ---------------------------------- | --------------------------------------------------------------------------------- |
| 1   | App 不传 keyword，仅 postType      | 与改前列表一致                                                                    |
| 2   | App + keyword 仅命中 title         | 返回含该帖；total 正确                                                            |
| 3   | App + keyword 仅命中 content       | 同上                                                                              |
| 4   | App + postType + subtype + keyword | 三者同时满足才返回                                                                |
| 5   | keyword 为 `"  "`                  | 等同未传                                                                          |
| 6   | keyword 长度 > 64                  | 400 + 40001                                                                       |
| 7   | 已软删帖                           | App 永不返回；Admin `includeDeleted=false` 不返回，`true` 可返回且 keyword 仍生效 |
| 8   | keyword 含 `%` / `_`               | 按字面匹配，不扩大为通配                                                          |
| 9   | Admin 不传 postType + keyword      | 可在全类型未删（或按 includeDeleted）结果中搜                                     |
