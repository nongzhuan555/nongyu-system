---

## 1. 背景

`post_replies` 与详情 / 发删留言 / 轮询新回复已落地，但 App 缺少「发出 / 收到」历史列表接口。本期在既有 `appMyPostRepliesRouter`（挂载于 `/api/app/users/me/post-replies`）上新增两个分页 GET，不改表结构。

## 2. 目标

1. 提供「收到的回复」分页列表：当前用户作为**帖子作者**收到的未软删 `admin_reply` + `comment`。
2. 提供「我发出的留言」分页列表：当前用户作为**留言作者**发出的、且帖主为他人的未软删 `comment`。
3. 鉴权、分页、软删过滤、响应包装与既有 App posts 接口一致；SQL 全参数化。
4. 补充单元测试覆盖主路径与过滤边界。

## 3. 边界（非目标）

- 不新建表、不改 `post_replies` 列、不做迁移。
- 不改 `/new` 轮询语义与置位逻辑。
- 不做未读计数接口；不返回留言者 / 管理员实名（App 侧匿名）。
- 不做 Admin 接口变更。
- 不在本接口内实现删除（删除继续走既有 `DELETE /api/app/posts/:id/comments/:commentId`）。

---

## 4. 数据与过滤规则

复用表 `post_replies` + `posts`。

公共过滤（两条列表均适用）：

- `r.deleted_at IS NULL`
- `p.deleted_at IS NULL`
- `JOIN posts p ON p.id = r.post_id`

### 4.1 收到的（received）

- `p.author_user_id = 当前用户`
- `r.kind IN ('admin_reply', 'comment')`
- 排序：`r.created_at DESC, r.id DESC`
- 说明：包含他人对我大院帖的留言，以及管理员对我反馈帖的回复；不包含我自己帖下自己发的留言（若存在，因 `author_user_id` 可等于帖主，**本期仍返回**——产品定义为「帖下发生的回复」；UI 可不区分。更严过滤「排除自留言」**不做**，保持 SQL 简单：凡落在我帖上的未删回复均列出。）

> 澄清对齐备注：用户要的是「他人对我帖子的留言」。为避免把自己对自己帖的留言混进「收到的」，**额外过滤**：`r.author_user_id <> 当前用户`。

最终 received 条件：

- `p.author_user_id = :uid`
- `r.author_user_id <> :uid`
- `r.kind IN ('admin_reply', 'comment')`
- 双方未软删

### 4.2 我发出的（sent）

- `r.author_user_id = 当前用户`
- `r.kind = 'comment'`
- `p.author_user_id <> 当前用户`（仅对他人帖）
- `p.post_type = 'courtyard'`（防御性；正常数据 comment 只挂大院）
- 排序：`r.created_at DESC, r.id DESC`

## 5. API 契约

挂载前缀既有：`/api/app/users/me/post-replies`（`requireAppAuth`）。

分页：`page` / `pageSize` 走既有 `pageParams`（默认 page=1，pageSize=20，上限 100）。

成功包装：既有 `ok(res, { list, total, page, pageSize })`。

### 5.1 `GET /api/app/users/me/post-replies/received`

- 用途：当前用户帖子下收到的回复 / 留言 inbox。
- Query：`page?`、`pageSize?`
- `list` 项：

```ts
{
  replyId: number;
  postId: number;
  postType: "feedback" | "courtyard"; // 来自 posts.post_type；理论上不含 announcement
  postTitle: string;
  kind: "admin_reply" | "comment";
  content: string; // 全文；客户端自行截断摘要
  publishedAt: string; // ISO UTC，取 r.created_at
}
```

- 不返回作者字段。
- 空列表：`list: []`，`total: 0`。

### 5.2 `GET /api/app/users/me/post-replies/sent`

- 用途：当前用户对他人大院帖发出的留言。
- Query：同上。
- `list` 项：

```ts
{
  replyId: number;
  postId: number;
  postType: "courtyard";
  postTitle: string;
  content: string;
  publishedAt: string;
}
```

- 不返回 `kind`（恒为 comment）亦可返回 `kind: "comment"` 以利客户端统一类型；**本期约定返回 `kind: "comment"`**，与 received 字段对齐便于 RN 共用类型。

统一列表项类型（推荐实现）：

```ts
type MyPostReplyListItem = {
  replyId: number;
  postId: number;
  postType: "feedback" | "courtyard";
  postTitle: string;
  kind: "admin_reply" | "comment";
  content: string;
  publishedAt: string;
};
```

sent 恒为 `kind: "comment"`、`postType: "courtyard"`。

### 5.3 错误与鉴权

- 未登录 / 无效票：与既有 App 路由一致（401）。
- Query 非法：Zod 400（与既有列表一致）。
- 无额外业务 4xx（过滤后为空即可）。

### 5.4 路由冲突

- 既有 `GET /new` 保持不变。
- 新增 `GET /received`、`GET /sent`，与 `/new` 并列；**禁止**用通配 `/:id` 抢占。

## 7. 业务流程

```
App 打开「留言与回复」→ Tab 收到的
  → GET .../post-replies/received?page=1
  → 渲染 list；点项 → 客户端跳转帖详情（本 Spec 不定义 RN）

App 切 Tab 我发出的
  → GET .../post-replies/sent?page=1
  → 删留言 → 既有 DELETE .../posts/:postId/comments/:replyId
  → 成功后客户端从列表移除 / 刷新
```

## 8. 验收标准与测试方案

| #   | 场景                   | 期望                                            |

| 7   | 未鉴权                 | 401                                             |
| 8   | `/new` 回归            | 行为与置位不变                                  |

单元测试：在既有 `postReplies` 测试套件中增补上述 1–6、8；用测试库插入 posts + post_replies 断言 JSON。
