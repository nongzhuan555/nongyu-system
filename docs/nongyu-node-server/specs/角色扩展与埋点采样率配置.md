## 1. 背景

RN 埋点 SDK 一期为全量采集。需要支持管理端配置采样率，App 启动时从 Node 拉取并按 session 采样；失败则本进程 100% 采样。

同时 `users.role` 仅 `0/1`，超管靠 `SUPER_ADMIN_STUDENT_NO` 学号比对，无法干净表达「仅超管可改采样率 / 提权管理员」。本需求一并扩展 `role=2`。

---

## 2. 目标

1. `users.role` 扩展为 `0 | 1 | 2`；业务权限以 role 为准。
2. 仅超管（`role=2`）可配置埋点采样率、可将用户在 `0↔1` 间切换。
3. 普通管理员（`role=1`）可管理用户的非 role 字段（沿用现网），不可改他人 role、不可改采样率。
4. App 冷启动拉取采样率；按 session 采样行为类事件；`crash`/`heartbeat` 始终全量；拉取失败降级 100%；请求未返回前事件全量入队且事后不回滚。

---

## 3. 边界（非目标）

| 非目标                       | 说明                           |
| ---------------------------- | ------------------------------ |
| 管理端任命多个 `role=2`      | `2` 仅由超管学号登录/迁移产生  |
| 按用户/设备稳定哈希采样      | 本版 session 随机              |
| 回前台重拉采样率             | 本进程只拉一次                 |
| 失败读本地历史采样率         | 失败一律 100%                  |
| 改 Go Track 入库/再采样      | 上报通道与契约不变             |
| 采样率审计页                 | 表可留 `updated_at`，无独立 UI |
| 大屏统计口径因采样的说明文案 | 后续另开                       |
| 独立技术方案文档             | 已跳过                         |

## 4. 详细需求

### 4.1 角色模型

| 值  | 含义       | 管理端登录 | 改他人 `0↔1` | 改采样率 |
| --- | ---------- | ---------- | ------------ | -------- |
| `0` | 普通用户   | 否         | 否           | 否       |
| `1` | 管理员     | 是         | 否           | 否       |
| `2` | 超级管理员 | 是         | 是           | 是       |

规则：

1. **业务权限唯一真相**：`users.role`（及 Admin JWT 中的真实 `role`）。
2. `SUPER_ADMIN_STUDENT_NO` **仅**用于：识别出厂超管学号、bootstrap 无库登录、默认密码双轨；**不再**用「学号命中」替代 `role===2` 做业务授权（采样率、提权等）。
3. App 登录若学号为超管学号：建档/更新时 **`role` 置为 `2`**（覆盖旧 Spec「置为 1」）。
4. Admin JWT claims.`role` 为库中真实值 `1` 或 `2`；校验「可进管理端」改为 `role IN (1, 2)`。
5. bootstrap 票：无库时仍可发；claims 可带 `role: 2` + `bootstrap: true`；**业务写接口**（含采样率写、改用户 role）仍拒绝 bootstrap（与现网一致，须先 App 建档）。
6. `PATCH` 用户 role：**只允许**目标值为 `0` 或 `1`；**禁止**经 API 写成 `2`。
7. 调用方必须 `role===2` 才能改他人 role；`role===1` 改 role → HTTP 403。
8. 禁止对自己降权/禁用等既有约束保留；额外：不可把最后一个/自己的超管 role 改掉的防护——**本版超管不可被 API 改 role**（目标用户若已是 `2`，拒绝 role patch）。

### 4.2 数据库

#### 4.2.1 `users.role`

- Migration：将 `CHECK (role IN (0, 1))` 改为 `CHECK (role IN (0, 1, 2))`（或等价：删旧约束加新约束）。
- 数据迁移：`UPDATE users SET role = 2 WHERE student_no = <SUPER_ADMIN_STUDENT_NO>`（学号取自运行配置；migration 可用应用启动补丁或 SQL + 文档说明；**推荐**：migration 只改约束，启动时/迁移脚本读 env 执行一次幂等升权）。
- 列注释更新为：`0用户 1管理员 2超级管理员`。

#### 4.2.2 `app_runtime_config`（新表，单行）

| 列                  | 类型        | 约束                              | 说明              |
| ------------------- | ----------- | --------------------------------- | ----------------- |
| `id`                | TINYINT/INT | PK，固定为 `1`                    | 单行哨兵          |
| `track_sample_rate` | TINYINT     | NOT NULL，默认 `100`，CHECK 0–100 | 采样率百分比      |
| `updated_at`        | DATETIME(3) | NOT NULL                          | 更新时间          |
| `updated_by`        | BIGINT NULL | 可选                              | 操作者 `users.id` |

- 迁移插入默认行：`id=1, track_sample_rate=100`。

### 4.3 Node API

统一响应信封与现网一致：`{ code, message, data }`。

#### 4.3.1 App：读采样率

`GET /api/app/track/sample-rate`

| 项          | 要求                                                                    |
| ----------- | ----------------------------------------------------------------------- |
| 鉴权        | App JWT（`requireAppAuth`）                                             |
| 成功 `data` | `{ sampleRate: number }`，整数 0–100                                    |
| 无行/异常   | 服务端仍应返回 100（表默认行保证）；若读库失败 → 5xx，由客户端降级 100% |

#### 4.3.2 Admin：读/写采样率

`GET /api/admin/dashboard/track-sample-rate`  
`PUT /api/admin/dashboard/track-sample-rate`

| 项          | 要求                                                      |
| ----------- | --------------------------------------------------------- |
| 鉴权        | 已建档 Admin（`requireProvisionedAdminAuth`）             |
| GET 授权    | 仅 `role===2`（`role===1` → 403）                         |
| PUT 授权    | 仅 `role===2`                                             |
| PUT body    | `{ sampleRate: number }`，整数，范围 `[0, 100]`，否则 400 |
| 成功 `data` | `{ sampleRate: number }`                                  |

建议错误：

| 场景                          | HTTP       | 语义                                                                                         |
| ----------------------------- | ---------- | -------------------------------------------------------------------------------------------- |
| 非超管读/写采样率             | 403        | 权限不足（可复用 `ADMIN_REQUIRED` 或新增更明确码；实现时与现网错误码风格一致并写进接口文档） |
| 普通管理员改用户 role         | 403        | 同上                                                                                         |
| 试图把 role 设为 2            | 400        | 非法 role                                                                                    |
| 试图改 `role===2` 用户的 role | 403 或 400 | 禁止动超管 role                                                                              |

#### 4.3.3 Admin：用户 role 变更（修订既有）

- `PATCH /api/admin/users/:id` 的 `role`：仍只接受 `0|1`。
- 额外鉴权：若 body 含 `role`，则要求操作者 `role===2`。
- 列表/详情返回的 `role` 类型改为 `0|1|2`；筛选可增加「超级管理员」。
- 大屏「管理员数」等统计：`role IN (1, 2)` 或保持「管理员」仅 `role=1`、另计超管——**本版约定**：管理员计数含 `role IN (1,2)`（超管也是管理员）。

#### 4.3.4 鉴权中间件/辅助

- `isAdminRole(role) => role === 1 || role === 2`
- `isSuperAdminRole(role) => role === 2`
- 所有原 `user.role !== 1` 拒管端处改为 `!isAdminRole(role)`
- 超管专属操作用 `isSuperAdminRole`

### 4.4 Web Admin

#### 4.4.1 数据大屏 · 采样率控件

- 页面：`DashboardPage`（数据大屏）**顶部**、主内容上方，一行低调条：
  - 文案「埋点采样率」
  - 数字输入（整数 0–100）
  - 「保存」按钮
- **仅当**当前登录用户 `role === 2` 时渲染；`role === 1` 或 bootstrap 不展示。
- 进入页面（或控件 mount）时 GET 当前值填入；保存 PUT；成功/失败 Toast。
- 不阻断下方大屏数据加载与刷新。

#### 4.4.2 用户管理

- 角色标签支持：普通用户 / 管理员 / 超级管理员。
- 「设为管理员 / 取消管理员」**仅 `role===2` 可见可点**。
- `role===1` 仍可打开用户详情、改 status 等非 role 操作（与现网一致的部分保留）。
- 列表筛选项增加超级管理员（可选但推荐）。

#### 4.4.3 类型

- 前端 `role: 0 | 1 | 2` 全链路替换原 `0 | 1`（auth store、用户类型、API 类型）。

### 4.5 RN App · Telemetry 采样

模块：`src/modules/telemetry/`（与一期一致）。

#### 4.5.1 拉取

- 时机：Telemetry 初始化且已具备 App JWT 时请求一次 `GET /api/app/track/sample-rate`（经现有 App API base，非 Track base）。
- 本 JS 进程内不因回前台重复请求。
- 成功：得到 `sampleRate`，立即做一次 session 判定：`sampledIn = random() * 100 < sampleRate`（`sampleRate===100` 恒真；`0` 恒假）。
- 失败（无 JWT、网络、超时、非 2xx、解析失败等）：`sampleRate` 视为 100，`sampledIn = true`。**不读 MMKV/本地历史采样率。**

#### 4.5.2 入队门禁

在 `enqueue`（或等价入口）增加：

| `event_type`                                         | 采样率未返回 | 已返回且 `sampledIn=true` | 已返回且 `sampledIn=false` |
| ---------------------------------------------------- | ------------ | ------------------------- | -------------------------- |
| `app_open` / `screen_view` / `button_click` / `perf` | 入队         | 入队                      | **丢弃（不入队）**         |
| `crash` / `heartbeat`                                | 入队         | 入队                      | 入队                       |

（`event_type` 以 `apps/nongyu-rn-app` 现网 `TRACK_EVENT_TYPES` 为准。）

- **不对已入队事件回滚**。
- `presence/offline` 等非 events 通道行为不受采样率影响（登出 offline 仍尽力调用）。

#### 4.5.3 与一期兼容

- 事件字段、Track URL、队列、flush、MMKV 重试逻辑不变。
- 仅增加「是否允许入队」判定与配置拉取。

## 5. 业务流程

### 5.1 超管改采样率

```
超管打开数据大屏
  → GET track-sample-rate（role=2）
  → 展示当前值
  → 修改并保存
  → PUT track-sample-rate
  → 写 app_runtime_config
  → Toast 成功
```

### 5.2 App 采样决策

```
App 启动且已登录
  → Telemetry 初始化
  → 并行：业务事件可能已 enqueue（门禁：采样未就绪 → 全放行）
  → GET /api/app/track/sample-rate
  → 成功：计算 sampledIn；之后行为类按 sampledIn
  → 失败：sampledIn=true（100%）
  → crash/heartbeat 始终 enqueue
  → 上报仍 POST Track /v1/track/events
```

### 5.3 提权管理员

```
超管在用户详情点「设为管理员」
  → PATCH role=1（调用方 role=2）
普通管理员尝试同样操作
  → UI 无入口；API 403
```

### 6.1 角色

## 7. 实现时注意

- 全仓检索 `role === 1` / `0 | 1` / `CHECK (role IN (0, 1))`，按「管理员 = 1|2、超管 = 2」语义修复，避免普管被误拒或超管被当成普通用户。
- RN `session` 持久化 role 类型需允许 `2`（若本地缓存 role）。
- 不改 Go Track。
