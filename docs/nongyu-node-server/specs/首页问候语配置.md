---

## 1. 背景

RN 首页打招呼第二句需可运营配置。本期在 Node 提供数据表、管理端 CRUD API、App 只读接口；Web Admin UI 不做。

**Why**：运营可改问候语，无需发版。  
**What**：`home_greetings` 表 + Admin CRUD（互斥启用）+ App 拉当前启用文案。

---

## 2. 目标

1. 持久化多条问候语；支持启用/禁用；**全局最多一条启用**。
2. Admin（已建档管理员 JWT）可列表、创建、更新、启停、删除。
3. App（App JWT）可读取当前启用文案；无启用时 `data` 为可识别空态，由客户端兜底。
4. 迁移含至少一条默认启用 seed，便于联调。
5. 关键行为有单元/集成测试覆盖。

---

## 3. 边界（非目标）

| 非目标              | 说明                                               |
| ------------------- | -------------------------------------------------- |
| Web Admin 配置页    | 见 `docs/nongyu-web-admin/specs/首页问候语管理.md` |
| 按时段/随机多条启用 | 本期互斥单条启用                                   |
| AI 生成问候         | 不做                                               |
| 公开无鉴权读接口    | App 读须 JWT                                       |

## 4. Grill 共识

| 决策     | 结论                                        |
| -------- | ------------------------------------------- |
| 归类     | 业务                                        |
| 启用语义 | 最多一条 `enabled=1`；启用新的关旧的        |
| App 鉴权 | 需 App JWT                                  |
| 文案上限 | 48 字（trim 后）                            |
| 本期范围 | DB + Admin API + App GET + Web Admin 配置页 |

## 5. 详细需求

### 5.1 数据模型

表名：`home_greetings`

| 列           | 类型                       | 约束 / 说明                  |
| ------------ | -------------------------- | ---------------------------- |
| `id`         | BIGINT AI PK               |                              |
| `message`    | VARCHAR(48) NOT NULL       | 问候语正文，trim 后 1～48 字 |
| `enabled`    | TINYINT NOT NULL DEFAULT 0 | `1` 启用 / `0` 禁用          |
| `created_at` | DATETIME(3)                | 默认当前时间                 |
| `updated_at` | DATETIME(3)                | 更新时刷新                   |

索引建议：

- `KEY idx_home_greetings_enabled (enabled)`（便于取当前启用）

约束语义（应用层保证即可，可不建 DB 唯一约束）：

- 任意时刻 `SUM(enabled=1) ≤ 1`。
- 将某条设为 `enabled=1` 时，同事务内将其余行置 `0`。
- 允许全部禁用（App 走客户端兜底）。

迁移：`007_home_greetings.sql`（序号以仓库现有 migrations 为准顺延）。

Seed（同迁移或紧随其后）：

- 插入一条默认：`message = '祝你今天学习顺利'`，`enabled = 1`。

### 5.2 统一响应

沿用现有 `{ code, message, data }`；成功 `code === 0`。

### 5.3 App API

#### `GET /api/app/home/greeting`

- 鉴权：`requireAppAuth`（Bearer App JWT）。
- 行为：返回当前 `enabled=1` 的一条；无则 `data: null`（仍 `code=0`，`allowNullData`）。

成功有文案：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "id": 1,
    "message": "祝你今天学习顺利"
  }
}
```

无启用：

```json
{
  "code": 0,
  "message": "ok",
  "data": null
}
```

未认证：沿用现有 `40101` 等鉴权错误码。

### 5.4 Admin API

前缀：`/api/admin/home-greetings`  
鉴权：已建档 Admin JWT（与 posts / llm keys 同级；超管 bootstrap 若现网限制写业务，则与现网一致处理）。

#### `GET /api/admin/home-greetings`

查询参数：

| 参数       | 说明                       |
| ---------- | -------------------------- |
| `page`     | 默认 1                     |
| `pageSize` | 默认 20，上限按现网惯例    |
| `enabled`  | 可选 `0` / `1`；不传为全部 |

响应 `data`：

```json
{
  "list": [
    {
      "id": 1,
      "message": "祝你今天学习顺利",
      "enabled": true,
      "createdAt": "ISO-8601",
      "updatedAt": "ISO-8601"
    }
  ],
  "total": 1,
  "page": 1,
  "pageSize": 20
}
```

#### `POST /api/admin/home-greetings`

Body：

| 字段      | 必填 | 说明                                     |
| --------- | ---- | ---------------------------------------- |
| `message` | 是   | trim 后 1～48 字                         |
| `enabled` | 否   | 默认 `false`；若 `true` 则互斥关掉其它条 |

响应：`{ "id": number }`。

#### `PATCH /api/admin/home-greetings/:id`

Body（至少一项）：

| 字段      | 说明                                |
| --------- | ----------------------------------- |
| `message` | 同创建校验                          |
| `enabled` | `true` 时互斥启用；`false` 仅关本条 |

响应：`{ "id": number }`。  
不存在 → 现网统一 Not Found 风格。

#### `DELETE /api/admin/home-greetings/:id`

- 硬删。
- 删除当前启用条后，可不自动启用其它条（允许零启用）。

### 5.5 校验与错误

| 情况         | 期望                       |
| ------------ | -------------------------- |
| `message` 空 | 4xx + 可读 message         |
| 超 48 字     | 4xx + 可读 message         |
| id 不存在    | 404 风格业务码（对齐现网） |

---

## 6. 业务流程

### App 读

```text
App JWT → 查 enabled=1 → 有则返回 {id,message} → 无则 data=null
```

### Admin 启用

```text
开启 A.enabled=true → 事务内：其它全部 enabled=0 → A.enabled=1 → commit
```

---

## 7. 验收标准与测试方案

### 单元 / 集成测试（Node）

1. Seed 后 App GET 返回启用文案。
2. 创建第二条并 `enabled=true` 后，仅新条启用；App GET 为新文案。
3. 全部禁用后 App GET `data=null`。
4. `message` 空 / 超长被拒。
5. 无 App JWT 不可读。
6. 无 Admin JWT 不可写。

### 手工联调

- 用 Admin API 改文案后，App 首页第二句随之变化（RN 侧见配套 Spec）。
