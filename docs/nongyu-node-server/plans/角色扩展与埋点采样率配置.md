## 1. 实施计划

一人交付；顺序 **Node（角色+配置 API）→ Web Admin（大屏控件+用户提权）→ RN（SDK 采样）**。先契约可测，再 UI，最后客户端联调。

| 步骤 | 内容                                                                                        | 风险 / 缓解                                                   |
| ---- | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| 1    | Migration：`users.role` CHECK 扩到 `(0,1,2)`；建 `app_runtime_config` 单行默认 100          | MySQL DROP CHECK 语法因版本而异；先查现网约束名再写 migration |
| 2    | 超管学号幂等升权 `role=2`（启动补丁或 migration 后脚本读 env）                              | env 未配时跳过并打日志，不阻断启动                            |
| 3    | 鉴权/`role` 类型全链路：`isAdminRole` / `isSuperAdminRole`；JWT 真实 role；App 超管登录落 2 | 漏改 `role!==1` 会拒超管或误放；全仓检索                      |
| 4    | Admin/App sample-rate API + users PATCH 提权仅超管 + 单测                                   | 与现有 vitest 风格对齐                                        |
| 5    | Web：大屏顶部采样率条（仅 role=2）；用户管理角色 UI/提权门禁；类型 `0\|1\|2`                | 控件低调，不挡大屏                                            |
| 6    | RN：拉采样率 + enqueue 门禁；失败 100%；请求中全放行不回滚                                  | 不改 Track 上报通道                                           |

**改动面**：`nongyu-node-server`、`nongyu-web-admin`、`nongyu-rn-app` 及对应 docs。

**不做**：独立 Tech 文档、采样率审计页、回前台重拉、本地历史采样率缓存、Go Track 改动、管理端任命 `role=2`。

## 2. 实施步骤

### 2.1 Node（`apps/nongyu-node-server`）

1. **Migration `010_role2_and_track_sample_rate.sql`**
   - 调整 `users.role` CHECK → `(0,1,2)`；注释更新。
   - `CREATE TABLE app_runtime_config`（`id=1` 哨兵、`track_sample_rate` 默认 100、`updated_at`、可选 `updated_by`）。
   - `INSERT` 默认行（幂等）。
2. **启动/迁移后升权**：读取 `SUPER_ADMIN_STUDENT_NO`，将该学号用户 `role` 幂等更新为 `2`。
3. **角色工具**：集中 `isAdminRole` / `isSuperAdminRole`；替换 Admin 登录校验、中间件、统计计数（管理员含 1|2）、zod `0|1` → 必要处扩 `2`。
4. **Auth**：App 超管学号建档/登录强制 `role=2`；Admin JWT 写入真实 `role`；校验 `role IN (1,2)`。
5. **Users Admin API**：`PATCH` 含 `role` 时要求操作者 `role===2`；body `role` 仅 `0|1`；禁止改目标为 `role===2` 的用户之 role。
6. **Sample-rate 模块**（可挂 `dashboard` 或独立 `runtimeConfig`）：
   - `GET/PUT /api/admin/dashboard/track-sample-rate`（provisioned + super）
   - `GET /api/app/track/sample-rate`（app auth）
7. **测试**：role 升权/拒权、sample-rate 读写校验与 403、默认 100。
8. **文档**：`接口文档概览.md`、`数据库设计文档.md` 同步。

### 2.2 Web Admin（`apps/nongyu-web-admin`）

1. 类型：`role: 0 | 1 | 2`；auth/`me` 透传。
2. `DashboardPage` 顶部：采样率输入 + 保存；仅 `user.role===2` 渲染；挂载 GET、保存 PUT。
3. 用户管理：角色标签含超管；设/取消管理员仅超管可见；筛选项可选加 `2`。
4. API client 封装 sample-rate 与类型更新。
5. 视觉：低调一行，遵循 `design-system/web-admin/MASTER.md`，不新开炫技样式。

### 2.3 RN App（`apps/nongyu-rn-app`）

1. `telemetry`：增加 sample-rate 拉取状态机（pending / ready）；session 内 `sampledIn`。
2. `enqueue` 门禁：行为类（`app_open`/`screen_view`/`button_click`/`perf`）在 ready 且 `!sampledIn` 时丢弃；`crash`/`heartbeat` 始终入队；pending 时全入队。
3. 拉取走 Node App API（现有 `API_BASE_URL` + JWT），**不**走 Track base。
4. 失败 → `sampledIn=true`；不写本地采样率缓存。
5. session 持久化 `role` 类型允许 `2`（若有本地缓存）。
6. 不改 Go Track 契约与 transport。

## 3. 注意事项

1. **全仓 `role === 1` 审计**：管理员语义改为 `1|2`，超管专属为 `===2`，避免漏网。
2. **Migration 可重复执行**：约束变更与默认行插入需幂等或可安全重跑。
3. **bootstrap 会话**：无建档超管不可写采样率/改 role（沿用 `requireProvisionedAdminAuth`）。
4. **采样与在线**：`heartbeat`/`presence` 不受采样率影响，避免在线指标被打穿。
5. **专家实现**：编码阶段 Node 用 backend 向、Web/RN 用 frontend 向（按仓库 agents 约定），实现后走 code-reviewer 门禁再 commit（若你要求提交）。
