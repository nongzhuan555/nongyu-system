## 3. 数据库设计

### 3.1 迁移 `009_post_replies.sql`

```sql
CREATE TABLE post_replies (
  id BIGINT NOT NULL AUTO_INCREMENT,
  post_id BIGINT NOT NULL,
  kind VARCHAR(16) NOT NULL,
  author_user_id BIGINT NOT NULL,
  content MEDIUMTEXT NOT NULL,
  notified_author TINYINT(1) NOT NULL DEFAULT 0,
  deleted_at DATETIME(3) NULL,
  created_at DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  updated_at DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
  PRIMARY KEY (id),
  KEY idx_replies_post_kind_created (post_id, kind, created_at),
  KEY idx_replies_author_created (author_user_id, created_at),
  KEY idx_replies_notified (notified_author, post_id),
  CONSTRAINT fk_replies_post FOREIGN KEY (post_id) REFERENCES posts(id) ON DELETE CASCADE,
  CONSTRAINT fk_replies_author FOREIGN KEY (author_user_id) REFERENCES users(id),
  CONSTRAINT chk_replies_kind CHECK (kind IN ('admin_reply','comment'))
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

### 3.2 单条回复约束（应用层）

MySQL 无部分唯一索引，采用事务内 `SELECT ... FOR UPDATE`：

```sql
SELECT id FROM post_replies
WHERE post_id = ? AND kind = 'admin_reply' AND deleted_at IS NULL
FOR UPDATE;
```

存在则 409（创建）/ 404（更新）；不存在则 INSERT / UPDATE。`FOR UPDATE` 行锁保证并发安全。

### 3.3 级联软删

删帖事务内：

```sql
UPDATE post_replies SET deleted_at = UTC_TIMESTAMP(3)
WHERE post_id = ? AND deleted_at IS NULL;
```

## 6. 注意事项

- **并发**：管理员回复创建用 `FOR UPDATE` 行锁；轮询置位用幂等 WHERE。
- **软删过滤**：所有查询 `deleted_at IS NULL`；Admin `includeDeleted` 仅 posts 列表用，回复/留言详情不单独提供含已删视图。
- **N+1**：`GET /api/admin/posts` 的 `replyCount` 用子查询或 `LEFT JOIN ... GROUP BY`，避免逐帖查询。
- **事务边界**：删帖级联、管理员回复 CRUD、轮询置位均走 `withTransaction`。
- **鉴权**：App 用 `requireAppAuth`；Admin 用 `requireProvisionedAdminAuth`（拒绝 bootstrap 票）。
- **SQL 注入**：全参数化，禁止字符串拼接。
- **测试**：`truncateAll` 已清 `post_replies`（需确认 truncate 列表包含新表，否则补 `TRUNCATE post_replies`）。
