## 1. 目标与约束

### 1.1 目标

为农屿单体业务后端提供可长期维护的技术底座，同一进程服务：

- `nongyu-rn-app`（`/api/app/*`）
- `nongyu-web-admin`（`/api/admin/*`）

支撑本期契约：鉴权与用户档案/设置、广场与阅读覆盖率、App 版本、管理端用户与本库大屏指标。

### 1.2 硬约束

- 语言与工程：**TypeScript + ESM**，纳入 monorepo（pnpm workspace）。
- 数据：**MySQL 8（InnoDB / utf8mb4）**；驱动 **`mysql2` 连接池**；时间按 **UTC** 读写（`DATETIME(3)`）。
- 会话：**JWT**（App / Admin 分 `typ`）；**无 Redis、无独立 session 表**；App 单设备靠 `token_version` + `deviceId`。
- API：REST + 统一响应包 `{ code, message, data }`；JSON **camelCase**，库表 **snake_case** 由服务端映射。
- 安全：不存教务密码；管理员密码仅存哈希；密钥与连接串走环境变量。
- 一致性：广场首次阅读更新 `post_reads` 与帖子计数时 **必须使用数据库事务**。
- 阶段：本地开发与同机生产部署并存；生产细则见 `部署与发布.md`。

### 1.3 非目标 / 后置

| 项                               | 说明                                                         |
| -------------------------------- | ------------------------------------------------------------ |
| 服务器部署 / 反向代理 / 进程守护 | 已收口到 `部署与发布.md`（Nginx + systemd；不上 Docker/PM2） |
| Redis / MQ / GraphQL / Nest      | 本期不上                                                     |
| 教务 / 二课业务代理              | 客户端直连或后续接口集                                       |
| 心跳 / 在线态刷新接口            | 接口文档已后置                                               |
| 埋点入库                         | 归 `nongyu-go-track-server`                                  |
| 课表领域 CRUD                    | 库表后置                                                     |

## 2. 工程与运行时

| 项          | 选型                        | 说明                                                 |
| ----------- | --------------------------- | ---------------------------------------------------- |
| 语言        | TypeScript                  | 遵循仓库代码规范                                     |
| 运行时      | Node.js（LTS）              | 本地开发用当前仓库约定的 LTS；生产版本随部署方案再锁 |
| 模块        | ESM（`"type": "module"`）   | 与现有 `package.json` 一致                           |
| HTTP 框架   | **Express 4**               | 延续脚手架；本期体量换 Fastify 收益有限              |
| 开发启动    | `tsx watch`                 | 现有 `dev` 脚本                                      |
| 构建        | `tsup` → ESM                | 现有 `build` 脚本                                    |
| Lint / 格式 | oxlint / oxfmt（仓库统一）  | —                                                    |
| 配置        | `dotenv` + 启动时校验必填项 | 缺关键配置直接失败，避免半残启动                     |

## 3. 应用架构

| 领域       | 选型                            | 说明                                                             |
| ---------- | ------------------------------- | ---------------------------------------------------------------- |
| 进程模型   | **单进程单体**                  | 双端路径前缀区分，不拆微服务                                     |
| 分层       | **按领域 modules**              | `routes` → `service` → `repo`；共享 `middlewares` / `lib`        |
| 校验       | **zod**                         | 请求体 / 查询参数 / 路径参数；与 RN 选型对齐                     |
| 错误模型   | 自定义业务错误 + 统一错误中间件 | HTTP 状态与业务 `code` 对齐接口文档（参数错误推荐 400 + 业务码） |
| 鉴权中间件 | App JWT / Admin JWT 分离        | Claims 与校验规则见接口文档 §2.5                                 |
| 响应       | 统一封装成功 / 失败包           | 禁止各路由自行拼不一致字段名                                     |

### 3.1 建议目录（落地时可微调，原则不变）

```text
apps/nongyu-node-server/src/
  index.ts                 # 监听与优雅退出入口
  app.ts                   # Express 组装
  config/                  # 环境变量解析与校验
  middlewares/             # auth、error、requestId、rateLimit(登录)
  modules/
    auth/
    users/
    settings/
    posts/
    versions/
    dashboard/
  lib/                     # db 池、jwt、password、errors、response、time
  migrations/              # 版本化 SQL（见第 4 节）
```

## 4. 数据访问与迁移

| 项          | 选型                                                    | 说明                                       |
| ----------- | ------------------------------------------------------- | ------------------------------------------ |
| 驱动        | **`mysql2/promise` 连接池**                             | 库表文档已约定；连接串来自环境变量         |
| 访问方式    | **手写 SQL + 薄 Repository**                            | 表少、查询模式清晰；不上 Prisma / Drizzle  |
| Schema 真相 | `数据库设计文档.md` 中的 DDL                            | 实现不得偏离已评审 DDL（变更先改文档）     |
| 迁移        | **版本化 SQL 文件**（`migrations/*.sql`）+ 简单执行约定 | 初版可直接落地完整 DDL；后续增量按序号追加 |
| 事务        | `connection.beginTransaction()`                         | 阅读计数等写路径强制事务                   |
| 命名映射    | repo / service 边界做 snake ↔ camel                     | 对外 API 只暴露 camelCase                  |

本期 **不引入** ORM 与 Redis 缓存层。

## 5. 安全与鉴权实现库

| 项             | 选型                                              | 说明                                                |
| -------------- | ------------------------------------------------- | --------------------------------------------------- |
| JWT            | **`jose`**                                        | 签发 / 校验 App 与 Admin Token                      |
| 管理员密码哈希 | **`bcrypt`**（或 `bcryptjs`，实现时二选一并写死） | 仅 `admin_password_hash`；普通用户该字段必须为 NULL |
| CORS           | `cors` 中间件                                     | 本地开发放行管理端 / 调试源；生产策略随部署再收紧   |
| 登录限流       | **`express-rate-limit`，仅登录相关路由**          | 降低撞库与爆破风险；全局限流本期不做                |

JWT 密钥、Bcrypt cost、Token TTL 等均配置化，禁止硬编码。
