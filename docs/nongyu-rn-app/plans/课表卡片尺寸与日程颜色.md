## 2. 实施步骤

### 2.1 Node（`apps/nongyu-node-server`）

1. 新增 migration `007_schedule_color_index.sql`：
   - `ALTER TABLE custom_schedules ADD COLUMN color_index TINYINT NULL;`
   - `CHECK (color_index IS NULL OR (color_index BETWEEN 0 AND 7))`（若 MySQL 版本允许；否则仅靠 API Zod）
2. `mapper.ts`：`ScheduleRow` / `ScheduleDto` 增加 `color_index` / `colorIndex`；`toScheduleDto` 映射 `null`。
3. `repo.ts`：`insertSchedule` / `updateSchedule` 读写 `color_index`（patch 支持显式 `null` 清色）。
4. `routes.ts`：create/patch Zod 增加  
   `colorIndex: z.number().int().min(0).max(7).nullable().optional()`，传入 repo。

### 2.2 RN 模型与偏好（`apps/nongyu-rn-app`）

1. `coursePrefs.ts`：`COURSE_ROW_HEIGHT.md = 110`，`lg = 130`。
2. `colors.ts`：导出只读色板（如 `COURSE_COLOR_PALETTE`）+ `getPaletteColor(index)`（非法返回 `null`）。
3. `types.ts`：`ScheduleEntry` 增加 `colorIndex?: number | null`。

### 2.3 表单（`ScheduleFormSheet.tsx`）

1. state：`colorIndex: number | null`；新建默认 `0`；编辑回填 `schedule.colorIndex ?? null`；切到新增 target 时重置为 `0`。
2. UI：「默认」芯片 + 8 色块；选中态描边。
3. `handleSave` 写入 `colorIndex`（无色为 `null`）。

### 2.4 卡片（`ScheduleCard.tsx`）

1. 合法 `colorIndex`：用色板 `bg`/`text`，细边用 `text` 浅透明，图标用 `text`。
2. 否则：保持现有 theme 浅底 + brand 边。

### 2.5 同步透传核对

1. 确认 `addSchedule` / `editSchedule` / Outbox / `createScheduleApi` 整对象或 patch 已带 `colorIndex`（类型扩展后通常自动透传；patch 路径需显式包含）。
2. **不改** Agent `courseTools` schema。

### 2.6 文档收尾

1. Spec 状态改为「已实现」（编码完成并自测后）。
2. 若改动触及既有 Spec 数据模型描述，可在 `课表扩展-自定义日程备注待办.md` 补一行 `colorIndex` 字段说明（可选，编码时一并）。

### 2.7 测试用例（人工）

对照 Spec §6：A1–A6、B1–B3、C1–C3。重点：中/大档高度、新建默认色 0、无色、改色持久化、旧数据兼容、非法 API 拒绝。

---

## 3. 注意事项

- patch 清色必须能写 DB `NULL`（勿把 `null` 当成「跳过字段」）。
- 色板只从 `colors.ts` 取，禁止表单/卡片各写一套 hex。
- 有色日程仍须保留「日程」视觉语义（细边 + 日历弱图标）。
- 本地已有无 `colorIndex` 的 JSON：读时按 `undefined` → 无色，勿崩溃。
- Coding 完成后跑 Node migration（开发环境）再测 pull/push。
