> 本计划为三端统一主计划，因需求跨三端且存在依赖顺序（DB → Node → RN/Admin）。

---

## 1. 依赖关系与实施顺序

```
[阶段1] Node: DB 迁移 + ErrorCodes
   ↓
[阶段2] Node: postReplies.repo + routes + 测试
   ↓
[阶段3a] RN: API 封装 + 详情 UI + 列表轮询   ←┐
[阶段3b] Admin: API 封装 + 详情 Drawer + 列表角标 ←┘ 并行
   ↓
[阶段4] 联调 + 文档同步 + lint/type-check/format
```

阶段 3a / 3b 互不依赖，可并行。阶段 2 完成后 RN/Admin 才能联调真实接口（开发期可先用 mock）。

## 4. 风险评估

| 风险                                                             | 等级 | 缓解                                                        |
| ---------------------------------------------------------------- | ---- | ----------------------------------------------------------- |
| `refetchInterval` 项目首次使用，TanStack Query 版本/行为不符预期 | 中   | 阶段 3a 早期先做最小轮询 PoC 验证；必要时降级为 setInterval |
| toast onPress 改动影响现有 toast 调用方                          | 低   | `onPress` 可选，不传保持原行为；改后回归现有 toast 场景     |
| 管理员回复 1:1 并发竞态                                          | 低   | `SELECT ... FOR UPDATE` 行锁兜底；业务低并发                |
| `truncateAll` 未覆盖 `post_replies` 导致测试脏数据               | 中   | 阶段 1.3 显式确认；必要时补 truncate                        |
| 详情联合查询性能（回复+留言一次查）                              | 低   | 单帖数据量小；索引覆盖                                      |
| 轮询 toast 刷屏                                                  | 中   | 服务端置位 + 客户端 seenIdsRef 双重幂等；后台不轮询         |
| 删帖级联遗漏（用户删帖路径）                                     | 中   | 阶段 2.2 显式覆盖 App/Admin 两条删帖路径 + 测试场景 7       |
| Admin 无 React Query，详情态管理易出 loading/error 缺失          | 低   | 对齐既有 PostListPanel 模式；review 把关                    |

## 5. 注意事项

- **文档先行**：每端改动前确认对应 Spec/Tech 已确认；改动中若偏离需先更新文档再改代码（开发规范铁律）。
- **BugLog**：若实现中发现既有 bug，修复后在 `docs/common/BugLog.md` 追加记录。
- **分支**：本需求为业务需求，在对应项目分支开发；通用文档/迁移属基建性质可在主分支，但按规范业务代码须在项目分支。建议三端各自从主分支拉业务分支。
- **不提交 mock Token / 敏感凭证**。
- **Code Review**：commit 前显式调用 `code-reviewer` subagent（开发规范软门禁）。
- **工程化门禁**：每端改动后跑 `pnpm lint` / `type-check` / `format`；commit 触发 husky 硬门禁。
