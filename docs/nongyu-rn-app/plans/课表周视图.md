## 1. 实施计划

| 里程碑 | 内容                                                                             | 风险                                                       |
| ------ | -------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| M0     | 文档状态同步；核对根布局是否已挂 GestureHandler / BottomSheet 所需 Provider      | 低：缺 Provider 则弹层异常                                 |
| M1     | `model/` 纯函数 + mock + repository + UI store（开学日 MMKV）                    | 中：周次边界（周日开学、跨年）                             |
| M2     | Phase 1 UI：WeekPager / WeekGrid / Card / Detail / 开学日选择；替换占位 Tab      | 中：横向+纵向嵌套滚动；初始 `scrollToIndex` 闪烁；底栏遮挡 |
| M3     | Phase 1 对照 Spec §6.1 自测清单打勾                                              | 低                                                         |
| M4     | Phase 2：span 连堂、三字段、动效、回本周 FAB、当日强调与高亮开关、Token 视觉收拢 | 中：连堂高度与行高对齐；FAB 与 TabBar 重叠                 |
| M5     | Phase 2 对照 Spec §6.2；lint / type-check；Spec/Tech/Plan 状态更新               | 低                                                         |

**预计改动面**：`app/(tabs)/course.tsx`、新建 `src/modules/course/**`、必要时 `app/_layout.tsx`（Provider）、`src/storage/mmkv.ts`（课表 key 常量，可选）。

**不改**：教务抓取、自定义课/日程、分享/海报、考试 Tab、背景图、统一配色开关、Node/Go 服务端。

**资源**：单人顺序交付；先 M1–M3 可独立验收，再 M4–M5。

**时间表（相对）**：M1 → M2 为关键路径；M4 依赖 M3 通过。不设日历日，以验收清单为准。

## 2. 实施步骤

### 2.0 前置核对（M0）

1. 读 `app/_layout.tsx`：确认 `GestureHandlerRootView`；`BottomSheetModalProvider` 若缺失则补上。
2. 读 `lightTokens.tabBar`：CourseScreen 底 padding 公式与首页一致。
3. 只读对照旧 `CourseTable` / `semesterDate` / `COURSE_TIMES` / 色板（不复制 Paper）。

### 2.1 领域与数据（M1）

1. `model/types.ts`：`CourseEntry`、`GridCell`（primary / occupied / null）。
2. `model/courseTimes.ts`：10 节次时间（对齐旧版）。
3. `model/colors.ts`：名称哈希 → 色板。
4. `model/semesterWeek.ts`：`computeCurrentWeek`、`getMondayOfWeek`、格式化 `M/D`；未设开学日不生成月日。
5. `model/weekMatrix.ts`：`weekMatches` + `buildWeekMatrix`；Phase 1 可先 `spanRows=1`，接口预留真实 span。
6. `data/mockCourses.ts`：若干跨周、单双周、跨大课区间样例（含至少一门可测连堂的课，供 Phase 2）。
7. `data/courseRepository.ts`：`listCourses()` → mock。
8. `store/courseUiStore.ts`：开学日 /（预留）高亮 / `viewWeekIndex`；MMKV hydrate。
9. （可选）`semesterWeek` / `weekMatrix` 的 `*.test.ts`——有现成 RN 测试脚本才接入，否则跳过不阻塞。

### 2.2 Phase 1 UI（M2）

1. `components/CourseCard.tsx`：色块 + 文案（Phase 1 可略宽于三字段）。
2. `components/WeekGrid.tsx`：表头（有开学日才显示月日）+ 时间列 + 5×7；空格无 `onPress`。
3. `components/WeekPager.tsx`：水平 `FlatList`；`initialScrollIndex` / 首屏定位；同步 `viewWeekIndex`。
4. `components/CourseDetailSheet.tsx`：`@gorhom/bottom-sheet`；基础字段。
5. `components/SemesterStartPicker.tsx`：封装 DateTimePicker。
6. `screens/CourseScreen.tsx`：顶栏 + 加载 courses + 组装上述组件；未设开学日轻提示。
7. `app/(tabs)/course.tsx`：导出 `CourseScreen`，删除 Placeholder。

### 2.3 Phase 1 验收（M3）

按 Spec §6.1 逐项点验；记录问题再进 Phase 2。

### 2.4 Phase 2 升级（M4）

1. `weekMatrix` 启用真实 `spanRows`；`CourseCard` / `WeekGrid` 合并高度。
2. 卡片仅 name / teacher / room；按压反馈。
3. `BackToCurrentWeekFab`：非本周显示；避开 TabBar。
4. 表头当日强调；`highlightTodayColumn` 开关 + MMKV。
5. 详情/卡片动效微调；Token 间距字号圆角收拢（无 design-system 文件时以现有 `lightTokens` + 旧观感为基，克制改动）。

### 2.5 收尾（M5）

1. Spec §6.2 点验。
2. `pnpm --filter nongyu-rn-app lint` / `type-check`。
3. 更新 Spec / Tech / Plan 状态为已实现（或「待人工回归」）。

---

## 3. 注意事项

- 严格两阶段可演示：M3 通过前不把 Phase 2 半成品混进主路径导致「既不像旧版又未达 PRD」。
- `scrollToIndex` 失败时降级 `scrollToOffset`，避免白屏。
- Android / iOS DateTimePicker 交互差异在 Picker 封装内消化。
- mock 数据勿提交真实学号隐私；用虚构课程名。
- 编码阶段遵循仓库代码规范；不主动 git commit。
- 若实现中发现必须偏离 Spec/Tech：先停，改文档并再确认，禁止静默扩 scope。
