## 1. 实施计划概览

| 阶段 | 内容                                                    | 风险                                                       |
| ---- | ------------------------------------------------------- | ---------------------------------------------------------- |
| A    | 工具包脚手架对齐教务（tsup/exports/目录）               | 低                                                         |
| B    | 逆向二课登录与核心接口，写入 `TECH.md`                  | **高**：站点可能走 i川农 / 独立 H5；凭据是否与教务共用未知 |
| C    | 实现个人二课信息 / 活动列表 / 活动详情原子 API          | 中：字段映射依赖 B                                         |
| D    | 包内 `README.md` + `TECH.md`；真机验登录 + 至少一项查询 | 中：依赖真机/校园网                                        |
| E    | `agent-sdk` 增加 `second-tools.ts` 并导出 `secondTools` | 低（SDK 已依赖本包）                                       |
| F    | RN：依赖接入、会话桥、入口 + 三业务页、路由             | 中：鉴权桥接依赖 B 结论                                    |

**文档策略**：跳过独立大技术方案；登录真机调通后可补 `docs/nongyu-rn-app/tech/二课鉴权方案.md`（对齐教务鉴权文档）。

## 2. 实施步骤

### 2.1 阶段 A — `nongyu-tool-second` 脚手架

对齐 `nongyu-tool-jiaowu`（不必 1:1 文件名，职责对齐即可）：

```text
packages/nongyu-tool-second/
  index.ts                 # 统一导出（可改入口，弃用仅占位 src/index.ts）
  package.json             # exports / type:module / tsup scripts；依赖 axios、iconv-lite、buffer（catalog）
  tsup.config.ts           # platform: neutral，与教务一致
  README.md / TECH.md
  core/
    login/                 # setLoginData / secondLogin / clearLoginData
    utils/                 # request、cookie、错误提示、可选 HTTP logger 挂载点
    extractor/             # HTML 或 JSON 清洗
    second/                # 业务查询函数（personal / activities / detail）
```

验收：`pnpm --filter nongyu-tool-second build` 通过；占位 `SecondTool` 删除。

### 2.2 阶段 B — 登录与会话逆向（阻塞后续）

1. 确认二课实际入口（网页 / i川农 H5 / API 网关）；用浏览器或抓包列出：登录 URL、会话载体（Cookie / Token / Header）、失效文案。
2. 实现 `secondLogin`：动态解析必要字段，**禁止**冻死抓包 Cookie / 固定 sign。
3. 实现 Cookie（或 Token）`get`/`set`、登录失效自动重登重放（对齐教务拦截器思路）。
4. 结论写入 `TECH.md`「已验证登录」；若与教务学号密码关系明确，同步记入后续鉴权方案。

**卡点处理**：若短期无法定位公开入口，先暂停 F 的 UI 精修，优先与用户同步已发现的域名/接口；不编造假数据接口冒充完成。

### 2.3 阶段 C — 原子业务 API

按 Spec §4.2 实现并导出：

| 语义                | 说明                                                                                           |
| ------------------- | ---------------------------------------------------------------------------------------------- |
| 个人二课信息        | 学分分布、附加分、累计分、综测、排名等；可聚合函数 + 必要时细粒度拆分，**均需可被 Agent 封装** |
| `listActivities`    | 入参：关键词、部落、分类（枚举以系统为准）                                                     |
| `getActivityDetail` | 入参：活动主键                                                                                 |

统一 Result 风格：`{ success, result?, message? }`。  
**禁止**在代码中导出报名等写操作；报名仅保留在接口清单文档。

### 2.4 阶段 D — 文档与真机门禁

1. `README.md`：安装、导出表、登录示例、查询示例、与 RN / Agent 关系、build 提醒。
2. `TECH.md`：网络层、登录步骤、页面/接口映射、否决项。
3. 真机/实网门禁：登录成功 + 至少一项查询成功，方可进入阶段 F 的数据联调（可并行写 UI 骨架，但不得用假成功掩盖未通接口）。

### 2.5 阶段 E — Agent Tool

1. 新增 `packages/nongyu-agent-sdk/src/core/tool/ExternalTools/second-tools.ts`（镜像 `jiaowu-tools.ts`）。
2. 每个业务查询 → `second_*` `tool()`；登录相关不封装。
3. 导出 `secondTools`；在 SDK 合适出口（`ExternalTools` index / 包 exports）挂上，便于 GUI/CLI 引用。
4. 可选：debug-cli 增加加载 `secondTools` 的注释或开关（不强制本轮跑通对话）。

### 2.6 阶段 F — RN 接入

1. `apps/nongyu-rn-app/package.json`：`nongyu-tool-second: workspace:*`；`pnpm install`。
2. Metro：若引入 iconv-lite/buffer，参照教务 `metro.config.js` 补齐。
3. 模块骨架（对齐 jiaowu）：

```text
src/modules/second/
  auth/          # session 桥、登录、登出清理（挂钩农屿登出）
  constants/     # 入口服务列表
  components/    # 壳、登录表单（可复用教务交互模式）、列表项
  screens/       # Home / Profile / Activities / ActivityDetail
app/home/second.tsx
app/home/second/...  # 子路由注册到根 Stack
```

4. 路由与 Spec 表一致；去掉占位文案中的「报名」暗示。
5. 页面：加载/空/错；列表搜索 + 部落/分类筛选；详情只读；语义 Token + 与教务一致的背景壳。
6. 登出农屿时清理二课会话（在既有 logout 链路挂钩）。

### 2.7 阶段 G — 收尾

1. 对照 Spec §6 清单自检。
2. `pnpm lint` / `type-check` / `format`（或按包 filter）。
3. Spec / 本计划状态改为「已实现 / 已完成」；有 Bug 则写 `docs/common/BugLog.md`。
4. 登录调通后补写 `docs/nongyu-rn-app/tech/二课鉴权方案.md`（可选但推荐）。

## 3. 注意事项

- **先 B 后深 UI**：无真实接口时不伪造业务数据冒充验收。
- **与教务隔离**：二课 Cookie/Token 独立存储键；勿覆盖教务 ASP Cookie。
- **密码不上云**：同教务；仅本机会话。
- **Agent 推荐**：只靠原子 tool + prompt，本轮不加推荐专用 tool。
- **专事专干**：RN 页面与视觉交给 `frontend-engineer`（加载 RN / frontend-design）；工具包网络与解析可由同会话实现，但需加载 golang 无关的 TS 规范与项目代码规范。
- **变更面**：`agent-sdk` 已声明依赖 `nongyu-tool-second`，改包后需 rebuild 两包再联调。
