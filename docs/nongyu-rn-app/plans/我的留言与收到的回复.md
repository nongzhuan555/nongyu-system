## 1. 依赖关系与实施顺序

```
[阶段1] Node: repo 列表查询 + routes `/received` `/sent` + 单元测试
   ↓
[阶段2] RN: API 封装 + 入口 + MyRepliesScreen 双 Tab + 删除
   ↓
[阶段3] 联调 + 接口文档同步 + lint/type-check/format + Review
```

阶段 1 完成前 RN 可先写 UI 与 API 封装，但联调依赖阶段 1。

## 2. 阶段分解

### 阶段 1：Node（约 1.5–2.5h）

| 步骤 | 产出                                                                                                                                              | 验证             |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------- |
| 1.1  | `postReplies.repo.ts`：`listReceivedRepliesForUser` / `listSentCommentsForUser`（count + page；过滤条件对齐 Spec §4）                             | SQL 手测或单测   |
| 1.2  | `appMyPostRepliesRouter` 新增 `GET /received`、`GET /sent`（Zod page/pageSize；映射 `publishedAt` ISO；**不返回作者字段**）；保持 `GET /new` 不变 | curl / 测试      |
| 1.3  | `tests/postReplies.test.ts` 增补 Spec §8 场景 1–7（含自留言不进 received、自己帖留言不进 sent、软删剔除、分页、`/new` 回归）                      | `pnpm test` 通过 |
| 1.4  | 更新 `docs/nongyu-node-server/接口文档概览.md`（及联调指南若有对应表）                                                                            | 人工核对         |

**过滤铁律（实现时对照 Spec）：**

- received：`p.author_user_id = uid` AND `r.author_user_id <> uid` AND 双方未软删
- sent：`r.author_user_id = uid` AND `r.kind = 'comment'` AND `p.author_user_id <> uid` AND `p.post_type = 'courtyard'` AND 双方未软删
- 排序：`r.created_at DESC, r.id DESC`

## 4. 风险评估

| 风险                                                   | 等级 | 缓解                                                           |
| ------------------------------------------------------ | ---- | -------------------------------------------------------------- |
| `/received` `/sent` 与 `/new` 路由顺序冲突             | 低   | 静态路径并列注册，勿用 `/:id`                                  |
| 自留言 / 自己帖过滤写反                                | 中   | 单测场景 3、4 锁死；编码前对照 Spec §4                         |
| RN 双 Tab 无限列表状态串扰                             | 低   | 独立 `queryKey`：`['posts','me','replies','received'\|'sent']` |
| 删除后详情缓存陈旧                                     | 低   | invalidate 详情 query key（若已有）或依赖进详情 refetch        |
| 文档与实现字段名不一致（`createdAt` vs `publishedAt`） | 中   | 列表统一 `publishedAt`；`/new` 保持既有 `createdAt` 不动       |
