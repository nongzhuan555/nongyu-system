# 教务请求缓存方案

> 状态：已对齐（2026-08-12）  
> 适用范围：`apps/nongyu-rn-app` 教务子页数据拉取  
> 依据：旧版 SWR 行为；新版统一使用已挂载的 **TanStack Query**（不引入 SWR）

## 1. 目标

- 对齐旧版：同用户、同资源在短时间内不重复打教务网；失焦不自动狂刷。
- 与全局技术选型一致：服务端/远端数据缓存用 TanStack Query；敏感凭据不进 Query 缓存。
- 与 UI 约定配合：加载 → 骨架屏；失败 → 失败提示页 + 可重试（`refetch`）。

## 2. 旧版 → 新版映射

旧版教务子页（成绩/排名/进度/考试等）典型配置：

- `useSWR(key, fetcher)`
- `dedupingInterval: 600000`（10 分钟）
- `revalidateOnFocus: false`
- key 含 `studentId`；未登录不发请求

新版对应：

| 旧 SWR                     | 新 TanStack Query                             |
| -------------------------- | --------------------------------------------- |
| `useSWR(key, fetcher)`     | `useQuery({ queryKey, queryFn })`             |
| `dedupingInterval: 600000` | `staleTime: 10 * 60 * 1000`                   |
| `revalidateOnFocus: false` | `refetchOnWindowFocus: false`                 |
| key 含学号                 | `queryKey: ['jiaowu', <resource>, studentId]` |
| 未登录不请求               | `enabled: !!studentId`（公开页可不依赖学号）  |
| `mutate` / 下拉刷新        | `refetch` / `invalidateQueries`               |

全局 `QueryClient` 已在 `AppProviders` 挂载；教务查询可在 hook 层覆盖 `staleTime` 等，避免把全站默认改成 10 分钟。

## 3. QueryKey 约定

```text
['jiaowu', 'notice']                         // 教务通知（公开）
['jiaowu', 'competition']                    // 竞赛通知（公开）
['jiaowu', 'progress', studentId]
['jiaowu', 'score', studentId]
['jiaowu', 'rank', studentId]
['jiaowu', 'exam', studentId]
['jiaowu', 'plan', studentId]                // 培养方案
```

- `studentId` 变化（换号登录）必须换 key，避免串数据。
- 登出：`queryClient.removeQueries({ queryKey: ['jiaowu'] })`。

## 4. queryFn 约定

- 直接调用 `nongyu-tool-jiaowu` 导出 API（如 `getScoreInfo`）。
- 工具返回 `{ success, result }` 时：`success === false` 视为失败（throw 或映射为 Query error），以便统一走失败页。
- **不要**在 Query 层再叠一层「空结果自动重登」：超时重登由工具请求拦截器负责（见《教务鉴权方案》）。
- Query 的 `retry` 保持较小（建议 0～1），避免与工具内部网络重试叠加过多。

## 5. 推荐封装

统一 hook（示意）：

- `useJiaowuQuery({ resource, queryFn, requireAuth, staleTime? })`
  - 组装 `queryKey` / `enabled`
  - 默认：`refetchOnWindowFocus: false`、`retry: 0|1`
  - 按资源应用下方「新鲜度」表中的 `staleTime`
  - 向外暴露：`data` / `isPending` / `isError` / `error` / `refetch` / `isRefetching` / `isFetching`

页面只负责：骨架 / 列表内容 / 失败页；不各自写一套缓存参数。

## 6. 新鲜度策略（缓存与实时性兼顾）

原则：**有缓存先展示，过期后后台刷新（Stale-While-Revalidate）；用户可下拉强制刷新；关键时刻主动失效。**

### 6.1 分资源 staleTime

| 资源                                   | `staleTime` | 说明                     |
| -------------------------------------- | ----------- | ------------------------ |
| `notice` / `competition`               | 3 分钟      | 相对新，进页过期后后台刷 |
| `exam`                                 | 10 分钟     | 考前可能更新             |
| `progress` / `score` / `rank` / `plan` | 15 分钟     | 学期内变化少             |

`staleTime` 内再次进入：直接用内存缓存，**不**发起教务请求。  
超过 `staleTime`：仍立刻渲染旧 `data`（若有），同时后台 `refetch`；页面用 `isFetching && !!data` 表示「更新中」，**不要**整页骨架。

### 6.2 刷新与失效

| 触发            | 行为                                                             |
| --------------- | ---------------------------------------------------------------- |
| 下拉刷新        | `refetch()`；失败时若已有 `data`，保留旧数据 + Toast，不整页失败 |
| 登录成功 / 换号 | `invalidateQueries({ queryKey: ['jiaowu'] })`                    |
| 登出            | `removeQueries({ queryKey: ['jiaowu'] })`                        |
| 焦点回前台      | **不**自动 refetch（`refetchOnWindowFocus: false`）              |

### 6.3 UI 状态机

- `isPending && !data` → 骨架屏（首次无缓存）
- `isError && !data` → 失败提示页 + 重试
- `data` 存在（含后台刷新中）→ 内容；可选轻量「更新中」
- 成功但列表为空 → 空态（与请求失败区分）

## 7. 缓存层级

| 层                     | 是否本版必做   | 说明                      |
| ---------------------- | -------------- | ------------------------- |
| React Query 内存缓存   | **必做**       | 按上表 stale；进程内有效  |
| MMKV 持久化 Query 结果 | **本版不做**   | 冷启动落盘可后续加        |
| SecureStore            | 不用于业务列表 | 仅学号/教务密码等敏感凭据 |

## 8. 注意事项

- 教务 HTML 抓取成本高：禁止对教务 query 使用 `refetchOnMount: 'always'`。
- 公开页（通知/竞赛）与鉴权页分开 key。
- 教务通知页使用「仅教学通知」数据源（`getTeachingNoticeInfo`），勿用合并版 `getNoticeInfo`。
- Query `retry` 保持 0～1，避免与工具内部网络重试叠加。
