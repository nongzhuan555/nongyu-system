## 3. 数据模型与 id 稳定性

### 3.1 教务课 id 稳定化

当前 `mapJiaowuCourseItems` 用 `${courseId}-${seq}-${day}-${start}`，`seq` 依赖遍历顺序，教务行序变则 id 变。改为：

```ts
function stableCourseId(name: string, day: number, startPeriod: number, endPeriod: number): string {
  return `jw-${hashStr(`${name}|${day}|${startPeriod}|${endPeriod}`)}`;
}
```

`hashStr` 用 FNV-1a 或 `crypto.createHash('sha1').update(...).digest('hex').slice(0,12)`。同课同时段恒定 id，备注/待办绑定稳定。

### 3.2 三类实体

见 Spec §4.1。`ScheduleEntry` 独立于 `CourseEntry`（不复用），但渲染时与教务课一起进 `weekMatrix`。

### 3.3 weekMatrix 扩展

`buildWeekMatrix` 现仅处理 `CourseEntry[]`。扩展为接收 `(CourseEntry[] | ScheduleEntry[])` 联合，或新增 `buildWeekMatrixWithSchedules(courses, schedules)`：先填课程，再在空格子填日程，冲突时课程优先（日程不应覆盖课程，但添加时已校验空格子，此处防御性保留课程）。

`GridCell` 扩展：

```ts
type GridSchedule = { kind: "schedule"; schedule: ScheduleEntry; spanRows: number };
type GridCell = GridPrimary | GridSchedule | GridOccupied | null;
```

### 4.2 `courseExtLocalStore.ts`

镜像 `courseLocalStore`：`read/write/clear` 三类，每类 JSON 数组整体读写。

### 4.3 mmkv.ts 扩展

新增按 prefix 批量删除（登出清理用）。底层 MMKV 有 `getAllKeys`，但当前 `KvStore` 封装未暴露。方案：在 `courseExtLocalStore` 与 `courseLocalStore` 各自暴露 `clearByStudentId(studentId)`，登出时显式调用三类 + 课表，不依赖通用 prefix 删除（更可控）。

## 5. 远程 API

### 5.1 迁移 `002_course_ext.sql`

见 Spec §4.3。`weeks_list` 存 JSON 字符串。

### 5.2 路由 `/api/app/course-ext`

```text
GET    /schedules            → 当前用户全部
POST   /schedules            → 新建（id 由客户端生成，服务端校验唯一）
PATCH  /schedules/:id        → 更新
DELETE /schedules/:id        → 删除
GET    /notes[?courseId=]     → 全部或按课程
POST   /notes
PATCH  /notes/:id
DELETE /notes/:id
GET    /todos[?courseId=]
POST   /todos
PATCH  /todos/:id
DELETE /todos/:id
```

- `requireAppAuth`，按 `req.appAuth.uid` 隔离。
- Zod 校验 body。
- `weeks_list` 接口层 JSON ↔ DB string 互转。
- 错误：404 not found / 403 非本人 / 400 校验失败。

### 5.3 `courseExtApi.ts`（RN 客户端）

复用 `src/api/` 现有 fetch 封装，注入 `appAuth` token。导出 `listSchedules/createSchedule/...`。

## 6. 同步策略

### 6.1 写操作（本地优先 + push）

```
addSchedule(entry)
  → writeLocal(schedules + [entry])
  → UI 立即更新（React Query setQueryData）
  → try { POST /schedules }
    → 成功：无需回写（id 客户端已生成）
    → 失败：记 console.warn，保留本地；下次 pull 时由远程权威覆盖
```

### 6.2 拉取（进课表 / 登录后）

```
pullCourseExt(studentId)
  → Promise.all([GET schedules, GET notes, GET todos])
  → 成功：writeLocal(远程数据) → queryClient.setQueryData
  → 失败：保留本地，不阻断
```

触发时机：

- `performJiaowuLogin` 末尾（已有课表 prefetch，追加 course-ext prefetch）
- `CourseScreen` mount（`useEffect` → `pullCourseExt`）

### 6.3 冲突

远程权威：pull 直接覆盖本地。写操作先本地后远程，远程失败不回滚（离线友好）。多设备场景：A 设备改后 push，B 设备进课表 pull 覆盖。无字段级合并（本期不做）。

## 11. 注意事项

| 项      | 说明                                                                                 |
| ------- | ------------------------------------------------------------------------------------ |
| id 稳定 | 改 `mapJiaowuCourseItems` 后旧本地课表 id 失效，首次升级需清本地课表缓存或重新 fetch |
| 离线    | 写操作本地立即生效；远程失败不阻断 UI；下次 pull 覆盖                                |
| 鉴权    | Node 接口必须 `requireAppAuth` + uid 隔离；Agent tool 经同一 token                   |
| 范围    | 不做考勤、提醒、海报、分享、教务课编辑/屏蔽                                          |
| 测试    | Node 接口可补 supertest；RN UI 手工验收                                              |
