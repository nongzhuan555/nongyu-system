## 1. 背景

**Why**：回到 Agent 聊天页时，`getOrCreateNongyuAgent` 异步未完成前整页只有「加载中」，与全 App 骨架体验不一致，等待感差。  
**What**：在 agent 未就绪阶段用聊天布局骨架屏替代纯文案加载态。

---

## 2. 目标

| #   | 目标                                          | 验收                                              |
| --- | --------------------------------------------- | ------------------------------------------------- |
| G1  | 消除 `agent === undefined` 时的居中「加载中」 | 页面上不再出现该文案作为主加载态                  |
| G2  | 展示贴近聊天页的脉冲骨架                      | 气泡占位 + 底部输入栏占位；顶栏为真实 Header      |

## 5. 详细需求

### 5.1 触发条件

- 当且仅当 `agent === undefined` 时渲染骨架屏（替换现有 `styles.center` +「加载中」分支）。
- `agent === null` 仍走现有 `UnconfiguredPanel`。
- `agent` 已就绪仍走现有 `AiChatPanel`。

### 5.2 UI 结构

1. **顶栏**：继续渲染真实 Header（菜单 /「农屿 AI」/ 新对话），不骨架化，避免可交互入口在等待期消失（按钮在 agent 未就绪时是否可点：保持现状；Header 本身已在骨架分支外层，始终可见）。
2. **消息区**：若干条气泡占位（建议 4～5 条），左右交替对齐：
   - 左侧（assistant 侧）：较宽灰条，可 1～2 行高度差
   - 右侧（user 侧）：较窄灰条
3. **底部输入栏**：一条圆角灰条，宽度接近真实 composer，可选右侧圆形发送按钮占位。
4. **动效**：`SkeletonBox` 自带脉冲，不额外加文案「加载中」。

### 5.3 组件落点

- 新增轻量组件（建议路径）：`apps/nongyu-rn-app/src/agent-ui/ChatLoadingSkeleton.tsx`（或同目录等价命名）。
- `app/ai.tsx` 在 `agent === undefined` 分支引用该组件。
- 样式跟当前 `/ai` 的间距 / 圆角 token，不另造视觉体系。

### 5.4 无障碍

- 骨架容器建议 `accessibilityRole="progressbar"` 或等价，并提供 `accessibilityLabel`（如「正在加载对话」），便于读屏识别等待态。

---

## 6. 业务流程

```
进入 / 聚焦 /ai
  → getOrCreateNongyuAgent() 进行中，agent === undefined
  → 显示 ChatLoadingSkeleton（Header 已在外层）
  → agent 解析完成
      → null → UnconfiguredPanel
      → Agent → AiChatPanel（含 hydrate 后的历史或空态）
```

---

## 7. 验收标准与测试方案

### 理想 UI

- 等待态：顶栏正常；中间左右交替灰气泡脉冲；底部输入条脉冲；**无**居中「加载中」二字。
- 就绪后：无缝切到空态欢迎 / 历史消息列表 / 未配置面板之一。

### 操作回归

1. 冷启动进 `/ai`：见骨架 → 见聊天或未配置。
2. 离开 `/ai` 再返回（触发 remount / agent 再拉取）：见骨架（若出现 `undefined`）→ 历史消息恢复。
3. 已配置 agent、有历史会话：就绪后消息与离开前一致（不测数据正确性变更，仅确认不被骨架挡住）。
4. 未配置模型：骨架结束后仍为「暂不可用平台模型」面板。

---

## 8. 实现提示（非契约）

- 历史 hydrate 本身为本地同步；用户感知的等待主要来自 agent 工厂异步。本期只改该等待 UI，不改 hydrate 时序。
