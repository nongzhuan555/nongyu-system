| 项       | 内容                                                                    |

| 应用     | `apps/nongyu-rn-app`                                                    |
| 需求类型 | **业务**                                                                |

| 参照     | `TabScreenBackground`、`JiaowuPageShell`、各 `modules/jiaowu/screens/*` |
| 状态     | **已实现（待人工点验）**                                                |

---

## 1. 背景

教务七大子页已能拉数展示，但：

1. 列表较长时缺少本地检索，查找成本高；
2. 子页壳为纯色底，与首页 / 广场 /「我的」的柔渐变不一致；
3. 学业进度仅展示文字百分比，不够直观。

本需求在不改教务鉴权与接口的前提下，优化交互与视觉一致性。

---

## 2. 目标

1. **搜索**：除专业排名外的 6 个列表类子页支持纯前端搜索（不区分大小写、子串匹配）；输入经防抖 + 假延时后过滤，以模拟联网搜索体感。
2. **背景**：7 个子功能页背景对齐主 Tab 的 `TabScreenBackground` 渐变。
3. **进度条**：学业进度每张卡片增加横向进度条，优先由 `progress` 字段解析百分比。

---

## 3. 边界（非目标）

- 不改教务首页入口列表（`JiaowuHomeScreen`）的搜索与布局（可顺带是否统一背景：**本次不做**）。
- 教务首页 / 子页不提供「退出登录」入口（登出在「我的」等既有入口完成）。
- 专业排名页不加搜索框（单卡、无可搜列表）。
- 不新增/修改 `nongyu-tool-jiaowu` 接口与缓存策略。
- 不做服务端搜索、拼音首字母、高亮命中、搜索历史。
- 不单独编写技术方案文档（变更面小，Spec + 实施计划即可）。
- 不改登录表单、鉴权引导逻辑。

---

## 4. 详细需求

### 4.1 统一背景

- 在 `JiaowuPageShell` 根层叠加与主 Tab 相同的 `TabScreenBackground`（`pointerEvents="none"`、绝对铺满）。
- `root` 底色可透明或与 `background` 一致，保证渐变可见；列表卡片 `surface` 保持不变。
- 七个子页均走 `JiaowuPageShell`，因此背景一次改壳即可覆盖。

### 4.2 统一搜索壳

在 `JiaowuPageShell` 增加可选搜索能力：

| Prop 约定（实现时可微调命名） | 说明                                       |
| ----------------------------- | ------------------------------------------ |
| `search` 可选对象             | 传入则展示搜索条；不传则不展示（专业排名） |
| `search.value`                | 输入框当前草稿（受控）                     |
| `search.onChangeText`         | 草稿变更                                   |
| `search.placeholder`          | 按页定制，如「搜索课程名、学期…」          |
| `search.searching`            | 假延时期间为 true，搜索条展示轻量转圈      |

行为：

- 搜索条位于顶栏下方、内容区上方（「更新中…」提示若存在，可在搜索条之上或之下，保持不挡操作即可）。
- **假联网搜索体感**（六页共用 hook，如 `useDeferredLocalSearch`）：
  - 输入防抖 **300ms**，防抖结束后再假延时 **400ms**，然后将草稿提交为生效关键词并做本地 filter；
  - 假延时期间 `searching=true`，搜索条旁小转圈；列表仍展示上一轮生效结果，避免闪空；
  - **清空关键词立即**恢复全量列表并取消进行中的定时器（不走防抖/假延时）。
- 仅做本地过滤，不发网络请求。
- **空态区分**：
  - 接口成功但原数据为空 → 沿用各页原有 `emptyText`（如「暂无成绩」）。
  - 原数据非空，**生效关键词**过滤后为空且非 searching → 展示「未找到相关结果」。
- 加载中 / 错误态不展示搜索条；**仅在非 loading、非 error、且已有成功数据时展示**。

### 4.3 各页过滤字段

过滤逻辑在各 Screen 内对已拉取数据做 `filter`（trim 后大小写不敏感；字段拼接或逐字段 `includes` 均可）。

| 页面     | Screen              | Placeholder 建议       | 参与匹配的字段                                                                 |
| -------- | ------------------- | ---------------------- | ------------------------------------------------------------------------------ |
| 教务通知 | `NoticeScreen`      | 搜索通知标题、日期     | `title`, `date`                                                                |
| 竞赛通知 | `CompetitionScreen` | 搜索竞赛标题、日期     | `title`, `date`                                                                |
| 学业进度 | `ProgressScreen`    | 搜索学分类型           | `type`                                                                         |
| 成绩查询 | `ScoreScreen`       | 搜索课程、学期、类型…  | `courseName`, `term`, `courseType`, `source`                                   |
| 考试安排 | `ExamScreen`        | 搜索课程、考场、时间…  | `courseName`, `examRoom`, `examTime`, `assessmentMethod`                       |
| 培养方案 | `PlanScreen`        | 搜索课程名、代码、类型 | `courseName`, `courseCode`, `courseType`（仅过滤 `courses`；方案标题区可保留） |
| 专业排名 | `RankScreen`        | —                      | **不传 `search`**                                                              |

成绩页：先过滤再按学期分组；某学期下无命中则不渲染该分组标题。

### 4.4 学业进度条

在 `ProgressScreen` 每张卡片中：

1. 从 `item.progress` 解析百分比：提取首个合法数字；若值在 `0–1` 视为比例并换算为 `0–100`；若在 `0–100` 视为百分比；超出夹紧到 `[0, 100]`。
2. 解析成功：在「应修 / 已修 / 进度」信息下方（或进度文案旁）展示横向进度条：
   - 轨道：浅色（如 border / 浅灰）
   - 填充：`brand`
   - 高度约 6–8，圆角
3. 解析失败：不渲染进度条，保留现有文字进度展示。
4. 进度百分比文字仍保留，与进度条并存。

### 4.5 可访问性与样式

- 搜索框需有 `accessibilityLabel`（可用 placeholder 或「搜索」）。
- 样式贴合现有 `lightTokens`（圆角、间距、描边），不引入新设计体系文档。
- 不引入第三方搜索组件。

## 5. 业务流程

```
进入子页 → 鉴权/拉数（既有）
  → 成功且有数据
       → 展示搜索条（排名除外）
       → 用户输入关键词 → 防抖 300ms → 假延时 400ms（搜索中…）→ 前端 filter → 列表更新
       → 清空 → 立即恢复全量
       → 无命中 →「未找到相关结果」
  → 成功但无数据 → 原 empty 文案（无搜索或可不展示搜索）
  → 失败 / 加载中 → 既有骨架/错误页
学业进度卡片额外：解析 progress → 画条或跳过
```

## 6. 验收标准与测试方案

### 6.1 背景

- [ ] 打开通知 / 竞赛 / 进度 / 成绩 / 排名 / 考试 / 培养方案，顶部柔渐变与首页 Tab 观感一致（色带同源 `TabScreenBackground`）。
- [ ] 卡片仍为白底 surface，可读性不下降。

### 6.2 搜索

- [ ] 专业排名无搜索条。
- [ ] 其余 6 页：有数据时出现搜索条；输入后约防抖 300ms + 假延时 400ms 再缩小列表；延时期间搜索条有转圈。
- [ ] 大小写不敏感；**清空后立即**恢复全量（无延时）。
- [ ] 过滤无结果时文案为「未找到相关结果」，且与「暂无 xxx」可区分（可用清空关键词验证恢复）。
- [ ] 成绩页过滤后分组正确（空分组不出现）。
- [ ] 六页共用同一延时 hook，行为一致。

### 6.3 学业进度条

- [ ] `progress` 含如 `80%` / `80` 时可看到对应长度进度条。
- [ ] 无法解析时无条、不白屏、文字仍在。

### 6.4 回归

- [ ] 下拉刷新、错误重试、教务登录引导、缓存行为与改前一致。
- [ ] `pnpm lint` / `type-check` / `format` 通过（按开发规范在改码后执行）。
