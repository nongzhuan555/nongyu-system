# Spec：开发态 HTTP 请求日志

| 项       | 内容                                                             |
| -------- | ---------------------------------------------------------------- |
| 应用     | `apps/nongyu-rn-app`                                             |
| 需求类型 | **基建**                                                         |
| PRD      | 对话确认：开发调试阶段打印全部请求结果；仅开发环境；生产构建移除 |
| 状态     | **已实现**                                                       |

---

## 1. 背景

RN 联调时请求分散在农屿后端 `fetch`、教务 axios、以及其它走 `fetch` 的 SDK 上。成功与失败都需要在 Metro / 设备控制台立刻看到结果，避免每个调用点临时加 `console.log`。正式包不得带这段调试输出。

## 2. 目标

1. 开发环境下，App 内发出的 **全部 HTTP 请求**（成功与失败）都将结果打印到控制台。
2. 生产构建 **不安装、不执行** 该日志逻辑（`__DEV__ === false` 时整段不可达，由打包器剔除）。
3. 日志足够对照一次请求：方法、URL、状态、耗时、请求体、响应体或失败原因。
4. 敏感字段打码；超大响应截断，避免教务 HTML 刷爆控制台。

## 3. 边界（非目标）

- 不覆盖 Web Admin / Web Site / Node 服务端日志。
- 不改变任何请求的成功/失败语义、重试、鉴权或业务解析。
- 不引入第三方 logger / 网络抓包 SDK。
- 不做持久化、不上报、不做日志开关 UI。
- 不保证覆盖系统级非 JS 请求（如图片原生加载、Expo 更新通道等）。
- **跳过独立技术方案文档（tech）与实施计划文档（plans）**——范围小、选型已定，以本 Spec 直接指导实现（需用户在评审中确认）。

## 4. 详细需求

### 4.1 覆盖范围

必须覆盖 RN 运行时由 JS 发出的两类 HTTP：

| 通道         | 典型来源                                           | 要求                                            |
| ------------ | -------------------------------------------------- | ----------------------------------------------- |
| 全局 `fetch` | `appFetch`、`appAuth` 直连、Agent SDK 等           | 启动时安装一次包装，后续所有 `fetch` 自动打日志 |
| 教务 axios   | `nongyu-tool-jiaowu` 的 `request` / `get` / `post` | 安装响应/错误拦截，成功失败都打                 |

同一请求只打 **一条结果日志**（含最终状态）。重试过程中的中间失败可另打简要失败行，但最终成功仍要有一条成功结果。

### 4.2 启用条件

- 仅当 `__DEV__ === true` 时安装包装 / 拦截器。
- 生产包不得调用安装函数，也不得打印本 Spec 定义的请求日志。
- 业务代码禁止为调试再散落 `console.log` 打完整响应；统一走本机制。

### 4.3 打印字段

每条结果日志至少包含：

| 字段     | 说明                                      |
| -------- | ----------------------------------------- |
| 标记     | 固定前缀，便于过滤，如 `[HTTP]`           |
| 成败     | `OK` 或 `FAIL`                            |
| method   | `GET` / `POST` 等                         |
| url      | 完整请求 URL（含 query）                  |
| status   | HTTP 状态码；网络层失败可为 `-`           |
| duration | 从发起到拿到结果的毫秒数                  |
| request  | 请求体（无 body 则省略）                  |
| response | 成功时的响应体；失败时为错误信息 / 响应体 |

请求头默认不整包打印。仅当需要对照鉴权是否带上时，可打印 **已打码** 的 `Authorization` / `Cookie` 是否存在（`present` / `absent`），不得打印原文。

### 4.4 脱敏

日志输出前必须打码，禁止明文出现：

- Header：`Authorization`、`Cookie`、`Set-Cookie`
- Body / JSON 字段名（大小写不敏感）：`password`、`pwd`、`token`、`accessToken`、`refreshToken`、`cookie`

打码替换为 `***`。其它字段原样输出（受截断约束）。

### 4.5 截断

- 请求体、响应体序列化后超过 **2048 字符** 则截断。
- 截断后后缀标明原文长度，例如 `… [truncated, total=18230]`。
- JSON 业务包（农屿 `{ code, message, data }`）通常短于阈值，应完整可见。
- 教务 HTML 等超大文本按阈值截断，不要求完整 DOM。

二进制 / `ArrayBuffer` 不尝试全文解码进日志，只标明类型与字节长度。

### 4.6 成功与失败

- **HTTP 通了**（有 Response）：打印 status + 解析后的文本/JSON（截断 + 脱敏）。业务 `code !== 0` 仍算「有结果」，按实际 status/body 打印；调用方随后 throw 不免除本条日志。
- **HTTP 没通**（网络错误、超时、abort）：打印 `FAIL` + `error.message`（脱敏后）。
- 日志打印失败不得影响原请求：包装内部 `try/catch`，吞掉日志异常。

### 4.7 安装时机

App 根入口（`app/_layout.tsx` 或等价最早 JS 入口）在渲染前、且仅 `__DEV__` 下调用一次安装函数。重复调用必须幂等（不叠多层 `fetch` 包装）。

## 5. 业务流程

```text
App 启动（仅 __DEV__）
  → 安装 fetch 包装
  → 安装教务 axios 拦截
任意业务发起 HTTP
  → 记录开始时间
  → 发出真实请求（语义不变）
  → 得到 Response 或 Error
  → 脱敏 + 截断
  → console 打印一条 [HTTP] OK/FAIL
  → 原样返回 / 抛出给调用方
```

## 6. 验收标准

1. `__DEV__` 下：登录（`/api/app/auth/login`）、带 JWT 的业务接口、教务任一查询，成功与故意失败都能在控制台看到 `[HTTP]` 日志，含 method、url、status/错误、耗时。
2. 登录请求日志中看不到密码、JWT、Cookie 原文。
3. 教务 HTML 响应被截断，控制台单条不会出现整页源码。
4. 生产构建（`__DEV__` 为 false）安装函数不可达，控制台无 `[HTTP]` 调试日志。
5. 打开/关闭本能力不改变接口返回值、错误类型与登录/教务业务流程。

### 测试方案

- 开发：Metro 连 Dev Client，登录一次（成功 + 错误密码各一次），进广场拉帖、进教务拉成绩；过滤 `[HTTP]` 核对字段与脱敏、截断。
- 生产：本地 `expo export` 或 release 包，确认无 `[HTTP]` 输出（抽查登录/业务请求）。
- 回归：登录、广场列表、教务成绩查询功能与改前一致。
