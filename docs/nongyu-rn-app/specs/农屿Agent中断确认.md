---

## 1. 背景

**Why**：生成中误触 Stop 需二次确认；同时不允许生成中追加/改写输入，避免并发打断发送。  
**What**：`isLoading` 时禁用输入框，右侧仅 Stop（确认后中断）；取消则继续生成。

---

## 2. 目标

| #   | 目标                                         | 验收                           |
| --- | -------------------------------------------- | ------------------------------ |
| G1  | loading 时输入框不可编辑，不能追加消息       | `editable={false}`，无发送入口 |
| G2  | loading 时右侧为 Stop；点按先确认再 `stop()` | 取消不中断                     |
| G3  | 非 loading 普通发送无需确认                  | 行为同前                       |
| G4  | 不改离页保活、系统返回等                     | 离页仍不主动 stop              |

---

## 3. 边界（非目标）

- **不做「打断并发送」**（生成中不可输入，故无此路径）
- 不新增硬件返回 / 离页中断确认
- 不改 `stopped` 语义、落盘、重试 / 重新生成
- 独立 tech / 实施计划文档

---

## 4. Grill 共识（含修订）

| 决策        | 结论                                     |
| ----------- | ---------------------------------------- |
| 归类        | 基建                                     |
| 生成中输入  | 禁用；去掉打断并发送                     |
| 中断        | 仅 Stop + 确认弹窗                       |
| 建议/重试等 | 生成中保持 `actionsEnabled={!isLoading}` |
| 返回 / 离页 | 本期不做                                 |

---

## 5. 详细需求

### 5.1 生成中输入锁定

- `isLoading === true`：`TextInput` `editable={false}`；placeholder 可提示「生成中，请稍候…」；composer 可略降透明度。
- 右侧按钮固定为 Stop（不再根据 input 是否为空切换发送）。

### 5.2 Stop 确认

1. 点 Stop → `confirm`：
   - 标题：`停止生成`
   - 说明：`将停止当前回复，已生成内容会保留。`
   - 确认：`停止`；取消：`取消`
2. 确认 → `stop()`；取消 → 不中断。

### 5.3 普通发送

- 仅 `!isLoading && input.trim()` 时可发送；无确认弹窗。

---

## 6. 验收

1. 生成中：无法聚焦输入/无法改字；仅见 Stop。
2. 点 Stop → 弹窗；取消后仍在生成；确认后「已停止」且可再输入。
3. 非生成中发送：无确认。
4. 生成中空态建议 / 重试 / 重新生成仍不可用。
5. 生成中离开 AI 页：仍不因本期改动而 stop。
