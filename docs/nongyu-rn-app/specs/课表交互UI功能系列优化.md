## 1. 背景

**Why**：课表主路径可用，但日程视觉、冲突叠卡、考勤、全学期预构建性能、首屏可观测性与刷新误触仍影响日常体验。

**What**：

1. 重做日程卡片视觉（高级简约）；
2. 允许日程与课程时间冲突，同格堆叠 + 翻牌切换，默认与重进课表均优先课程；
3. 课程考勤（本地 + 远程），他人课表不可见；
4. 周矩阵懒构建（当前周 ±2）；
5. 采集并上报课表首屏耗时；
6. 页头「刷新 / 查看他人」换位，刷新前全局确认。

本 Spec **修订** `课表扩展-自定义日程备注待办.md` 中「有课格子拒绝添加日程 / 冲突时日程跳过」的约定：改为允许冲突并堆叠展示。

## 3. 边界（非目标）

- **不做** Agent `course_attendance_*` / `course_ext_snapshot` 考勤字段扩展（下轮）
- **不做** 上课提醒、海报、二维码
- **不做** 单周 5 行竖向虚拟列表
- **不做** 教务课编辑/屏蔽
- **不做** 翻牌索引持久化（会话内有效；重进/切周重置）
- **不做** 考勤统计报表页
- **不做** 按课程批量重置全学期考勤

## 4. 详细需求

### 4.1 日程卡片 UI

- 组件：`ScheduleCard`（周视图）；Agent 侧 `CourseScheduleCard` 若共用视觉语义可对齐，**非必须**改 Agent 卡。
- 视觉约束：
  - 背景：品牌色极低透明或 surface 浅底，非实心色块；
  - 边框：`hairline` + 弱品牌色；
  - 圆角与课程卡同档；
  - 左上或顶栏弱日历图标，不抢标题；
  - 标题居中加粗；地点一行次级色；内容可选一行 ellipsis；
  - 阴影：无或极轻（elevation ≤ 1）；
  - 按下：轻微 scale / opacity，与课程卡同交互量级。

### 4.2 冲突叠卡与翻牌

#### 4.2.1 数据与矩阵

- `weekMatrix`：同格可持有 **stack**（有序卡片列表），不再在冲突时 `continue` 跳过日程。
- 堆叠顺序（稳定）：
  1. 若有课程：课程永远在 index 0；
  2. 其余为命中该格的日程，按 `createdAt` 升序。
- 仅多日程无课程：按 `createdAt` 升序；默认展示第一张。
- 连堂：以起始大课行写入 stack；跨行 `occupied` 逻辑仍指向 primary 行；翻牌宿主在 primary 行。

#### 4.2.2 展示优先级

- 进入课表、切到某周、该周 grid 首次挂载：正面 = stack[0]（有课则为课程）。
- 翻牌索引仅存 UI 状态（按 `weekIndex + day + startRow` 或等价 key）；**不**写入 MMKV。
- 离开该周再回来、或离开课表 Tab 再进：该 key 重置为 0。

#### 4.2.3 手势

| 条件           | 单击                 | 长按                                 |
| -------------- | -------------------- | ------------------------------------ |
| stack.length=1 | 打开该卡详情         | ActionSheet「添加日程」（只读无）    |
| stack.length>1 | 打开**当前正面**详情 | 翻牌切到下一张 + 系统震动（Haptics） |

- 翻牌动画：绕 Y 轴翻卡牌（约 200–350ms）；切换中途切换正面内容。
- 堆叠视觉提示：角标 `当前/总数`（如 `1/3`），弱样式，不挡标题。

#### 4.2.4 冲突添加

- **长按** 单卡格：ActionSheet 含「添加日程」（只读 peer 模式无此入口）；多卡格长按用于翻牌，添加日程走空格或详情入口。
- **课程详情**：提供「在此时间添加日程」，预填 day / periods / 当前周进 `weeksList`（与空格添加一致）。
- `ScheduleFormSheet`：**移除**「与已有课程时间冲突则拒绝提交」校验；仍校验标题非空、节次合法、周次非空等原有规则。
- **重叠提示**：新建（或保存后检测到）日程与任一课程在「同星期 + 节次交叉 + 周次有交集」时 Toast：`你所添加的日程和课程有重叠，长按卡片可切换`（不阻断保存）。
- 空格点击添加逻辑保留。

### 4.3 课程考勤

#### 4.3.1 模型 `CourseAttendance`

```ts
export type AttendanceStatus = "present" | "late" | "absent" | "leave" | "nocheck";
// present=签到 late=迟到 absent=缺勤 leave=请假
// nocheck=未考勤（老师未检查本节上课情况；与四态平等落库）

export type CourseAttendance = {
  id: string; // uuid
  studentId: string;
  courseId: string; // CourseEntry.id
  week: number; // 教学周 ≥ 1
  day: 1 | 2 | 3 | 4 | 5 | 6 | 7;
  status: AttendanceStatus;
  createdAt: string; // ISO
  updatedAt: string; // ISO
};
```

- **唯一性**：同一 `(studentId, courseId, week, day)` 至多一条；再次标记为 **upsert**（更新 status + updatedAt）。
- 仅绑定**课程**（教务 `CourseEntry`），不绑定自定义日程。
- **`nocheck` ≠ 无记录**：无记录表示用户尚未标记；`nocheck` 是用户主动选择的业务态。

#### 4.3.2 UI（详情）

- 仅 `CourseDetailSheet` 内「考勤」区块（与备注/待办同级）。
- 展示：当前详情所对应教学周 + 星期的状态；可切换**五态**（签到 / 迟到 / 缺勤 / 请假 / **未考勤**）。
- **重置**：独立按钮；删除**本节** `(courseId, week, day)` 记录（本地 + 远程 tombstone）；不是整门课清空。无记录时重置禁用或隐藏。
- 文案：原「清除记录」改为「重置」。
- **本学期汇总（详情内，2026-08-16）**：在本节操作区下方展示该 `courseId` 全学期次数（含签到与未考勤，如 `签3·迟1·缺1·未2`）及按周排序的记录列表（`第N周 · 周D · 状态`）；无记录时显示「本学期暂无考勤记录」。
- `readOnly` / peer / diff：**整段不渲染**考勤。

#### 4.3.2b UI（课程卡本节状态 + 详情学期记录，2026-08-16）

- **课程卡**：仅展示**本节**完整状态名（签到/迟到/缺勤/请假/未考勤）；无本节记录则不渲染考勤行。**不**在卡片上展示学期汇总。
- **详情弹窗「本学期考勤记录」**：在本节操作区下方；汇总用完整中文，如 `签到 3 · 迟到 1 · 未考勤 2`；下列表 `第N周 · 周一 · 迟到`；无记录显示「本学期暂无考勤记录」。
- peer / diff：卡片与详情均不渲染考勤。

#### 4.3.3 本地 + 远程

- 对齐现有 course-ext：`courseExtLocalStore` / `courseExtApi` / `courseExtRepository` / Outbox / Tombstone。
- Node：`course_attendances.status` 允许值含 `nocheck`；迁移放宽 CHECK（`005` 为四态 → 新迁移改为五态）；Zod `attendanceStatus` 枚举同步。
- 共享课表查找 API **不得**返回考勤；RN peer 模式不 pull、不读本地他人考勤。

#### 4.3.4 Agent

- 本轮**不**暴露考勤 tools。

### 4.4 周矩阵懒构建

- 废弃「一进课表就 `buildAllWeekMatricesWithSchedules` 全量」作为首屏路径。
- 维护窗口：`[viewWeekIndex - 2, viewWeekIndex + 2]`（夹在 `0..maxWeek-1`）。
- `WeekPager` `data` 可为占位 + 已构建周；或保持长度 = maxWeek，未构建周渲染轻量占位，进入窗口再构建。
- `maxWeek` 仍可由课程/日程的周次上界快速算出（O(n) 扫条目，**不**建矩阵）。
- 切周时扩展窗口；窗口外矩阵可丢弃以省内存（可选，推荐丢弃）。

### 4.5 首屏埋点

- 事件：`event_type: "perf"`，`event_name: "course_week_first_paint"`（稳定英文名）。
- `duration_ms`：自 `CourseScreen` 挂载（或本人课表开始展示的 commit）起，至**当前周** `WeekGrid` 首次 `onLayout`。
- 条件：已登录、`viewMode === "self"`、非 loading/error 占位；每进入课表屏成功渲染当前周 **最多报 1 次**（同一次 mount）。
- `props` 建议：`{ week_index, max_week, has_local_cache?: boolean }`；禁止 PII。
- 使用现有 `track` / 手写 `enqueue` 均可；不必包在 `measure()` 里（跨异步 layout）。

### 4.6 页头按钮与刷新确认

- 本人模式 actions 顺序调整为：**刷新** → **查看他人** → 设置 → 开学日（即原「查看他人」与「刷新」对调）。
- 点刷新：`confirm({ title, message, confirmText, cancelText })`（`docs/.../全局确认框.md`）。
  - 推荐文案：标题「刷新课表」；内容「将从教务重新拉取并覆盖本地课表，是否继续？」；确认「刷新」；取消「取消」。
- 仅确认返回 `true` 后调用现有 `forceRefresh`；peer 模式行为不变。

## 5. 业务流程

### 5.1 叠卡翻牌

```text
构建周矩阵 → 同格 stack 排序（课优先）
  → 渲染正面 stack[i]
  → 单击 → 打开正面详情
  → 长按且 length>1 → i = (i+1) % length，翻牌动画 + Haptics
  → 长按且 length=1 → ActionSheet 添加日程
  → 切周 / 重进课表 → i = 0
```

### 5.2 考勤

```text
打开本人课程详情
  → 读本地 (courseId, week, day)
  → 用户选五态（含 nocheck）→ upsert 本地 → push / outbox
  → 用户点「重置」→ 删除本节记录 → tombstone / outbox
  → pull 时合并远程；tombstone 删除传播
周视图课程卡
  → 仅本节有记录时显示完整状态名（不展示学期汇总）
详情弹窗
  → 「本学期考勤记录」完整中文汇总 + 按周列表
查看他人 → 无考勤 UI、无考勤请求
```

### 5.3 首屏 perf

```text
CourseScreen mount (self)
  → t0 = now
  → 当前周 WeekGrid onLayout
  → track perf course_week_first_paint (duration_ms = now - t0) 一次
```

## 6. 验收标准与测试方案

### 6.1 UI / 交互

- [ ] 日程卡：浅底细边、弱图标、信息层级清晰；暗色/浅色主题可读。
- [ ] 同格 1 课 + 2 日程：默认课程；单击开当前正面详情；长按翻牌并震动；角标份数正确。
- [ ] 仅 1 张卡：单击直接详情；长按弹出添加日程。
- [ ] 新建与课程重叠的日程：保存成功且 Toast 提示长按可切换。
- [ ] 切周再回 / 杀进程重进：正面回到课程（有课时）。
- [ ] 详情「在此时间添加日程」可用；空格添加仍可用。
- [ ] 日程表单与课程时间重叠可保存成功。

### 6.2 考勤

- [ ] 详情可标记五态（含「未考勤」/`nocheck`）并再次修改。
- [ ] 「重置」仅删除本节 `(courseId, week, day)`；其他周/其他课记录保留；重置后无选中态。
- [ ] `nocheck` 与无记录可区分：选「未考勤」后有记录且 chip 高亮；重置后无记录。
- [ ] 断网可写本地；联网后远程可见（同设备 pull 或第二设备）；Node 接受 `nocheck`。
- [ ] 删除后他端 pull 消失（tombstone）。
- [ ] peer / diff：详情无考勤区块；共享 API 响应无考勤字段；课程卡无考勤文案。
- [ ] 本人课程卡：仅本节有记录时显示完整状态名（如「迟到」）；不展示学期汇总。
- [ ] 详情弹窗「本学期考勤记录」：汇总为完整中文（如「签到 3 · 迟到 1」）；列表为「第N周 · 周一 · 迟到」。

### 6.3 性能与埋点

- [ ] 进课表首屏不因全学期矩阵构建明显卡顿；滑邻近周有预热。
- [ ] Track 收到 `perf` / `course_week_first_paint` 且 `duration_ms` 合理；peer 模式不报。

### 6.4 页头

- [ ] 刷新与查看他人位置已对调。
- [ ] 刷新弹出全局确认；取消不请求；确认才拉取并 toast。
