---

## 1. 背景

**Why**：AI 页对话目前仅存内存，离开页面或杀进程即丢失，无法多会话切换续聊；业内 Agent 产品普遍提供本机会话列表。  
**What**：在本机按学号持久化最多 10 条会话（LRU），于 AI 页顶栏提供左侧抽屉管理会话，支持续聊、删除、清空；登出清除。

---

## 2. 目标

1. 用户发出消息后的会话可本地保存，杀进程后可从侧边栏找回并续聊（含工具卡片所需数据）。
2. AI 页顶栏：左开抽屉、中固定「农屿 AI」、右「新对话」。
3. 侧边栏可浏览（时间分组）、切换、单删、清空全部；草稿不占配额。
4. 每学号最多 10 条；超限 LRU 淘汰；数据不上传；登出 / Token 失效本地清会话时清空。

---

## 5. 详细需求

### 5.1 数据模型（逻辑）

每个已落盘会话至少包含：

| 字段         | 说明                                            |
| ------------ | ----------------------------------------------- |
| `id`         | 稳定唯一 ID                                     |
| `title`      | 首条用户消息截断（约 20 字，超出加省略）        |
| `createdAt`  | 创建时间（ms）                                  |
| `updatedAt`  | 最近一次消息变更时间（ms）                      |
| `lastUsedAt` | LRU 用；打开或发用户消息时更新                  |
| `messages`   | `ChatMessage[]`（可 JSON 序列化；含 toolCalls） |

另需持久化：**当前活跃会话 id**（可为 null，表示草稿）。

欢迎语：草稿与新会话展示用；**落盘的 `messages` 是否包含欢迎语由实现自定**，但恢复后 UI 不得重复堆叠多条欢迎语，且续聊上下文行为与现页一致。

### 5.2 存储与配额

| 项     | 要求                                                         |
| ------ | ------------------------------------------------------------ |
| 介质   | MMKV（`appStorage`）                                         |
| 分桶   | key 含 `studentId`；无学号时不得写入用户会话（或仅内存草稿） |
| 上限   | 每学号 **10** 条已落盘会话                                   |
| 超限   | 写入新会话前，删除 `lastUsedAt` 最小的 1 条（并列任选其一）  |
| 序列化 | `JSON.stringify`；tool 的 input/output 须为可 JSON 化数据    |
| 远程   | 禁止上传                                                     |

### 5.3 登出与鉴权失效

在下列路径中增加「清除当前学号（或全部）Agent 会话本地数据」：

- `performJiaowuLogout`
- `clearLocalAuthSession`（Token 失效）

清除后：侧边栏为空；再进 AI 页为新草稿。须同时 `invalidate` 内存中的会话相关状态（若有）。

### 5.4 AI 页顶栏

| 区域 | 行为                                                                                                                |
| ---- | ------------------------------------------------------------------------------------------------------------------- |
| 左   | 图标按钮，打开左侧会话抽屉；需可访问性标签（如「会话列表」）                                                        |
| 中   | 固定文案「农屿 AI」                                                                                                 |
| 右   | 「新对话」图标/按钮；生成中点击：不 stop，切到新草稿并改订阅（旧会话后台继续）；细则见《农屿 Agent 生成保活不中断》 |

未配置模型：顶栏与抽屉仍可用（可看历史、删会话）；输入发送逻辑保持现有「未配置」空态/限制。

### 5.5 会话侧边栏（左侧抽屉）

| 项       | 要求                                                                                                                            |
| -------- | ------------------------------------------------------------------------------------------------------------------------------- |
| 形态     | 自左侧滑入覆盖层 + 半透明遮罩；点遮罩或返回手势关闭                                                                             |
| 顶区     | 「新对话」入口；其下为按标题搜索框                                                                                              |
| 搜索     | 按会话标题子串匹配（忽略首尾空白、大小写不敏感）；输入后模拟远程拉取假延迟约 **450ms** 再出结果；延迟中展示加载态；无结果有空态 |
| 列表分组 | **今天** / **昨天** / **更早**（按 `updatedAt` 或 `lastUsedAt`，Spec 约定用 `updatedAt` 分组展示，LRU 仍用 `lastUsedAt`）       |
| 列表项   | 标题一行截断；次要信息显示相对时间或短日期                                                                                      |
| 当前会话 | 视觉高亮（与主题 brand / brandMuted 一致，避免卡片堆砌）                                                                        |
| 点击项   | 关闭抽屉 → 切换到该会话并 touch `lastUsedAt`                                                                                    |
| 单删     | 标题右侧垃圾桶图标，点击二次确认；删除当前会话则切到新草稿                                                                      |
| 清空全部 | 入口 + `confirm` 二次确认；确认后删光并进入新草稿                                                                               |
| 空态     | 文案引导开始新对话                                                                                                              |

### 5.6 会话生命周期

```
[新草稿] --首条用户消息--> [已落盘] --续聊/stop--> [增量保存]
     ^                         |
     |                         +-- 用户删除 / LRU 淘汰 / 清空 / 登出 --> 销毁
     |
  「新对话」或删除当前会话后
```

| 事件                 | 行为                                                                               |
| -------------------- | ---------------------------------------------------------------------------------- |
| 进入 `/ai`           | 若有活跃会话 id 且仍存在 → 加载；否则新草稿                                        |
| 首条用户消息成功发出 | 创建会话、写 title、计入配额（必要时 LRU）、设为活跃                               |
| 一轮回复结束 / stop  | 持久化当前 `messages`，更新 `updatedAt`                                            |
| 打开某历史会话       | 设为活跃，更新 `lastUsedAt`，remount 聊天（`key=sessionId`）                       |
| 新对话               | 活跃 id 置空；展示欢迎语草稿；不写盘                                               |
| 生成中切换           | **不** `stop`；改订阅目标，旧会话后台跑完落盘（见保活不中断 Spec）；他会话发送互斥 |

### 5.7 续聊与 SDK 约束

- `useAgentChat` 的 `initialMessages` 仅首 mount 生效；**切换会话必须用 `key` remount**（或等价强制重建）。
- 恢复的 messages 须足以驱动现有 `MessageList` / 工具卡片渲染（保留 `toolCalls`）。
- 不在本期要求改 Agent 服务端上下文；续聊即本地历史 + 后续新消息照常 `append`/`handleSubmit`。

### 5.8 标题规则

- 取**第一条** `role === "user"` 的 `content`，去首尾空白，截断约 **20** 个字符（按码点/可视字符合理即可），超出加 `…`。
- 若异常无用户消息（不应落盘），不创建会话。

## 6. 业务流程

### 6.1 首次对话并保存

1. 用户进入 AI 页 → 新草稿（或恢复活跃会话）。
2. 发送首条消息 → 创建会话 → 列表可见。
3. 杀进程 → 再进 AI → 恢复该活跃会话内容。

### 6.2 多会话切换

1. 打开抽屉 → 点另一会话 → 抽屉关闭 → 消息列表变为该会话。
2. 再发消息 → 仅更新该会话；`lastUsedAt` 更新。

### 6.3 LRU

1. 已有 10 条，再在新草稿发首条消息。
2. 淘汰 `lastUsedAt` 最旧的一条后写入新会话。
3. 被淘汰会话不可再打开。

### 6.4 登出

1. 用户登出或 Token 失效清本地。
2. Agent 会话本地数据清空；再登录进 AI 为新草稿，侧栏为空。

## 7. 验收标准与测试方案

### 7.1 UI / 交互（理想态）

| 场景       | 期望                                                            |
| ---------- | --------------------------------------------------------------- |
| 顶栏       | 左菜单、中「农屿 AI」、右新对话；风格贴合现有 AI 页与主题 Token |
| 抽屉       | 左侧滑入；遮罩可关；列表分组正确；当前项高亮                    |
| 空态       | 无会话时有引导，无报错                                          |
| 删除       | 单删后列表刷新；清空前有确认，取消不删                          |
| 未配置模型 | 仍可打开抽屉管理历史；发送仍受限                                |

### 7.2 功能检查清单

- [ ] 首条消息后侧栏出现会话，标题来自首条用户文案截断
- [ ] 杀进程后活跃会话内容与 tool 卡片可恢复续聊
- [ ] 草稿（仅欢迎语）杀进程后不出现在列表
- [ ] 新对话不立刻增加列表项，直到首条用户消息
- [ ] 切换会话 / 新对话在生成中不主动 stop；旧会话可后台完成并落盘（见保活不中断 Spec）
- [ ] 第 11 个会话创建后总数仍为 10，且最久未用者消失
- [ ] 打开会话但不发消息也会推迟其 LRU 淘汰（相对未打开者）
- [ ] 侧栏按标题搜索：有假延迟加载态，匹配正确，无结果有提示
- [ ] 单删、清空全部、登出、Token 失效后数据符合 §5.3 / §5.5
- [ ] 同机换学号登录看不到另一学号会话（分桶）
- [ ] 重回 `/ai` 恢复上次活跃会话（仍存在时）
- [ ] 聊天中点卡片进他页再返回：消息列表与输入态仍在（非欢迎语重置）

### 7.3 非功能

- 单会话 messages 体积需可接受（本期不设硬上限；异常巨大时允许失败并 toast，不得白屏）
- 抽屉打开/关闭不得导致聊天输入状态错乱（切换会话时输入框清空为佳）
