| 项       | 内容                                                                      |

| 应用     | `apps/nongyu-rn-app`（主）；必要时轻量触达 `nongyu-agent-sdk` 仅限接线层  |

| PRD      | `docs/forhuman/rawprds/nongyu-rn-app/Shell/农屿Agent生成保活不中断PRD.md` |
| 入口     | `/ai` 对话生成；App 前后台切换；离开 / 返回 AI 页                         |
| 关联     | 农屿 Agent 会话管理、`useAgentChat` / Agent 单例、全局 Toast / confirm    |

本 Spec **修正**《农屿 Agent 会话管理》Grill「生成中切换 → 先 `stop()`」：改为生成中切会话 / 离页 **不**主动 `stop`，由本 Spec 接管。

---

## 1. 背景

**Why**：生成中切后台或离开 AI 页时，可能因系统挂起，或因离页主动 `stop()`，导致大模型调用中断，体验差。  
**What**：轻量尽力保活；离页 / 切后台不主动中断；回前台若已异常中断则 Toast；主动停止 / 登出仍立即中断。

---

## 2. 目标

1. 生成中将 App 切到后台再回前台：在系统允许的短时后台窗口内尽量继续生成；若仍因挂起/断流中断，回前台 Toast 告知并可重试。
2. 生成中离开 AI 页（返回上一页等）：**不**调用 `agent.stop()`；生成在模块级 Runner 中继续，完成后按会话管理规则落盘。
3. 生成中切换查看其他会话 / 点「新对话」：旧会话生成继续；回到该会话可见完整或进行中结果。
4. 同一时刻仅允许 **一路** 生成（受现有 Agent 单例约束）；他会话发起发送须拦截并 Toast。
5. 停止按钮、登出、`invalidateNongyuAgent` 仍立即中断并做必要落盘 / 清态。

## 5. 详细需求

### 5.1 运行时归属

- 进行中的生成（messages 流式更新、`isLoading`、当前 `sessionId`/草稿键）由 **模块级单例 Runner** 持有，生命周期 **不**绑定 `AiChatPanel` 挂载。
- `/ai` 页挂载时订阅当前查看会话（或草稿）的 Runner 快照；卸载时 **取消订阅**，**不** `stop`。
- 现有「失焦 `stopAndPersist`」行为废除，改为：失焦 / 离页仅 **落盘当前可见快照（可选）** 或依赖 Runner 在完成 / 停止时落盘；**禁止**因离页调用 `stop()`。

### 5.2 前后台

- 监听 `AppState`：进入 `background`/`inactive` 且 Runner 正在生成时，申请平台允许的 **短时后台执行**（尽力；失败不单独 Toast）。
- 回到 `active` 时：
  - 若 Runner 仍在生成 → 正常继续展示（若当前在 AI 页且订阅该会话）。
  - 若本次生成已因网络错误 / 流中断 / 进程挂起导致异常结束（非用户点停止）→ **Toast**（文案见 §5.6），并将对应 assistant 消息标为可感知的失败或保留已生成部分（与现 `useAgentChat` 错误语义对齐）。

### 5.3 会话切换与发送互斥

- **查看**其他会话 / 新对话草稿：允许；不停止正在跑的会话。
- **发送**（含快捷建议触发）：若 Runner 已有进行中的生成且目标不是「允许续写的同一逻辑 run」（即已有一路 busy）→ **拦截**，Toast「请等待当前回复完成」。
- 删除正在生成的会话 / 清空全部：须先 `stop` 该 run（或全部），再删数据（避免幽灵写入）。
- 登出 / `invalidateNongyuAgent`：`stop` + 清 Runner 态（会话数据清除规则仍跟会话管理 Spec）。

### 5.4 工具审批

- `toolApproval.onApprove` 在离页或后台时 **不得**自动拒绝或自动通过。
- 审批 Promise 可挂起；用户回到 AI 页且 App 前台后再展示 confirm；用户确认/取消后继续 Loop。

### 5.5 落盘

- 生成完成、用户停止、异常中断：对 **该会话** 按会话管理 Spec 增量落盘（含已生成部分）。
- 离页不强制要求立即完整落盘，但完成/停止/异常路径必须落盘，保证再进入可见一致结果。

### 5.6 Toast 文案

| 场景                   | 文案（可微调，语义不变）             |
| ---------------------- | ------------------------------------ |
| 回前台发现生成异常中断 | 「应用进入后台后生成已中断，请重试」 |
| 他会话/忙碌时尝试发送  | 「请等待当前回复完成」               |

普通业务错误（API Key、模型 4xx 等）仍走现有「对话失败」类 Toast，不与后台中断文案混用。

### 5.7 与会话管理 Spec 的关系

| 原会话管理约定                        | 本期变更                              |
| ------------------------------------- | ------------------------------------- |
| 生成中切换：先 `stop()`，已生成部落盘 | **废止**；改为不 stop，后台跑完再落盘 |
| 回页保持内存态 / 勿误卸面板           | 仍有效；Runner 单例后更易满足         |

## 6. 业务流程

### 6.1 生成中切后台

```
用户发送 → Runner 生成中
  → AppState background → 申请短时后台（尽力）
  → AppState active
       ├─ 仍在生成 → 继续
       └─ 已异常中断 → Toast（§5.6）+ 落盘已有内容
```

### 6.2 生成中离 AI 页再返回

```
生成中 → 离开 /ai（取消订阅，不 stop）
  → Runner 继续 → 完成则落盘
  → 再进入 /ai → 订阅该会话 → 展示完成或进行中消息
```

### 6.3 生成中切会话后尝试发送

```
会话 A 生成中 → 用户打开会话 B
  → 在 B 点发送 → 拦截 + Toast「请等待当前回复完成」
  → A 完成后 → B 可发送
```

## 7. 验收标准与测试方案

### 7.1 功能

- [ ] 生成中按 Home，短时内回前台：多数情况下可继续出字/出工具卡（尽力，不 100% 保证长后台）。
- [ ] 人为长时间挂后台导致中断：回前台出现 §5.6 后台中断 Toast；已生成部分已落盘或可见。
- [ ] 生成中返回上一页再进 AI：未因离页被 stop；完成后消息完整；再进入与落盘一致。
- [ ] 生成中切到其他会话仅浏览：A 继续；在 B 发送被拦截并 Toast。
- [ ] AI 页停止按钮：立即停止当前 run。
- [ ] 登出 / 清鉴权：生成停止，Runner 清空。
- [ ] 需审批工具：离页期间不自动拒绝；回 AI 前台后可 confirm 并继续。
- [ ] 删除正在生成的会话：先停再删，无向已删 id 继续写入。

### 7.2 UI / 操作（理想）

- AI 页仍为现有对话布局；忙碌时他会话发送无双生流、无错乱气泡。
- Toast 使用全局 toast，文案符合 §5.6。
- 切回仍在生成的会话时，输入区仍为「停止」态（`isLoading`），与现页一致。

### 7.3 回归

- [ ] 会话抽屉切换、新对话、LRU、登出清会话仍符合会话管理 Spec。
- [ ] 摘要压缩 Toast / 落盘不被本需求破坏。
- [ ] 用户主动停止 **不** 误弹「后台中断」Toast。
