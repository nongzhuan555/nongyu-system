## 1. 背景

学生端「广场」Tab（`/(tabs)/center`）目前仅为占位。Node 侧广场帖子接口（列表 / 详情计阅读 / 发帖 / 删帖 / 最新公告 / 我的帖子）已可联调。本期在 App 落地三区内容与发帖阅读能力，并打通首页通知栏与「我的帖子」，形成完整业务闭环。

**为什么做**：提供官方公告触达、匿名反馈渠道，并以「农屿大院」轻量试探社交属性。反馈墙与大院对用户彼此匿名，署名仅管理端可见。

---

## 2. 目标

1. 广场主界面以分段切换 **公告 / 反馈墙 / 大院**，共用列表卡片组件。
2. 支持列表分页、下拉刷新；点击进入详情（打开详情即触发服务端阅读统计；App 端列表/详情不展示阅读量）。
3. 反馈墙、大院支持纯文本发帖；公告只读。
4. 首页通知栏对接 `GET /api/app/posts/announcements/latest`，点击直达该公告详情。
5. 「我的」提供「我的帖子」入口：列表展示 `viewCount`，可删除本人帖。
6. 开发期可用 mock App JWT 联调（不入库、不提交仓库）。

---

## 3. 边界（非目标）

- 不做评论、点赞、图片/音频、HTML 富文本编辑器（后续版本再升级）。
- 不支持用户编辑已发布帖子。
- 不做管理端发公告 UI（公告由 Admin 已有接口产生）。
- 不在本期完善「我的」整页 PRD（仅加「我的帖子」入口与独立列表页）。
- 不编写独立技术方案文档（`tech/`）；规格确认后写简短实施计划再编码。
- App 列表/详情 **永不展示** `viewCount` / `uniqueReaderCount`（仅「我的帖子」展示 `viewCount`）。
- 不把联调 mock Token 硬编码进仓库；仅通过本地 env / `__DEV__` 注入。

## 4. 详细需求

### 4.1 路由

| 界面         | 路由约定            | 说明                                                                             |
| ------------ | ------------------- | -------------------------------------------------------------------------------- |
| 广场主界面   | `/(tabs)/center`    | 三分段 + 当前分段列表                                                            |
| 帖子详情     | `/center/post/[id]` | 公告 / 反馈 / 大院共用；打开即计阅读                                             |
| 发帖         | `/center/compose`   | Query：`postType=feedback\|courtyard`                                            |
| 我的帖子     | `/mine/posts`       | 从「我的」进入                                                                   |
| 首页通知跳转 | → `/home/notice`    | **一律**进公告列表（复用广场 `PostFeedList`，固定 `announcement`）；不再直达详情 |

`/home/notice`：顶栏「公告」+ 返回；列表行为与广场「公告」分段一致（含进详情）。

### 4.2 鉴权与联调 Token

- 所有广场相关 App 接口需 `Authorization: Bearer <App JWT>`。
- 正式路径：使用 `session.token`（登录签发）。
- **仅 `__DEV__`**：若 `session.token` 为空，可读 `EXPO_PUBLIC_DEV_APP_TOKEN`（本地 `.env`，gitignore）作为请求 Token，便于当前联调。
- 生产构建不得依赖 mock Token；无 Token 时请求不发出，UI 提示需登录 / 引导登录。
- 联调用 mock JWT **禁止写入 Spec 正文、禁止 commit**。

### 4.3 广场主界面（`/(tabs)/center`）

#### 信息架构

- 顶部分段：**公告** | **反馈墙** | **大院**（对应 `postType`: `announcement` / `feedback` / `courtyard`）。
- 默认落在「公告」。
- 切换分段：重置为第 1 页并请求对应列表；可保留各分段已加载缓存（React Query），非必须强制清空。

#### 列表

- 接口：`GET /api/app/posts?postType=&page=&pageSize=`（默认 `pageSize=20`）。
- 排序：服务端 `publishedAt DESC`。
- 卡片字段展示：
  - 发布时间（本地化相对或 `YYYY-MM-DD HH:mm`，全 App 一致即可）
  - 类型标签（见 §4.7 subtype 映射）
  - 标题
  - 内容摘要 `contentPreview`
  - **不展示作者**：反馈墙与大院对用户彼此匿名（`authorDisplayName` 恒为 `null`）；公告不强调作者名。署名仅管理端可见。
- 交互：点击卡片 → 详情。
- 分页：上拉加载更多；到底无更多时提示「没有更多了」。
- 下拉刷新：刷新当前分段第 1 页。
- 回顶 FAB：下滑超过阈值后右下角霜膜圆钮；点击动画回顶并刷新（见 `docs/nongyu-rn-app/specs/列表回顶悬浮按钮.md`）。
- 状态：loading 骨架 / 空态文案 / 错误态可重试。
- 滚动内容需兼顾悬浮底栏叠压（与底栏 Spec 一致：底部留白或渐隐）。

#### 发帖入口

- **仅**「反馈墙」「大院」显示右下角或顶栏「发帖」入口；「公告」无发帖。
- 进入 `/center/compose?postType=...`。

### 4.4 帖子详情

- 接口：`GET /api/app/posts/:id`（成功即服务端计阅读）。
- 展示：标题、类型标签、发布时间、正文；**不展示作者名**（含大院）。
- **首次加载**：展示详情骨架屏（标题/元信息/多行正文占位），禁止仅用「加载中…」文案。
- 正文本期按 **纯文本** 渲染（`Text`）；若历史公告含 HTML 标签，可做简单去标签后展示，**不**引入 WebView/富文本引擎。
- `isMine === true` 时可提供删除（与列表删除同一确认流）；公告不可删。
- 删除成功：返回上一页并失效相关列表缓存。

### 4.5 发帖（纯文本）

- 接口：`POST /api/app/posts`
- 表单：
  - `postType`：由路由锁定，不可改
  - `subtype`：必选（§4.7）
  - `title`：1–200 字
  - `content`：非空纯文本（`TextInput` multiline）
- 成功：Toast + 返回对应分段列表并刷新。
- 校验失败 / 网络错误：Toast 展示服务端或本地错误信息。

### 4.6 首页通知栏联调

- 请求 `GET /api/app/posts/announcements/latest`。
- 有数据：栏上展示最新公告 `title`。
- **无数据 / 失败 / 无 Token：必须回退显式占位文案（`FIXED_NOTICE`），栏位 UI 始终保留；禁止因无数据整栏隐藏。**
- **点击（无论真实公告或占位）→ `/home/notice` 公告列表**；列表内再点卡片进详情。
- loading：保留现有骨架形态。
- 失败：不阻断首页；用占位文案兜底（不强制 Toast 刷屏）。

### 4.7 subtype 客户端约定

| postType       | subtype 值   | 展示文案                                                               |
| -------------- | ------------ | ---------------------------------------------------------------------- |
| `announcement` | 服务端原样   | 优先映射：`system`→系统公告，`activity`→活动公告；未知则原文或「公告」 |
| `feedback`     | `feedback`   | 反馈                                                                   |
| `feedback`     | `suggestion` | 建议                                                                   |
| `feedback`     | `bug`        | Bug                                                                    |
| `courtyard`    | `life`       | 生活                                                                   |
| `courtyard`    | `study`      | 学习                                                                   |
| `courtyard`    | `other`      | 其他                                                                   |

发帖 UI：反馈墙三选一；大院三选一。不做自由输入。列表不做 subtype 筛选（本期）。

### 4.8 我的帖子

- 「我的」Tab 增加入口「我的帖子」→ `/mine/posts`。
- 接口：`GET /api/app/users/me/posts`（可选 `postType`；本期默认两类合查）。
- 卡片在广场列表字段基础上 **额外展示** `viewCount`（如「阅读 12」）。
- 支持分页、下拉刷新、删除本人帖（`DELETE /api/app/posts/:id`，二次确认）。
- 删除公告类不会出现在该列表（契约已排除）。

### 4.9 API 封装与数据层

- 在 `src/api/`（或 `src/modules/center/api/`）封装帖子相关请求，复用统一 envelope 解析（对齐现有 `appAuth.ts` 的 `parseApiResponse` 模式；宜抽公共 `appFetch`，避免复制粘贴）。
- 列表/详情优先 TanStack Query（与教务模块一致）：按 `postType` / `id` / `me` 分 key；详情打开不强制乐观更新阅读量（App 不展示）。
- Token 解析优先级：`session.token` →（仅 DEV）`EXPO_PUBLIC_DEV_APP_TOKEN`。

### 4.10 UI 基调（高级简约 · 主题无关）

- **颜色一律走语义 Token**（`lightTokens.color.brand` / `brandMuted` / `background` / `surface` / `text` / `textSecondary` / `border` 等），禁止硬编码某一品牌色（如川农绿 hex）；主题切换后广场 UI 必须跟色。
- 整体气质：**高级简约**——大留白、弱分割、少描边卡片堆叠、无多阴影；签名记忆点为顶部分段的玻璃胶囊 + 选中指示器。
- 三区共用同一套 `PostCard`（或等价）组件。
- **页背景**：与首页 /「我的」共用 `TabScreenBackground`（`primaryContainer` → 近底色 → `background`，`locations` `[0, 0.48, 0.78]`），禁止广场单独一套渐变范围。

#### 4.10.1 顶部分段（对齐底部悬浮 Tab）

- 形态：水平**全圆胶囊**，三项均分（公告 / 反馈墙 / 大院）。
- 材质：与底栏同一套水滴选中动效；因广场页在 `BlurTargetSurface` **内部**，**禁止**再嵌套真 `BlurView`（Android 易闪退）。
- **底色**：胶囊必须使用主题浅系 `brandMuted`（可略透），保证未滚动时也能一眼认出是 Tab。禁止「几乎透明」导致看不见分段条。
- 选中态：椭圆指示器与轨底**同系轻抬升**——`surface` 半透明叠在 `brandMuted` 上（透出轨色），极弱同色描边或无描边；**禁止**实心白块 + 品牌色硬描边造成突兀切块。文案选中为 `brand`，未选中为 `textSecondary`。
- 动效：与底栏 `TabLiquidIndicator` **同一套水滴参数**（水平滑动 + 途中拉伸 + 落地轻弹；约 380–450ms 软弹簧；连点可打断追新项）。
- 发帖入口：仅反馈墙/大院；顶栏右侧极简图标按钮（语义色），不做实心大胶囊抢戏。

#### 4.10.2 列表 / 详情 / 发帖 / 我的帖子

- 列表：**简约圆润卡片**（`surface` 底 + 轻描边或极弱分隔感，圆角用 token `radius.md`/`lg`）；标题主层级 + 预览次层级 + meta 轻量；骨架与卡片形态一致。禁止做成无底色的纯文字流（易与背景糊成一片）。
- **顶部滚出渐隐**：默认完全不透明。仅当**同时**满足：① 用户正在滑动列表；② 卡片已有 **≥50%** 高度滚出顶部不可见——才开始把剩余可见部分插值变透明（50%→约 78% 不可见对应不透明→**完全透明**，终点偏早以便观感更透）。静止、或不可见不足 50% 时保持不透明。实现须兼容 FlashList 回收，避免卡顿。
- 详情：阅读排版（更大行距、标题与正文拉开）；顶栏干净；删除为文字危险色。
- 发帖：输入区弱边框/大留白；subtype 选择与分段气质一致（轻选中态，跟主题）。
- 我的帖子：顶栏与详情同族；列表复用广场卡片并展示阅读量。

## 5. 业务流程

### 5.1 浏览广场

```
进入广场 → 默认公告分段 → GET posts?postType=announcement
→ 点击卡片 → GET posts/:id（计阅读）→ 展示详情
切换反馈墙/大院 → 对应列表；可发帖 → POST → 回列表刷新
```

### 5.2 首页通知

```
进入首页 → GET announcements/latest
→ 有公告：栏上展示最新 title；无公告 / 失败 / 无 Token：FIXED_NOTICE（栏位不消失）
→ 点击公告栏 → /home/notice（复用 PostFeedList · announcement）
→ 列表点卡片 → 详情
```

### 5.3 我的帖子

```
我的 → 我的帖子 → GET users/me/posts
→ 可看 viewCount → 删除确认 → DELETE → 列表更新
```

## 6. 验收标准与测试方案

### 6.1 UI / 交互验收

| #   | 场景             | 期望                                                    |
| --- | ---------------- | ------------------------------------------------------- |
| 1   | 打开广场         | 见玻璃胶囊三分段，默认公告列表或空/错态；无硬编码品牌色 |
| 2   | 切换分段         | 指示器水滴滑动；列表随 `postType` 变化；底栏不遮挡末条  |
| 3   | 上拉             | 有下一页则追加；无则「没有更多了」                      |
| 4   | 点卡片           | 进详情，正文可读；返回后列表仍在                        |
| 5   | 反馈墙/大院发帖  | 选 subtype + 标题正文，成功后列表可见新帖               |
| 6   | 公告分段         | 无发帖入口；不可删他人/公告                             |
| 7   | 首页有最新公告   | 通知栏文案正确；点击进 `/home/notice` 公告列表          |
| 8   | 首页无公告       | 通知栏仍在，展示占位文案；点击同样进 `/home/notice`     |
| 9   | 我的帖子         | 可见本人帖与阅读数；删除后消失                          |
| 10  | DEV 无登录 Token | 配置 `EXPO_PUBLIC_DEV_APP_TOKEN` 后广场可请求成功       |
| 11  | 匿名性           | 反馈墙/大院列表与详情不展示作者名；他人帖无署名线索     |

### 6.2 联调验收（对照联调指南 §6.3 / 清单）

- [ ] `GET /api/app/posts?postType=announcement|feedback|courtyard` 列表与 App 一致
- [ ] App 列表/详情 `authorDisplayName` 恒为 `null`；Admin 详情仍有 `authorName`/`authorStudentNo`
- [ ] `POST` 发 `feedback` / `courtyard` 后列表可见
- [ ] `GET /api/app/posts/:id` 可打开；重复打开不导致 App 崩溃（阅读计数在服务端）
- [ ] `GET /api/app/posts/announcements/latest` 驱动首页通知栏
- [ ] `GET /api/app/users/me/posts` + `DELETE` 在「我的帖子」可用
- [ ] 未授权 / Token 失效时有可读错误提示

### 6.3 非功能

- 不在 git 中出现 mock JWT 明文。
- `pnpm lint` / `type-check` / `format` 通过（编码阶段）。
