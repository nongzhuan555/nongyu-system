## 1. 背景

广场三区（公告 / 反馈墙 / 大院）已有列表、详情、发帖、删帖、我的帖子能力，但**不支持回复 / 留言**，且**无任何轮询**。本期：

- 反馈墙详情展示管理员单条回复（统一「管理员回复」，不暴露管理员身份）。
- 大院详情展示用户匿名留言列表，并支持当前用户发表 / 删除自己的留言。
- 引入 30s 轮询：广场 Tab 前台轮询反馈墙 / 大院列表；App 任意前台轮询「我的帖子新回复」并 toast。
- 「我的帖子」列表项展示回复状态角标。

公告墙不参与本次变更（不轮询、不回复）。

## 2. 目标

1. 帖子详情按 `postType` 展示回复 / 留言：feedback 显示 `adminReply`；courtyard 显示 `comments` 并可发可删自己的。
2. 广场 Tab 前台时，反馈墙 / 大院列表每 30s 自动 refetch 第 1 页（公告分段不轮询）。
3. App 任意前台时，每 30s 轮询 `GET /api/app/users/me/post-replies/new`，对返回项 toast。
4. 「我的帖子」列表项展示「已回复 / N 条留言」角标。
5. 复用既有 `appFetch` / TanStack Query / toast / confirm / 主题 token / 骨架屏体系。

## 3. 边界（非目标）

- 不做嵌套回复 UI（楼中楼）。
- 不做留言 / 回复的点赞、举报、富文本、图片。
- 不做公告墙的回复 / 留言 / 轮询。
- 不做后台轮询（App 进入后台 / 失活立即停止）。
- 不做用户编辑自己留言的 UI（仅删除）。
- 不做推送通知（仅前台 toast）。
- 不在列表卡片展示回复 / 留言内容（仅「我的帖子」展示数量角标）。
- 不引入新的全局状态管理库；轮询用 TanStack Query `refetchInterval` + AppState 控制。

## 4. 数据模型与 API 封装

### 4.1 类型扩展（`src/modules/center/api/posts.ts`）

在既有 `PostDetail` 上新增可选字段（保持向后兼容）：

```ts
export type AdminReply = {
  content: string;
  publishedAt: string;
};

export type PostComment = {
  id: number;
  content: string;
  publishedAt: string;
  isMine: boolean;
};

export type PostDetail = {
  // ...既有字段
  /** feedback：管理员单条回复（无作者信息，用户侧统一「管理员回复」） */
  adminReply?: AdminReply | null;
  /** courtyard：顶层留言列表（匿名，isMine 自识） */
  comments?: PostComment[];
};
```

`PostListItem` 新增可选字段（「我的帖子」用，普通广场列表服务端可不返回）：

```ts
export type PostListItem = {
  // ...既有字段
  /** 未软删回复总数（含 admin_reply 与 comment）；仅 me/posts 返回 */
  replyCount?: number;
  /** 是否存在未软删回复；仅 me/posts 返回，便于角标 */
  hasReply?: boolean;
};
```

### 4.2 新增 API 函数

```ts
/** POST /api/app/posts/:id/comments —— 大院留言 */
export async function createPostComment(
  postId: number,
  body: { content: string },
): Promise<{ id: number; publishedAt: string }>;

/** DELETE /api/app/posts/:id/comments/:commentId —— 删自己的留言 */
export async function deletePostComment(postId: number, commentId: number): Promise<void>;

/** GET /api/app/users/me/post-replies/new —— 轮询我的新回复 */
export type NewPostReply = {
  replyId: number;
  postId: number;
  postType: PostType;
  postTitle: string;
  kind: "admin_reply" | "comment";
  content: string;
  createdAt: string;
};
export async function fetchNewPostReplies(): Promise<NewPostReply[]>;
```

鉴权、envelope 解析、`appFetch` 复用既有模式（与 `posts.ts` 一致）。

## 5. 详细需求

### 5.1 帖子详情（`PostDetailScreen` 扩展）

#### 5.1.1 反馈墙详情

- 在正文下方渲染 `adminReply` 区块（若存在）：
  - 标签「管理员回复」（语义色 `brand`，弱底 `brandMuted` 胶囊或文字标签，与 subtype 标签同族）。
  - 回复正文（纯文本，与帖子正文排版同族但可略小 / 弱分隔）。
  - 回复时间 `formatPublishedAt(adminReply.publishedAt)`。
  - **不展示**任何管理员姓名 / 学号 / 头像。
- 若 `adminReply` 为 null，不渲染该区块（无空态文案；反馈墙未回复即不显示）。

#### 5.1.2 大院详情

- 在正文下方渲染留言区：
  - 标题行「留言」+ 留言数量（如「留言 · 3」），语义色 `textSecondary`。
  - 留言列表：每条展示内容 + 时间；**不展示**作者任何标识。
  - `isMine === true` 的留言：右上角弱标记「我」（`textSecondary`，极弱底），并提供删除入口（文字危险色「删除」，二次确认 `confirm`）。
  - 排序：服务端 `created_at ASC`。
  - 空态：留言数为 0 时展示极简空态文案「还没有留言」。
- 底部留言输入区（固定在详情底部安全区上方）：
  - `TextInput` multiline，placeholder「说点什么…（匿名留言）」。
  - 发送按钮（语义色 `brand`），防重复提交（`isPending` 禁用）。
  - 长度上限 1000，超限本地拦截 + toast。
  - 发送成功：乐观追加到列表末尾（`isMine=true`），清空输入，`invalidateQueries(['posts','detail',id])` 拉取最新。
  - 失败：toast 错误信息，输入内容保留。

#### 5.1.3 公告详情

- 不渲染 `adminReply` / `comments` 区块（保持现状）。

### 5.2 轮询机制

#### 5.2.1 列表轮询（广场 Tab 前台）

- 仅当 **当前分段为 `feedback` 或 `courtyard`** 且 **广场 Tab 处于前台**（AppState `active` 且路由为 `/(tabs)/center`）时，对应列表 `useInfiniteQuery` 启用 `refetchInterval: 30_000`。
- `announcement` 分段 **不启用** `refetchInterval`（保持下拉刷新 / 分页 / focus refetch 既有行为）。
- 轮询触发后：仅 refetch 第 1 页（`refetchPage: (page, idx) => idx === 0`），不自动追加新页；新帖出现在顶部，用户上拉可加载更多。
- 轮询失败：静默不 toast（避免刷屏）；TanStack Query 自动退避重试。
- AppState 切到后台 / 失活：`refetchInterval` 置为 `false`（通过 `enabled` / 动态 `refetchInterval` 控制）。

#### 5.2.2 我的新回复轮询（App 任意前台）

- 新建全局轮询 hook `useNewPostRepliesPoller()`，在 **App 根布局**（或登录后根容器）挂载：
  - `useQuery({ queryKey: ['posts','me','new-replies'], queryFn: fetchNewPostReplies, refetchInterval: 30_000, enabled: isForeground && isAuthed })`。
  - `isForeground` 由 `AppState` 监听（`active` 为 true）。
  - `isAuthed` 由 session token 是否存在决定；未登录不轮询。
- 对每次成功返回的**新数据**（与上次相比新增的项）逐条 toast：
  - `kind='admin_reply'`：「你的反馈帖《{postTitle}》已被管理员回复」。
  - `kind='comment'`：「你的大院帖《{postTitle}》收到新留言」。
  - toast 点击：跳转到对应帖子详情 `/center/post/{postId}`。
- 去重：服务端已置位 `notified_author`，同一回复不会重复返回；客户端额外用 `replyId` 集合做幂等保护（避免 refetch 同批数据重复 toast）。
- 轮询失败：静默。
- App 进入后台：停止轮询；回前台立即触发一次 refetch。

### 5.3 「我的帖子」列表（`MyPostsScreen` 扩展）

- 列表卡片在既有字段基础上，若服务端返回 `replyCount` / `hasReply`：
  - feedback 帖：展示「已回复」/「未回复」角标（语义色：已回复 `success`，未回复 `textSecondary`）。
  - courtyard 帖：展示「N 条留言」角标（N=0 时展示「暂无留言」弱文案）。
- 角标样式极简（小号文字 + 弱底胶囊），不抢标题视觉。
- 其余交互（分页 / 下拉刷新 / 删帖）不变。

### 5.4 删除自己的帖子

- 既有删除流程不变；删除成功后 `invalidateQueries(['posts'])` 同时失效详情（含 comments）。

### 5.5 UI 基调

- 严格遵循 `design-system/rn-app/MASTER.md` 与既有 `广场功能.md` §4.10「高级简约 · 主题无关」基调。
- 颜色一律走语义 token；回复 / 留言区块复用 `surface` / `brandMuted` / `border` / `textSecondary`，禁止硬编码品牌色。
- 留言输入区与发帖页同族（弱边框、大留白、跟主题）；**固定在详情底部**。
- 键盘弹出时输入条底边对齐键盘上沿（`useComposerKeyboardInset`；Android 使用 `softwareKeyboardLayoutMode: pan` 避免双倍顶起）。
- 多行输入增高至上限后**输入框内部滚动**，不推动整页布局、不改变输入条相对键盘的位置。
- 留言列表不做卡片堆叠，用弱分隔线 + 留白区分（避免与帖子卡片视觉冲突）。
- 「管理员回复」标签与 subtype 标签同族胶囊，但用 `brandMuted` 底 + `brand` 文字以示官方回复身份。

## 6. 业务流程

### 6.1 大院留言

```
进大院帖详情 → GET posts/:id（含 comments）
  → 底部输入留言 → POST posts/:id/comments → 201
  → 乐观追加（isMine=true）
  → 删自己留言 → DELETE posts/:id/comments/:commentId → 软删移除
```

### 6.2 反馈墙查看管理员回复

```
进反馈帖详情 → GET posts/:id
  → adminReply 非空 → 渲染「管理员回复」区块（无管理员姓名）
```

### 6.3 列表轮询

```
广场 Tab 前台 + 分段为 feedback/courtyard
  → useInfiniteQuery refetchInterval=30s，仅 refetch 第 1 页
  → 新帖顶部出现，自动渲染
公告分段 → 不轮询，下拉刷新既有行为
```

### 6.4 我的新回复 toast

```
App 任意前台 + 已登录
  → useQuery refetchInterval=30s 调 fetchNewPostReplies
  → 返回未通知项 → 逐条 toast → 点击跳详情
  → 服务端同事务置位，下次轮询不重复返回
```

## 7. 验收标准与测试方案

### 7.1 UI / 交互验收

| #   | 场景                                    | 期望                                                                                            |
| --- | --------------------------------------- | ----------------------------------------------------------------------------------------------- |
| 1   | 反馈帖有管理员回复                      | 详情正文下方见「管理员回复」标签 + 内容 + 时间；无管理员姓名                                    |
| 2   | 反馈帖无管理员回复                      | 详情不渲染回复区块                                                                              |
| 3   | 大院帖有留言                            | 详情正文下方见留言列表（内容 + 时间）；无作者标识                                               |
| 4   | 大院帖本人留言                          | 该条见「我」标记 + 删除入口；删除二次确认后移除                                                 |

| 6   | 大院帖无留言                            | 见「还没有留言」空态                                                                            |
| 7   | 公告详情                                | 不渲染回复 / 留言区块                                                                           |
| 8   | 广场 Tab 前台 + feedback/courtyard 分段 | 30s 后列表自动刷新第 1 页，新帖顶部出现                                                         |
| 9   | 广场 Tab 前台 + announcement 分段       | 不自动刷新；下拉刷新仍可用                                                                      |
| 10  | App 切到后台                            | 所有轮询停止；回前台立即触发一次                                                                |
| 11  | 未登录                                  | 新回复轮询不发起                                                                                |
| 12  | 我的帖子 - feedback 已回复              | 卡片见「已回复」角标                                                                            |
| 13  | 我的帖子 - courtyard 有 N 条留言        | 卡片见「N 条留言」角标                                                                          |
| 14  | 新回复 toast                            | 文案正确；点击跳对应详情；同条不重复 toast                                                      |
| 15  | 主题切换                                | 回复 / 留言区块跟色，无硬编码品牌色                                                             |

### 7.2 非功能

- 轮询不阻塞 UI；列表使用 FlashList 虚拟化（既有）。
- `pnpm lint` / `type-check` / `format` 通过。

## 8. 决策记录（grill 结论）

| 项                  | 结论                                             |
| ------------------- | ------------------------------------------------ |
| 需求分类            | 业务需求                                         |
| 反馈墙管理员回复 UI | 只读展示「管理员回复」，无管理员身份             |
| 大院留言 UI         | 顶层列表 + 底部输入；本人可删；完全匿名 + isMine |
| 列表轮询范围        | 仅 feedback/courtyard 分段 + 广场 Tab 前台       |

| 新回复 toast 去重   | 服务端置位 + 客户端 replyId 幂等集合             |
| 我的帖子角标        | feedback 已/未回复；courtyard N 条留言           |
