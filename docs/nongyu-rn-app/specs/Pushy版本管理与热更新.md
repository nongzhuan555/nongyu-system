| 项       | 内容                                                                                                   |
| -------- | ------------------------------------------------------------------------------------------------------ |

---

## 1. 背景

农屿 App 不进应用商店，正式分发依赖侧载 + [Pushy](https://pushy.reactnative.cn/) 热更新。一期已接入根树 `UpdateProvider`；本增量补齐「每次进入 App 检测」与设置页版本查看 / 手动检查。

**Why**：用户需可见版本号，并在无感热更之外能主动触发检查。  
**What**：检测策略改为冷启动 + 回前台；设置新增「版本」子页。  
**不做什么**：不接自研版本 API；不做强制更新自定义弹窗。

---

## 2. 目标

1. Release 包在有效 `appKey` 下：冷启动与从后台回前台均自动检查；有热更则 `silentAndLater` 静默下载，**下次冷启动**生效。
2. 开发态默认不检查；无效 key 不崩。
3. 设置首页可进「版本」：展示应用版本 / 构建号 / 热更状态；可手动检查更新（Toast 反馈）。
4. 运维手册与策略描述保持同步。

---

## 3. 边界（非目标）

- 不实现自定义热更弹窗 / `metaInfo.force` 强制热更 UI。
- 不实现应用内 APK 静默安装权限全流程（原生包过期可走 Pushy 默认 Alert / 打开 `downloadUrl`）。
- 不接 `/api/app/versions/*` 与管理端版本页。
- 不做「关于与反馈」整页（反馈渠道仍可即将开放）。
- 不在 Expo Go 保证热更；不做鸿蒙。

---

## 4. 详细需求

### 4.0 Grill 共识（增量）

| 决策     | 结论                                                                             |
| -------- | -------------------------------------------------------------------------------- |
| 检测时机 | `checkStrategy: "both"`（冷启动 + 回前台）                                       |
| 更新策略 | 仍为 `silentAndLater`                                                            |
| 设置入口 | 新增「版本」→ `/mine/settings/version`；关于与反馈可仍灰显                       |
| 展示信息 | 应用版本 + 构建号 + 热更 hash（无则「基准包」）                                  |
| 手动检查 | `checkUpdate` + Toast；有热更提示下次启动生效；不改系统 Alert 策略为默认弹窗热更 |

### 4.1 配置

同既有：`update.json` 分平台 `appKey`；`.update` 不入库；无效 key 直通。

### 4.2 客户端接入

| 项         | 要求                                                        |
| ---------- | ----------------------------------------------------------- |
| 初始化     | `updateStrategy: "silentAndLater"`，`checkStrategy: "both"` |
| Provider   | 全树唯一，挂于 `AppProviders` 最外                          |
| `__DEV__`  | 不设 `debug: true`；手动检查时 Toast 说明开发态不检热更     |
| 自动流水线 | 由 Provider 完成静默下载；业务页可不订阅                    |

### 4.3 设置「版本」子页

| 项       | 要求                                                                                                                                        |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 路由     | `/mine/settings/version`，`headerShown: false`，标题「版本」                                                                                |
| 首页     | 设置列表增加可进项「版本」，说明如「查看版本并检查更新」                                                                                    |
| 展示     | 应用版本（`expo-application` nativeApplicationVersion）；构建号（nativeBuildVersion）；热更：有 `currentHash` 显示截断 hash，否则「基准包」 |
| 无 Pushy | 仍展示应用版本/构建号；检查按钮 Toast「当前环境未启用热更新」                                                                               |
| 检查按钮 | 文案「检查更新」；loading 防抖                                                                                                              |

手动检查结果（Pushy 已启用且非 `__DEV__` 跳过）：

| 结果        | UX                                                                |
| ----------- | ----------------------------------------------------------------- |
| 已最新      | Toast「已是最新版本」                                             |
| 有热更      | Provider 已静默下载；Toast「已下载更新，下次启动后生效」          |
| 原生包过期  | 有 `downloadUrl` 时跟随 Pushy 默认引导；否则 Toast 提示需安装新包 |
| 失败/无结果 | Toast 错误或「检查失败，请稍后重试」                              |

### 4.4 与自研版本 API

禁止客户端调用 `/api/app/versions/check`。

### 4.5 文档

运维步骤以 [`Pushy版本管理手册.md`](../Pushy版本管理手册.md) 为准（决策树、路径 A 换壳 / 路径 B 热更、Windows CLI）。`开发文档.md` §7 只保留摘要并链到手册。

---

## 5. 业务流程

```text
冷启动 / 回前台（release + 有效 appKey）
  → checkStrategy=both 触发检查
  → 有热更 → silentAndLater 下载 → 下次冷启动生效

设置 → 版本
  → 展示本地版本信息
  → 点「检查更新」→ checkUpdate → Toast 反馈
```

---

## 6. 验收标准

| #   | 场景               | 期望                                 |
| --- | ------------------ | ------------------------------------ |
| 1   | release 回前台     | 会触发检查（可结合 Pushy 后台/日志） |
| 2   | 设置 → 版本        | 可见版本号与构建号；热更行有意义文案 |
| 3   | 手动检查最新       | Toast「已是最新版本」                |
| 4   | 手动检查有热更     | Toast 提示下次启动；再冷启动生效     |
| 5   | `__DEV__` 手动检查 | Toast 说明不检；不崩溃               |
| 6   | 无 appKey          | 版本页可开；检查 Toast 未启用        |
