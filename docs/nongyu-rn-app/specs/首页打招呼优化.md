---

## 1. 背景

首页 `Greeting` 现为本地单句 + 打字机，无骨架、无运营第二句。需改为「称呼 + 时段问候」+ 后端问候语，并在数据就绪后再播放打字机。

**Why**：更自然、可运营。  
**What**：本地第一段 + App 拉第二段 + 区域骨架 + 同一打字机。

---

## 2. 目标

1. 第一段：`{姓名}，{时段}好`；无姓名：`你好，{时段}好`。
2. 第二段：后端当前启用文案；失败/无数据/未登录用本地兜底。
3. 两段以 **中文逗号** 连接成同一句，**一条** `TypewriterText` 连续播放。
4. 打招呼区域 loading 时显示骨架；**完整文案就绪后**再撤骨架并开始打字。
5. 与通知栏骨架互不影响。

---

## 3. 边界（非目标）

| 非目标                        | 说明                          |
| ----------------------------- | ----------------------------- |
| Web Admin UI                  | 不在 RN / 本期                |
| AI / 天气问候                 | 不做                          |
| 改通知栏逻辑                  | 不动                          |
| 改打字机组件通用 API 除非必要 | 优先复用现有 `TypewriterText` |

## 5. 详细需求

### 5.1 时段与第一段

复用 `getTimeSlotLabel` 的 7 档切分（深夜 / 清晨 / 上午 / 中午 / 下午 / 傍晚 / 晚上）。

| 条件                          | 第一段文案         |
| ----------------------------- | ------------------ |
| `profile.name` 有 trim 后非空 | `{name}，{slot}好` |
| 否则                          | `你好，{slot}好`   |

示例：`唐磊，晚上好` / `你好，清晨好`。

### 5.2 第二段与完整文案

| 来源                                         | 第二段                      |
| -------------------------------------------- | --------------------------- |
| 接口成功且 `data.message` 非空               | trim 后的 `message`         |
| 未登录 / 请求失败 / `data=null` / message 空 | 本地常量 `祝你今天学习顺利` |

完整 `fullText`：

```text
{第一段}，{第二段}
```

（时段问候后接中文逗号；过长时自然折行，最多 **3** 行：`numberOfLines={GREETING_MAX_LINES}`，预留高度 `34 * 3`。）

### 5.3 数据加载

对齐通知栏模式（`useQuery` + session hydrated + Token）：

- Hook 建议：`useGreetingBootstrap`（命名可等价）。
- `enabled`：会话 hydrated 且存在 App Token。
- 无 Token：不请求；`loading` 仅在等待 hydrated 时可 true；就绪后立即用兜底第二句，**不**长时间骨架。
- 有 Token：pending 且无缓存数据 → `loading=true` → 骨架。
- 成功 / 失败 / null → `loading=false`，拼好 `fullText` 后交给打字机。
- `staleTime` 建议 ≥ 60s；回到首页可 refetch（对齐 Notice，非硬性，但推荐）。

**铁律**：打字机的 `fullText` 在某次展示周期内应在撤骨架时已是终稿；禁止先打第一段再异步改全文导致重开打字。

### 5.4 骨架屏

- 新增打招呼骨架（如 `GreetingSkeleton`）：三行脉冲条，宽度约 62% / 88% / 74%，高度对齐字号行高，水平 padding 与 `Greeting` 一致。
- `loading === true` → 只渲染骨架。
- `loading === false` → 渲染 `TypewriterText`（`active=true`）。

### 5.5 组件行为

- `Greeting` 读取 session 姓名 + bootstrap 结果。
- 复用 `TypewriterText`（末字 boost 等可保持现状）。
- 姓名在会话中从无到有：允许下次进入首页或 refetch 后用新姓名重新打字；本期不要求打字中途热更新姓名。

### 5.6 API 客户端

- 封装 `GET /api/app/home/greeting`（`appFetch`，需鉴权）。
- 类型：`{ id: number; message: string } | null`。

---

## 6. 业务流程

```text
进入首页 Greeting
  → hydrated？否：骨架（短）
  → 无 Token：第二段=兜底 → 拼 fullText → 打字机
  → 有 Token：骨架 → 请求 greeting
       → 成功有 message：第二段=message
       → 否则：第二段=兜底
  → 撤骨架 → TypewriterText(fullText)
```

---

## 7. 验收标准与测试方案

### UI / 交互（理想描述）

1. 17:30 登录用户「唐磊」：骨架短暂出现后打出：`唐磊，傍晚好，后端配置句（或兜底）`。
2. 无姓名会话：第一行为 `你好，{时段}好`。
3. 断网 / 接口失败：仍有第二行兜底，不空白、不卡死骨架。
4. 未登录进首页（若可达）：不长时间骨架，本地兜底可打字。
5. 通知栏仍可独立骨架；打招呼与通知互不等待。
6. 打字过程中布局不剧烈跳动（预留高度生效）。

### 回归

- 通知栏、常用网站、入口卡不受影响。
- `首页模块骨架.md` 中「问候无骨架 / 单句本地文案」以本 Spec 为准覆盖。
