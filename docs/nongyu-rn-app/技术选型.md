## 1. 目标与约束

### 1.1 目标

为农屿学生端（课表、登录鉴权、我的/设置、Agent、埋点等）提供可长期维护的跨端客户端技术底座。

### 1.2 硬约束

- 技术路线固定在 **React Native 生态**，跨平台友好（Android / iOS 同一套架构与依赖策略）。
- **不进入应用商店**；安装包侧载 / 内部分发（如蒲公英、OSS 直链等）。
- 开发过程中须保持 **随时可发 Android，也可直接发 iOS**（禁止 Android 专用捷径、单端写死原生能力）。
- 排期上允许 **Android 先发验证**，但工程与依赖从第一天按双端选型。
- 敏感数据（Token、教务密码本地缓存）不得明文持久化。
- 埋点与故障上报 **不采用任何商用 SaaS**；自研或开源自托管封装。

### 1.3 非目标 / 搁置

| 项                           | 说明                                                                                                                   |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| 上课本地通知                 | PRD 允许暂缓；**本期不引入** `expo-notifications`，可能不做                                                            |
| 应用商店分发与商店内更新跳转 | 明确不做                                                                                                               |
| 原生崩溃采集                 | **本版客户端明确不做**；仅 JS 层（ErrorUtils / 可选 Error Boundary）。原生层崩溃不采集、不接商用 APM；是否另开版本再议 |
| 服务端实现细节               | Token、Track、教务代理等后端方案另开文档；本文只定客户端侧                                                             |

## 3. 应用架构层

| 领域             | 选型                                             | 说明                                                        |
| ---------------- | ------------------------------------------------ | ----------------------------------------------------------- |
| 路由             | **Expo Router**                                  | 文件路由；登录态分流、深层链接友好                          |
| 客户端状态       | **Zustand**                                      | 会话、主题、课表 UI 偏好等；不承载服务端缓存                |
| 网络与服务端缓存 | **TanStack Query** + axios（或 fetch）           | 用户信息、课表拉取、重试与焦点刷新；与本地持久化分层        |
| 表单校验         | **zod**                                          | 登录学号格式、设置与自定义课程等表单                        |
| 日期计算         | **dayjs**                                        | 开学日期、周次等                                            |
| 日期选择 UI      | **`@react-native-community/datetimepicker`**     | 系统原生选择器                                              |
| 教务身份校验     | **App 直连教务**，成功后再请求自家后端签发 Token | 可复用 `nongyu-tool-jiaowu`；后端不存教务密码（见登录 PRD） |
| Agent            | 正式依赖 **`nongyu-agent-sdk`**                  | 设置中开关与 API Key / 模型配置                             |

## 4. UI 与交互

| 领域                  | 选型                                                               | 说明                                                                                                     |
| --------------------- | ------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------- |
| 样式与主题            | **StyleSheet + Design Token**                                      | 支持川农新绿 / 樱花浅粉 / 暗黑 / 跟随系统；不与大型 UI Kit 绑死                                          |
| 组件策略              | **自研组件库为主**                                                 | 复杂交互引入成熟实现，避免重复造轮子翻车                                                                 |
| 半屏详情弹层          | **`@gorhom/bottom-sheet`**                                         | 依赖 Reanimated / Gesture Handler；课表卡片详情等                                                        |
| 列表                  | **FlashList 为主**，短列表可用 FlatList                            | 长列表与埋点中的列表性能场景                                                                             |
| 动画与手势            | **`react-native-reanimated`** + **`react-native-gesture-handler`** | 弹层、课表滑动切周、按压反馈等                                                                           |
| Toast                 | **`react-native-toast-message`**                                   | 网络错误、业务提示等                                                                                     |
| 图标                  | **`@expo/vector-icons`**                                           | **Ionicons filled 为主**，MaterialIcons 实心为辅；禁止以 outline / Feather 为主风格；要求圆角饱满 filled |
| 内置浏览器            | **`expo-web-browser` 为主**                                        | 设置「网页打开方式」；必要时再上 WebView                                                                 |
| 图片                  | **`expo-image`** + **`expo-image-picker`**                         | 课表周视图背景图等                                                                                       |
| 课表海报 / 二维码分享 | **view-shot（或等价）** + **qrcode-svg** + **`expo-sharing`**      | 依赖方向先定；实现可按 PRD 优先级后置                                                                    |

设计视觉细则见后续 `design-system/rn-app`（若空则另开 UI 定调，不在本文展开）。

## 5. 本地存储

| 数据类别       | 选型                                   | 示例                                       |
| -------------- | -------------------------------------- | ------------------------------------------ |
| 敏感           | **`expo-secure-store`（SecureStore）** | Token、教务密码（自动登录）                |
| 偏好与业务缓存 | **MMKV**                               | 主题、首屏是否课表、开学日期、课表 JSON 等 |

说明：课表以 JSON 文档缓存即可，首版不上 SQLite；登出须清空敏感与隐私相关本地数据（见登录 PRD）。

## 6. 埋点与可观测性（自研）

**原则**：不使用商用埋点 / APM SaaS；客户端自研 Telemetry SDK，上报自有 Track API。

| 能力            | 方案                                                                                                      |
| --------------- | --------------------------------------------------------------------------------------------------------- |
| 页面浏览        | Expo Router **全局自动**打 `screen_view`（全页面覆盖，禁止仅靠每页手写）                                  |
| 按钮点击        | **可追踪封装组件 / HOC** + **事件名常量**；重点按钮显式埋点                                               |
| 性能            | SDK 内 `measure` 等；覆盖课表渲染耗时、部分列表耗时（可采样）                                             |
| 故障（本版）    | **仅 JS**：全局异常处理 + Error Boundary → Track `crash`。**原生层崩溃：本版不做**（产品决策 2026-08-15） |
| 传输            | 内存队列 + **批量 POST** + 失败写入 **MMKV** 重试                                                         |
| 在线状态 / 日活 | 由行为与心跳类事件支撑（协议字段在 Track 服务 Spec 中定义）                                               |
| 服务端落点      | 客户端约定打 **自有 Track API**；实现预定 **`nongyu-go-track-server`**（另开基建，本文不展开接口）        |

## 7. 版本管理与更新（Pushy）

分发：**不进应用商店**。热更新采用 [Pushy 极速热更新](https://pushy.reactnative.cn/)（npm：`react-native-update`，CLI：`pushy`）。

### 7.1 与 Expo 的关系

- **禁止**同时安装 `expo-updates` / 使用 EAS Update（与 Pushy 冲突）。
- 仍可使用 **EAS Build** 产出 APK / IPA；OTA 走 Pushy。

### 7.2 两层版本

| 层                      | 含义                                                      | 操作                                                                      |
| ----------------------- | --------------------------------------------------------- | ------------------------------------------------------------------------- |
| 原生壳 `packageVersion` | `versionName` / `CFBundleShortVersionString` 对应的安装包 | 打 release → `pushy uploadApk` / `uploadIpa` → **同一份文件**再分发给用户 |
| 热更包                  | JS / 静态资源变更                                         | `pushy bundle` → publish → 绑定到对应原生版本                             |

展示版本采用 **SemVer**（如 `1.2.3`）；Android `versionCode` / iOS `buildNumber` 单调递增（可由 EAS 自动管理）。

**硬约束**：用户安装包必须与已 upload 的基准包一致（含编译时间戳）；重新编译同版本号必须重新 upload，否则可能无法领取热更。

### 7.3 客户端策略

| 项       | 选型                                                                   |
| -------- | ---------------------------------------------------------------------- |
| 检查时机 | 启动检查（可按 Pushy `checkStrategy` 配置）                            |
| 热更默认 | **`silentAndLater`**：静默下载，下次冷启动生效                         |
| 强制热更 | 自定义 UI + `metaInfo`（如 `force`）                                   |
| 强制换壳 | Pushy **`expired` + 后台 `downloadUrl`**（指向自托管 APK/IPA，非商店） |
| 灰度     | Pushy `rollout`（按需）                                                |

原生变更（新原生依赖、权限、升 Expo SDK 等）必须发新壳并升 `packageVersion`；仅业务 JS 变更走热更。

### 7.4 构建与分发分工

| 动作       | 工具                                       |
| ---------- | ------------------------------------------ |
| 开发调试   | Dev Client + Metro                         |
| 正式壳构建 | EAS Build 优先；本地打包允许               |
| 热更发布   | Pushy CLI / 管理后台                       |
| 安装包分发 | 侧载 / 内测平台 / OSS 等（**非应用商店**） |

## 8. 依赖清单（逻辑名）

工程初始化时按 Expo SDK 矩阵安装兼容版本；下列为逻辑选型，非钉死 semver。

**核心**：`expo`、`expo-dev-client`、`expo-router`、`react`、`react-native`、TypeScript

**状态与数据**：`zustand`、`@tanstack/react-query`、`axios`（或 fetch）、`zod`、`dayjs`

**UI / 交互**：`@gorhom/bottom-sheet`、`@shopify/flash-list`、`react-native-reanimated`、`react-native-gesture-handler`、`react-native-toast-message`、`@expo/vector-icons`

**设备与媒体**：`expo-secure-store`、`react-native-mmkv`、`expo-web-browser`、`expo-image`、`expo-image-picker`、`@react-native-community/datetimepicker`、`expo-sharing`、海报/二维码相关库（view-shot、qrcode-svg 等）

**更新**：`react-native-update`（Pushy）；**不要** `expo-updates`

**工作区**：`nongyu-tool-jiaowu`、`nongyu-agent-sdk`

**自研**：Telemetry SDK（应用内模块或 packages 均可，实现阶段定路径）
