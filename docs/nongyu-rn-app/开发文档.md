## 1. 背景

农屿 App 面向四川农业大学学生，核心能力包括：教务登录（登录即注册）、课表周视图、我的/设置、Agent、自研埋点，以及**不进应用商店**的侧载分发 + [Pushy](https://pushy.reactnative.cn/) 热更新。

工程形态为 **Expo + Dev Client（prebuild）**：日常改 JS 用 Metro；凡新增**原生模块**需重打 Dev Client / 正式壳，并重新 `pushy upload*`（分发包必须与上传基准包一致）。

本仓库为 pnpm monorepo；RN 应用位于 `apps/nongyu-rn-app`，可复用 `nongyu-tool-jiaowu`、`nongyu-agent-sdk`。

## 3. 目录结构（骨架）

```text
apps/nongyu-rn-app/
  app/                 # Expo Router 文件路由
    _layout.tsx        # 根布局 + Provider
    (tabs)/            # 首页 / 课表 / 广场 / 我的
    ai.tsx             # 农屿 AI 聊天页（Agent + Generative UI）
    login.tsx          # 登录骨架
  src/
    theme/             # Design Token（v3 色板已迁入；切换待设置页）
    stores/            # Zustand
    providers/         # Query / 手势 / Toast 等
    storage/           # MMKV（无原生时内存回退）
    agent/             # Agent 实例与 mock 模型（基建 demo）
    agent-ui/          # Generative UI 渲染框架：工具→组件注册表 + 内联渲染
    components/
      agent/           # Agent 内联卡片组件（WeatherCard 等）
      navigation/      # 悬浮底栏、毛玻璃 BlurTarget 等
  assets/              # 图标、闪屏
  app.json             # Expo 配置（包名、scheme、插件）
  eas.json             # EAS Build Profile
  babel.config.js
  metro.config.js      # monorepo watchFolders
```

路径别名：`@/*` → `src/*`。

## 4. 如何把项目跑起来

在**仓库根目录**执行。

### 4.1 安装依赖

```bash
pnpm install
# 或只装本应用及其依赖：
pnpm --filter nongyu-rn-app install
```

### 4.2 类型检查（不启 UI 也可验证）

```bash
pnpm --filter nongyu-rn-app type-check
```

### 4.3 开发：Dev Client（推荐，与选型一致）

**首次或原生依赖变更后**需要生成本地原生工程并安装到设备：

```bash
cd apps/nongyu-rn-app
pnpm prebuild          # 生成 android/ / ios/（已 gitignore，可本地生成）
pnpm android           # 或 pnpm ios
```

之后日常只改 JS/TS：

```bash
pnpm --filter nongyu-rn-app start
# 等价：cd apps/nongyu-rn-app && pnpm start
```

用已安装的 Dev Client 扫码 / 自动连上 Metro。

也可用 EAS 打开发壳（适合不想本机编原生时）。`eas-cli` 已作为本应用 **devDependency** 持久安装，在应用目录用：

```bash
cd apps/nongyu-rn-app
pnpm exec eas login
pnpm exec eas init    # 首次关联项目，写入 app.json 的 extra.eas.projectId
pnpm eas:build:dev    # 云端打 development Android APK
# 等价：pnpm exec eas build --profile development --platform android
```

不要用 `pnpm eas -- build ...`（`--` 会被当成 eas 的子命令，报 `command -- not found`）。

EAS 云端安装依赖后会跑 `eas-build-post-install`：构建 `nongyu-tool-jiaowu` / `nongyu-tool-second` / `nongyu-agent-sdk`（其 `dist/` 被 gitignore，必须在远端现编，否则 Bundle JS 会失败）。本地 Expo 模块（如 `modules/nongyu-android-widget/android`）必须入库；应用 `.gitignore` 仅忽略根目录 `/android`、`/ios`。该模块 `android/build.gradle` 必须声明 `defaultConfig.versionName`（及 `versionCode`），否则 `expo-autolinking` 配置 `:nongyu-android-widget` 时会失败。

### 4.4 仅用 Expo Go（不推荐做产品路径）

```bash
pnpm --filter nongyu-rn-app start:go
```

部分原生能力（如 MMKV、Pushy）在 Expo Go 中不可用；骨架里 MMKV 有内存回退，但**正式开发请用 Dev Client**。

### 4.5 验证打包链路（可选）

```bash
cd apps/nongyu-rn-app
pnpm exec expo export --platform android --output-dir dist-android
```

能成功导出说明 Metro / 依赖解析正常（产物目录已 ignore）。

### 4.6 非同局域网预览：USB + adb reverse（Android）

手机与电脑 **不在同一 Wi‑Fi** 时，可用 USB 把手机的 `localhost:8081` 转到电脑 Metro（不必开 Expo tunnel）。

#### 步骤

1. 安装 **Android SDK Platform-Tools**（需有 `adb`）。本机若未装、且 PATH 无 `adb`，可用：

   ```powershell
   winget install --id Google.PlatformTools -e --accept-package-agreements --accept-source-agreements
   ```

   安装后需 **新开终端**（或刷新 PATH）再执行 `adb`。

2. 手机开启 **开发者选项 → USB 调试**（一加 / ColorOS 等若有「USB 调试（安全设置）」一并打开）。用数据线连接电脑，弹出 **「允许 USB 调试」** 时点允许（可勾选始终允许）。

3. 确认设备与端口转发：

   ```powershell
   adb devices
   adb reverse tcp:8081 tcp:8081
   adb reverse --list
   ```

   `adb devices` 应出现 `device`（不是空、也不是 `unauthorized`）。`reverse --list` 中应有 `tcp:8081 tcp:8081`。

4. 电脑照常启动 Metro：

   ```bash
   pnpm --filter nongyu-rn-app start
   ```

5. 手机打开已安装的 **Dev Client**，连不上时手动填：`http://localhost:8081`（或 `exp://127.0.0.1:8081`）。

插拔线、重启 `adb`、重启手机后，需重新执行 `adb reverse tcp:8081 tcp:8081`。

#### 踩坑经验（2026-08-14，一加 Ace 5 Pro + Windows）

| 现象                                                                | 原因 / 处理                                                                                                                                                                                    |
| ------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 通知栏已选「传输文件 / MTP」，但 `adb devices` 仍为空               | **MTP ≠ USB 调试**。Windows 可能已认出「一加 Ace 5 Pro」（WPD/便携设备），但设备管理器里没有 `Android ADB Interface`。必须单独打开 USB 调试，并处理「允许 USB 调试」弹窗（与传文件弹窗不同）。 |
| 电脑有 **深信服 Sangfor VDI Usbhub**（设备管理器里可能为 Degraded） | 易劫持 USB，导致只有 MTP、没有 ADB。退出 / 关掉 USB 重定向或相关客户端后再插手机。                                                                                                             |
| `adb` 命令找不到                                                    | 未装 Platform-Tools 或未进 PATH；用上文 `winget` 安装并重开终端。                                                                                                                              |
| `unauthorized`                                                      | 手机点允许调试；或 `adb kill-server` → `adb start-server` 后重插。                                                                                                                             |
| 多台设备                                                            | `adb -s <序列号> reverse tcp:8081 tcp:8081`。                                                                                                                                                  |

**说明**：本方案只解决 **Metro / JS Bundle** 连通。App 调 Node API 见下方 **§4.7**（跨网用 Cloudflare 临时隧道）。

异地临时预览 Metro 也可用 `pnpm --filter nongyu-rn-app start -- --tunnel`；长期协作可考虑 Tailscale 等组网。Android 真机 Metro 优先本小节 USB reverse（更稳、更低延迟）。

### 4.7 跨网联调 Node API（Cloudflare 临时隧道）

权威步骤与约束见 Node 侧 [`联调指南.md`](../nongyu-node-server/联调指南.md) **§2.6 / §3.1 / §7.1**。RN 侧只记客户端怎么配。

| 场景                          | `EXPO_PUBLIC_API_BASE_URL`（无尾斜杠） |
| ----------------------------- | -------------------------------------- |
| 本机 / Expo Web               | 默认 `http://127.0.0.1:3000`（可不设） |
| Android 模拟器访问本机 Node   | `http://10.0.2.2:3000`                 |
| 真机且与电脑同局域网          | `http://<电脑局域网IP>:3000`           |
| **真机跨网 / 无同网**（推荐） | `https://<随机子域>.trycloudflare.com` |

**跨网时配合方式**（Metro 与 API 分开）：

1. 本机 Node 已在 `3000` 监听；按联调指南 §2.6 启动 `cloudflared tunnel --url http://127.0.0.1:3000`，记下日志里的 `https://….trycloudflare.com`。
2. 在 `apps/nongyu-rn-app/` 建本地 `.env`（gitignore，勿提交）：

   ```bash
   EXPO_PUBLIC_API_BASE_URL=https://<随机子域>.trycloudflare.com
   # 可选：广场等未走登录时的 mock JWT（仅 __DEV__）
   # EXPO_PUBLIC_DEV_APP_TOKEN=...
   ```

3. Metro 用 §4.6 的 `adb reverse`（或同网扫码）连上 Dev Client；**改完 `.env` 须重启 Metro / 重开 App** 后变量才生效。
4. 探活：`curl -s https://<随机子域>.trycloudflare.com/health` 应与本地一致（`code=0`，`db=up`）。

**注意**：

- 须同时保持 **Node + cloudflared**；隧道重启后 URL 通常会变，`.env` 要跟着改。
- 临时隧道仅开发联调，禁止当生产入口。
- 配置读取见 `src/config/env.ts`（`API_BASE_URL`）。

### 4.8 联调埋点服务（Track）

权威步骤见 [`联调指南-埋点.md`](./联调指南-埋点.md)。RN 侧只记客户端怎么配。

**现状（2026-08-15）**：本机 Track HTTP 可联调；RN Telemetry SDK **一期已接入**（见 [`联调指南-埋点.md`](./联调指南-埋点.md) §9 测试方法）；云上 Track 机尚未部署。

| 场景                                        | `EXPO_PUBLIC_TRACK_BASE_URL`（无尾斜杠）                                         |
| ------------------------------------------- | -------------------------------------------------------------------------------- |
| 本机 / Expo Web                             | 默认 `http://127.0.0.1:8082`（可不设）                                           |
| Android 模拟器                              | `http://10.0.2.2:8082`                                                           |
| USB 真机（`adb reverse tcp:8082 tcp:8082`） | `http://127.0.0.1:8082`                                                          |
| 真机同局域网                                | `http://<电脑局域网IP>:8082`（Track 须听 `0.0.0.0:8082`）                        |
| 真机跨网                                    | `https://<随机子域>.trycloudflare.com`（隧道指向 **8082**，勿与 Node 3000 混用） |

本机 Track **不要占用 8081**（与 Metro 冲突）。Token 与业务登录同一颗 App JWT。配置读取见 `src/config/env.ts`（`TRACK_BASE_URL`）。

## 5. 日常如何开发

### 5.1 工作流（SDD）

1. 确认有对应 PRD（`docs/forhuman/rawprds/...`）
2. 写 Spec →（按需）技术方案 → 实施计划 → 编码（见 `.agents/skills/sdd-guidelines`）
3. 改完跑：`pnpm --filter nongyu-rn-app type-check`，以及仓库级 `pnpm lint` / `pnpm fmt`
4. Commit 前按开发规范做 AI Review（有实际业务代码时）；husky 会跑 oxlint/oxfmt/commitlint

### 5.2 页面与路由

- 新页面：在 `app/` 下加文件即可（Expo Router）
- Tab：改 `app/(tabs)/`
- 登录等栈屏：与 `app/_layout.tsx` 中 `Stack.Screen` 对齐
- 教务登录走正式表单（`JiaowuLoginForm` → `performJiaowuLogin`：教务校验 → 档案 → Node Token），见 [`tech/教务鉴权方案.md`](./tech/教务鉴权方案.md)
- 未登录全局门禁只显示登录页，见 [`specs/登录门禁.md`](./specs/登录门禁.md)

### 5.3 状态与请求

- 客户端状态：`src/stores`（Zustand）——会话、主题偏好等
- 服务端数据：TanStack Query（在 `AppProviders` 已挂载）
- 敏感数据：SecureStore；偏好/课表缓存：`src/storage/mmkv.ts`
- 教务直连登录（已真机调通）：见 [`tech/教务鉴权方案.md`](./tech/教务鉴权方案.md) §8；实现在 `nongyu-tool-jiaowu` 的 `jiaowuLogin`

### 5.4 UI

- StyleSheet + `src/theme`（默认 `lightTokens` = 川农新绿；樱花/暗色色板已入库未切换）
- 图标：优先 **Ionicons filled**
- 复杂交互：Bottom Sheet / FlashList 等已进依赖，按需使用

### 5.5 何时必须重打原生壳

新增或升级带原生代码的依赖、改 `app.json` plugins / 权限 / 包名、升降 Expo SDK 后：

1. `pnpm prebuild`（或 EAS Build）
2. 重装 Dev Client / 正式包
3. 若已接入 Pushy：对新壳 `pushy uploadApk` / `uploadIpa`，**分发同一文件**

纯 JS/样式/业务逻辑变更：**不必**重打壳，可用 Pushy 热更（接入完成后）。

## 6. 如何调整配置

| 调整项                 | 位置                                                                                                |
| ---------------------- | --------------------------------------------------------------------------------------------------- |
| 应用名 / scheme / 包名 | `app.json` → `expo.name` / `scheme` / `ios.bundleIdentifier` / `android.package`                    |
| 版本号                 | `app.json` → `version`；iOS `buildNumber`；Android `versionCode`                                    |
| 闪屏 / 图标            | `assets/icon.png`、`adaptive-icon.png`、`splash-icon.jpg`（对齐旧版视觉）+ `app.json` splash / icon |
| EAS 构建档             | `eas.json`（development / preview / production）                                                    |
| Metro monorepo         | `metro.config.js`（含 `watchFolders`；为 `iconv-lite` 映射 `string_decoder`/`buffer` polyfill）     |
| 主题 Token             | `src/theme/`（`palettes` / `resolveColor` / `tokens`；默认川农新绿）                                |
| Expo 项目 ID           | `app.json` → `extra.eas.projectId`（执行 `eas init` 后替换）                                        |
| Pushy appKey           | `update.json`（按平台；见 [`Pushy版本管理手册.md`](./Pushy版本管理手册.md)）                        |
| 版本查看 / 检查更新    | 设置 →「版本」`/mine/settings/version`                                                              |

**不要**安装 `expo-updates`（与 Pushy 冲突）。

升级 Expo 大版本：显式决策 → 改 `expo` 版本 → `npx expo install --fix` → 全量回归 → 新壳 + Pushy 新基准包。

## 7. 如何发布（无应用商店）

整体链路见 [`技术选型.md`](./技术选型.md) 第 7 节，摘要如下。

### 7.1 打正式壳

```bash
cd apps/nongyu-rn-app
# 推荐
pnpm eas:build:prod
# 或本地
pnpm prebuild && cd android && ./gradlew assembleRelease
```

iOS 同理（需证书与 macOS）。

### 7.2 上传 Pushy 基准包并分发

1. 安装 CLI：`npm i -g react-native-update-cli`
2. `pushy login` → `pushy createApp` / `selectApp`（生成可提交的 `update.json`；本地 `.update` 勿提交）
3. `pushy uploadApk <同一份将分发的 apk>`（iOS：`uploadIpa`）
4. 将该 **完全相同** 的安装包放到蒲公英 / OSS / 内测渠道给用户

客户端一期已接入：`UpdateProvider` + `silentAndLater` + `onAppStart`（见 `src/modules/update/`、[`specs/Pushy版本管理与热更新.md`](./specs/Pushy版本管理与热更新.md)）。完整操作步骤见 [`Pushy版本管理手册.md`](./Pushy版本管理手册.md)。

### 7.3 仅 JS 热更

```bash
pushy bundle --platform android   # 或 ios
# 按 CLI 提示 publish，并绑定到对应原生 packageVersion
```

### 7.4 强制换壳

在 Pushy 后台将旧原生包标为过期，配置 `downloadUrl` 指向新 APK/IPA 下载地址（非商店链接）。细节见手册 §6。
