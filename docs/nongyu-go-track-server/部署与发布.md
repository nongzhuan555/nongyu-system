## 1. 目标与原则

### 1.1 目标

- 本机编写 / 调试 Go 代码
- 变更后尽快把**可运行产物**同步到 Track 专用机并重启生效
- 文档先行；口令、密钥、真实 IP 账号明细只放本机敏感文件

### 1.2 硬约束

| 项     | 约定                                                             |
| ------ | ---------------------------------------------------------------- |
| 发布物 | **Linux 二进制**（非整仓源码实时同步到服务器编译）               |
| 数据   | 服务器上 `DB_PATH` 的 SQLite 文件；**默认不**用本机库覆盖生产库  |
| 敏感   | IP/账号/口令/私钥 **不进 git**；公开文档只用占位符               |
| Agent  | 允许在已授权前提下使用本机敏感文件登录运维；操作前须有本文档依据 |

### 1.3 非目标（本期）

- 自动「保存即部署」（防止半成品上线）
- 在 2G 机上安装完整 Go 工具链做日常编译
- 把 Track 与业务 Node 强绑同一发布流水线（可后续再统一）

## 2. 推荐发布路径

```text
本机改代码 → 本机 go test / 手工验
    → 交叉编译 linux/amd64（或实测 arch）
    → scp/rsync 二进制到服务器
    → systemctl restart（或等价）
    → curl 本机回环 /health（经 SSH）
```

### 2.1 交叉编译（本机）

服务代码落地后，在 `apps/nongyu-go-track-server` 下：

```bash
# 架构以服务器 `uname -m` 为准；常见为 x86_64 → amd64
GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -o dist/nongyu-track ./cmd/track-server
```

Windows PowerShell：

```powershell
$env:GOOS = "linux"
$env:GOARCH = "amd64"
$env:CGO_ENABLED = "0"
go build -o dist/nongyu-track ./cmd/track-server
```

### 2.2 上传与重启

由本机脚本执行（脚本读 **gitignored** 环境文件，见 §4）：

1. 上传 `dist/nongyu-track` → 远程路径（如 `/usr/local/bin/nongyu-track`）
2. `chmod +x`
3. `systemctl restart nongyu-track`（单元名以实现/装机时为准）
4. 探活：`curl -s http://127.0.0.1:8081/health`（经 SSH 在远端执行）

### 2.3 何时全量同步源码

仅在需要服务器上排障、对照源码时，用 `git` 或受限 `rsync`（排除 `.env`、`*.db`）。**日常发布不以源码同步为主路径。**

## 3. 服务器角色（公开描述）

| 项       | 说明                                                                             |
| -------- | -------------------------------------------------------------------------------- |
| 角色     | Track 专用轻量云（已探活：CentOS 8 / x86_64 / 约 2C2G / 40G 盘，与方案假设一致） |
| 交叉编译 | **`GOOS=linux GOARCH=amd64 CGO_ENABLED=0`**（以探活 `uname -m=x86_64` 锁定）     |
| 进程     | 单实例 `nongyu-track`，监听本机（如 `127.0.0.1:8081`）                           |
| 数据目录 | 如 `/var/lib/nongyu-track/`（`track.db` + WAL）                                  |
| 备份目录 | 如 `/var/backups/nongyu-track/`                                                  |
| TLS      | Nginx/Caddy 反代终止（装机阶段再落细则）                                         |

真实 IP、SSH 用户、口令：**只写在** `服务器连接信息.md`（本机）。

## 5. 安全要求

1. **禁止**将 root 口令、私钥、`track-deploy.env`、`服务器连接信息.md` 提交到 git。
2. 聊天中出现过的口令视为已暴露风险：完成 SSH 公钥登录后，**应在云控制台或机器上修改 root 密码**，并改用密钥登录；部署脚本优先走密钥。
3. Agent / 脚本默认使用 `scripts/ops/track-deploy.env`；不得把口令写进可提交脚本正文。
4. 生产 SQLite 与备份目录权限收紧（仅运行用户可读）。

### 5.1 SSH 公钥登录（推荐运维方式）

本机专用密钥（不入库，放用户 `~/.ssh/`）：

| 项       | 约定                                                     |
| -------- | -------------------------------------------------------- |
| 私钥     | `%USERPROFILE%\.ssh\id_ed25519_nongyu_track`             |
| 公钥     | 同名 `.pub`                                              |
| 远端     | `/root/.ssh/authorized_keys` 追加本机公钥一行            |
| 部署 env | 设置 `TRACK_SSH_KEY_PATH` 指向私钥；口令字段可留空作备份 |

步骤摘要：

1. `ssh-keygen -t ed25519 -f ...\id_ed25519_nongyu_track -N "" -C "nongyu-track-deploy"`
2. 将 `.pub` 内容追加到服务器 `authorized_keys`（权限 `700`/`600`）
3. 用 `ssh -i <私钥> root@<host> 'echo ok'` 验证
4. 更新本机 `服务器连接信息.md` 与 `track-deploy.env`
5. **人工改 root 密码**（Agent 默认不改密，除非你显式要求）
