## 1. 目标与原则

### 1.1 目标

- Track 跑在 **独立轻量云** 上，数据为服务器 SQLite，不碰该机可能存在的 MySQL
- 公网只暴露 **Nginx :443**（及 ACME 用的 :80）；Go 进程不直接对公网监听
- 对外访问形态：`https://<公网IP>/...`（无域名）
- `main` 上 Track 目录有变更时，GitHub CD 交叉编译 linux/amd64、覆盖二进制并 **systemd 重启 + /health 回滚**

### 1.2 硬约束

| 项       | 约定                                                                                              |
| -------- | ------------------------------------------------------------------------------------------------- |
| 与 MySQL | Track **不连** MySQL。机上若有 mysqld，部署脚本**不得**重启/重装/覆盖                             |
| 发布物   | GitHub Ubuntu（或本机）`GOOS=linux GOARCH=amd64 CGO_ENABLED=0` 静态二进制（**禁止**在 2G 机编译） |
| 进程     | systemd 单元 `nongyu-track.service`；**不用** nohup / screen / 远端 `go run`                      |
| TLS      | Nginx 终止；Let’s Encrypt **IP 证书**（shortlived，约 6 天，必须自动续期）                        |
| 监听     | Track 仅 `127.0.0.1:8081`；Nginx `proxy_pass` 到该地址                                            |
| 敏感     | IP / SSH / `.env` 口令 **不进 git**                                                               |
| `.env`   | 只在服务器维护（`/etc/nongyu-track.env`）；日常发布**不同步**本机 `.env`、**不覆盖** SQLite       |

### 1.3 非目标（本期）

- 本机保存文件即自动 scp（须 push `main` 或手动 dispatch）
- 在服务器上日常编译 Go
- 把 Node 与 Track **强制一次全量发布**（按路径独立 job）
- 为 IP 申请普通 90 天域名证书
- 改动该机已有 MySQL

## 2. 拓扑

```text
公网客户端（App Telemetry / Node BFF）
    │  HTTPS  https://<Track公网IP>/
    ▼
Nginx :443（IP 证书）  +  :80（ACME；443 未放行时仍反代业务）
    │  HTTP  127.0.0.1:8081
    ▼
nongyu-track（systemd）
    │  文件  /var/lib/nongyu-track/track.db
    ▼
本机 SQLite（WAL）
```

Node 在**另一台机**：Track 的 `NODE_INTERNAL_BASE_URL` 填 Node 公网 HTTPS 根（无尾斜杠）。Node 的 `TRACK_BASE_URL` 填 Track 公网 HTTPS 根。双方 `INTERNAL_TOKEN` 对齐。禁止把对端配成 `127.0.0.1`。

## 3. HTTPS 绑 IP

与 Node 现网相同：

| 项       | 现网约定                                                                                |
| -------- | --------------------------------------------------------------------------------------- |
| 档案     | ACME `shortlived`；有效期约 **6 天**                                                    |
| 校验     | HTTP-01（webroot `/var/www/acme`）                                                      |
| 客户端   | `/root/.acme.sh/acme.sh`                                                                |
| 证书文件 | `/etc/nginx/certs/<公网IP>.fullchain.pem` 与 `.key`                                     |
| 续期     | crontab：`acme.sh --install-cronjob` 写入每 6 小时检查；成功后 `systemctl reload nginx` |
| 防火墙   | 公网 **80、443**；80 必须保留给 ACME                                                    |

客户端 Base URL：`https://<Track公网IP>`（无尾斜杠）。RN：`EXPO_PUBLIC_TRACK_BASE_URL`。

## 4. 推荐发布路径（日常）

日常：本机 `go test` / 手工验后 push `main`，由 [GitHub 持续交付](../common/GitHub持续交付.md) 交叉编译并安全重启。不覆盖 SQLite、不同步 `.env`。

应急：

```text
本机改代码 → 本机 go test / 手工验
    → powershell -File scripts/deploy-nongyu-track.ps1
    → 交叉编译 linux/amd64
    → scp 二进制到 /tmp，install 到 /usr/local/bin/nongyu-track
    → systemctl restart nongyu-track
    → SSH 上回环 curl http://127.0.0.1:8081/health
```

不上传：`.env`、`*.db`、源码、Windows 非 linux 产物。

二进制覆盖 + 重启通常数秒到半分钟（含本机编译）。

### 4.1 本机命令

```powershell
powershell -File scripts/deploy-nongyu-track.ps1
```

跳过编译（已有 `dist/nongyu-track`）：`-SkipBuild`。只上传不重启：`-SkipRestart`。

## 7. 装机清单（首次）

1. 创建用户 `nongyu-track` 与目录 `/var/lib/nongyu-track`、`/var/backups/nongyu-track`、`/var/www/acme`。
2. 写入 **仅服务器** `/etc/nongyu-track.env`（`HTTP_ADDR=127.0.0.1:8081`、`DB_PATH`、与 Node 对齐的 `JWT_SECRET` / `INTERNAL_TOKEN`、`NODE_INTERNAL_BASE_URL=https://<Node公网IP>`）。
3. 本机交叉编译并上传二进制；安装 systemd 单元（见 `apps/nongyu-go-track-server/deploy/nongyu-track.service.example`），`systemctl enable --now nongyu-track`。
4. 本机 `curl http://127.0.0.1:8081/health` 应 `ok`。
5. 安装 Nginx；从主配置去掉内联 `default_server`；按 `docs/nongyu-go-track-server/deploy/nongyu-track.nginx.conf.example` 配 80。
6. 用 **acme.sh** 申请 IP 短寿证书；`--install-cert` 的 reload 为 `nginx -s reload`。
7. 安全组：放行 80/443；**保持 8081、以及该机 3306 不对公网新开**（3306 历史策略不在本次改）。
8. Node 生产 `TRACK_BASE_URL` 改为 `https://<Track公网IP>` 并重启 Node。
9. 客户端改 `EXPO_PUBLIC_TRACK_BASE_URL` 为 `https://<Track公网IP>`。

## 8. 安全

1. 禁止把 root 口令、私钥、`track-deploy.env`、服务器 `.env`、`服务器连接信息.md` 提交到 git。
2. 聊天中出现过的口令视为已暴露：公钥登录可用后应在云控制台轮换 root 密码；Agent 默认不改密。
3. 生产 SQLite 与备份目录仅 `nongyu-track` 可写。
4. Admin 查询仍走 Node BFF，不要把 `INTERNAL_TOKEN` 下发到 App。
