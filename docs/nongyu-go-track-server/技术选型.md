## 1. 目标与约束

### 1.1 目标

为农屿自研埋点提供可长期维护的轻量接入服务，支撑：

- App 批量上报（页面 / 按钮 / 性能 / 启动 / 心跳 / JS 崩溃）
- 原始事件短保留 + 日聚合长保留
- 管理端经 Node BFF 查询的概览、趋势、维度分布、崩溃列表
- 心跳驱动业务库 `users.is_online` / `last_active_at` 回写

### 1.2 硬约束

- 语言与工程：**Go**，单二进制部署；纳入 monorepo 的 `apps/nongyu-go-track-server`。
- 存储：**嵌入式 SQLite**（本机文件）；**禁止**把埋点原始事件 / 聚合表写入业务 MySQL。
- 驱动：**`modernc.org/sqlite`（纯 Go）** + `database/sql`；**无 CGO**，运行机无需安装 SQLite 软件包。
- 进程：**单实例、单进程**；写入经应用内 **单 writer** 串行化。
- 部署假设：独立轻量云 **2 核 / 2G / 40G**；仅跑本服务 + SQLite。
- 鉴权：App 上报用与业务共享的 **App JWT**；Admin 查询仅内部 Token / 内网，**禁止公网直暴露**。
- 客户端：自研 Telemetry，**禁止商用埋点 / APM SaaS**（见 RN 选型 §6）。

### 1.3 非目标 / 后置

| 项                             | 说明                                     |
| ------------------------------ | ---------------------------------------- |
| ClickHouse / 独立 MySQL 分析库 | 一期不上；升级触发见技术方案 §2          |
| 原生崩溃采集                   | 二期                                     |
| 实时复杂漏斗 / 会话重放        | 一期不做                                 |
| 多实例水平扩展写               | 一期单实例；需要时再议迁库 / 架构        |
| Redis / MQ                     | 不上；背压与重试靠内存队列 + 客户端 MMKV |
| Node / Admin / RN 实现细节     | 另见对应项目文档；本文只定 Track 侧底座  |

## 2. 工程与运行时

| 项       | 选型                                                           | 说明                                                             |
| -------- | -------------------------------------------------------------- | ---------------------------------------------------------------- |
| 语言     | Go（与仓库 Go 模块版本对齐，实现时锁定）                       | 遵循项目 golang Skills                                           |
| 模块路径 | `apps/nongyu-go-track-server` 独立 `go.mod`                    | 与 Node/TS workspace 解耦                                        |
| HTTP     | **`net/http` + [`go-chi/chi`](https://github.com/go-chi/chi)** | 方案允许 chi/echo 择一；**本文锁定 chi**，依赖少、与标准库兼容好 |
| 构建产物 | 单静态/准静态二进制 `nongyu-track`                             | 无 CGO；linux/amd64 为主                                         |
| 配置     | 环境变量（启动时校验必填项）                                   | 缺关键配置直接失败                                               |
| 时区语义 | 业务日 `Asia/Shanghai`；库内时间 UTC ms                        | `stat_date` 按上海日历日计算                                     |

### 2.1 建议目录（落地可微调，原则不变）

```text
apps/nongyu-go-track-server/
  cmd/track-server/main.go
  internal/
    config/           # 环境变量解析与校验
    httpapi/          # 路由、中间件（鉴权、限流、body limit）
    ingest/           # 批量校验、幂等、presence 触发
    store/sqlite/     # DB、PRAGMA、backup、读写连接
    aggregate/        # 日聚合与原始清理
    presence/         # 超时扫描
    auth/jwt/         # App JWT 本地校验
    usersync/         # 必须：回写 Node 在线态
  go.mod
```

## 3. 存储与数据访问

| 项          | 选型                                         | 说明                                                       |
| ----------- | -------------------------------------------- | ---------------------------------------------------------- |
| 引擎        | **SQLite（WAL）**                            | 文件路径如 `/var/lib/nongyu-track/track.db`                |
| 驱动        | **`modernc.org/sqlite`**                     | 纯 Go；禁止默认走 CGO `mattn/go-sqlite3`（除非明确改选型） |
| 访问方式    | `database/sql` + 预编译语句                  | 禁止拼接 SQL                                               |
| 连接模型    | **写 1 条长连接**；查询可 `mode=ro` 只读连接 | 配合单 writer，降低锁竞争                                  |
| Schema 真相 | 技术方案 §8 DDL                              | 变更先改技术方案 / 再改迁移脚本                            |
| 迁移        | 版本化 SQL 或启动 embed 迁移                 | 初版可整包 DDL；后续增量编号                               |

### 3.1 启动 PRAGMA（与方案一致）

| PRAGMA         | 建议值                          |
| -------------- | ------------------------------- |
| `journal_mode` | `WAL`                           |
| `synchronous`  | `NORMAL`                        |
| `busy_timeout` | `5000`                          |
| `foreign_keys` | `ON`                            |
| `temp_store`   | `MEMORY`                        |
| `cache_size`   | `-20000`（约 80MB，可压测下调） |
| `mmap_size`    | `67108864`（可降为 0）          |

进程 RSS 目标 &lt; 200MB；`MemoryMax` 等部署细节见技术方案 §4 / §12。

## 4. 应用架构要点

| 领域     | 选型                                           | 说明                                                       |
| -------- | ---------------------------------------------- | ---------------------------------------------------------- |
| 写入路径 | 校验 → 单 writer 队列 → 批量事务               | `BEGIN IMMEDIATE` → 批量 INSERT → `COMMIT`；队列满返回 503 |
| 幂等     | `events.event_id` UNIQUE                       | 重复忽略，计入 `duplicated`                                |
| 聚合     | 进程内定时任务                                 | 日聚合 00:10；清理 03:00；在线超时每 1 分钟（上海业务日）  |
| 在线态   | Track `user_presence` + **必须**回写 Node      | 业务权威在 MySQL `users`；失败入重试队列                   |
| 心跳落库 | presence 每次更新；`events` 可 5 分钟/用户采样 | 仍触发 Node 回写（短时合并，如 30s）                       |

分层保存、VACUUM、备份策略不在本文展开，见技术方案 §6。

## 5. 安全与鉴权实现库

| 项              | 选型                                                        | 说明                                                                  |
| --------------- | ----------------------------------------------------------- | --------------------------------------------------------------------- |
| App JWT 校验    | 标准库 `crypto` + 轻量 JWT 库（如 `golang-jwt/jwt` 或等价） | 与 Node **共享 `JWT_SECRET`**；一期验签名 + `exp` + `typ=app` + `uid` |
| `token_version` | **一期不强制实时校验**                                      | 已作废 token 仍可上报可接受；二期可再议 Node 推送缓存                 |
| Admin / 运维    | `X-Internal-Token` 与配置 `INTERNAL_TOKEN` 常量时间比较     | 仅内网或反代后暴露                                                    |
| Body 限制       | 反代 + 服务端双重限制，建议 **≤ 1MB**                       |                                                                       |
| 限流            | 内存 token bucket：按 `user_id` + 按 IP                     | 如单用户 120 req/min；超限 429                                        |
| TLS             | Nginx/Caddy 终止                                            | 进程监听 `127.0.0.1:8081`（可配）                                     |

Claims 对齐 Node App JWT：`uid`、`studentNo`、`tokenVersion`、`typ: "app"`、`deviceId`（Track 一期可不读 `tokenVersion` / `deviceId`，但须能解析出 `uid`）。

## 8. 配置项（环境变量）

| 变量                        | 必填 | 说明                                                     |
| --------------------------- | ---- | -------------------------------------------------------- |
| `HTTP_ADDR`                 | 是   | 如 `127.0.0.1:8081`                                      |
| `DB_PATH`                   | 是   | SQLite 文件路径                                          |
| `JWT_SECRET`                | 是   | 与 Node App JWT 相同                                     |
| `INTERNAL_TOKEN`            | 是   | Admin / 运维 / 被 Node 调用时的内部令牌                  |
| `NODE_INTERNAL_BASE_URL`    | 是   | Node 内部 API 根，如 `http://127.0.0.1:3000`             |
| `NODE_INTERNAL_TOKEN`       | 是   | 调用 Node 回写时携带的 Token（可与上者同值策略由部署定） |
| `PRESENCE_OFFLINE_AFTER_MS` | 否   | 默认 `600000`（10 分钟）                                 |
| `TZ` / 业务日               | 否   | 聚合按 `Asia/Shanghai` 实现，不依赖宿主机偶然时区        |

具体键名实现时可微调，但语义不得删减；变更须同步 `接口文档.md` 与部署清单。

## 9. 依赖清单（实现期引入）

### 运行时（计划）

| 模块                         | 用途           |
| ---------------------------- | -------------- |
| `net/http`                   | HTTP 服务      |
| `github.com/go-chi/chi/v5`   | 路由           |
| `modernc.org/sqlite`         | SQLite 驱动    |
| JWT 库（选定后写死一种）     | App JWT 校验   |
| 标准库 `log/slog`、`context` | 日志与取消传播 |

### 明确不引入（一期）

| 项                  | 原因                |
| ------------------- | ------------------- |
| CGO SQLite          | 部署与交叉编译成本  |
| Echo / Gin 等重框架 | 已锁定 chi          |
| Redis / Kafka       | 资源与复杂度        |
| ORM（GORM 等）      | 表少，手写 SQL 足够 |

具体版本在 `go.mod` 锁定；本文只定方向。
