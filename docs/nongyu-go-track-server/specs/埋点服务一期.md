## 1. 背景

农屿需要自研埋点（页面、按钮、性能、启动、心跳、JS 崩溃），支撑管理端趋势与分布，并驱动业务库 `users.is_online` / `last_active_at`。

业务 MySQL 专注账号与业务；埋点写入量大、查询偏分析，故独立为 Go + SQLite 服务 `nongyu-go-track-server`。App 直连上报；管理端经 Node BFF 查询（BFF 本身不在本期落地，见 §3）。

---

## 2. 目标

1. App 可批量上报事件；重复 `event_id` 幂等；失败可由客户端重试（服务端不丢已接受事件）。
2. 原始事件保留 30 天；日聚合保留约 400 天；支撑 overview / trend / dims / crashes 查询。
3. 心跳、显式离线、超时扫描必须回写 Node，使业务 `users.is_online` 最终正确。
4. 在 2C2G40G 单实例上可运行：单 writer、WAL、队列满返回 503。
5. 本机可交叉编译 linux/amd64 二进制，按 `部署与发布.md` 上传重启后 `/health` 可用。

---

| 不做                           | 说明                                                          |

| RN Telemetry SDK / MMKV 重试   | App 客户端另开基建；本期用 curl / 单测验收 Track              |
| Node Admin BFF 代理 Track      | 管理端大屏拼装后置；本期 Admin API 用 Internal Token 直打验收 |
| 管理端大屏 UI 接 Track         | 后置                                                          |
| 原生崩溃采集                   | 二期                                                          |
| ClickHouse / 业务 MySQL 埋点表 | 一期禁止                                                      |
| 多实例写扩展 / Redis / MQ      | 一期单进程                                                    |
| 实时漏斗 / 会话重放            | 一期不做                                                      |
| 公网暴露 Admin API             | 禁止；进程默认听 `127.0.0.1`                                  |

**本期必须顺带做（Track 依赖）**：Node `POST /api/internal/users/presence`（内部 Token），否则在线态回写无法闭环。

## 4. 详细需求

### 4.1 服务能力

实现 `接口文档.md` 中全部路径：

| 路径                              | 角色     |
| --------------------------------- | -------- |
| `GET /health`                     | 探活     |
| `POST /v1/track/events`           | App 上报 |
| `POST /v1/track/presence/offline` | App 离线 |
| `GET /v1/admin/overview`          | Admin    |
| `GET /v1/admin/metrics/trend`     | Admin    |
| `GET /v1/admin/metrics/dims`      | Admin    |
| `GET /v1/admin/crashes`           | Admin    |
| `POST /v1/admin/jobs/aggregate`   | 运维     |
| `POST /v1/admin/jobs/purge`       | 运维     |

鉴权、错误码、部分成功语义、心跳采样、`stat_date`（Asia/Shanghai）均按接口文档，不得另起一套。

### 4.2 存储与任务

- Schema = 技术方案 §8.7 DDL；启动时迁移到该结构。
- 单 writer：`BEGIN IMMEDIATE` → 批量 INSERT → `COMMIT`。
- 日聚合：每天 00:10（上海）聚合昨日，幂等 upsert；启动时检查空洞可补。
- 原始清理：每天 03:00 删除 30 天前 `events`；随后 `PRAGMA optimize`（默认不 VACUUM）。
- 在线超时：每 1 分钟扫描，默认 10 分钟无心跳 → 本地离线 + 回调 Node。
- DAU：当日存在至少 1 条 `app_open` 且 `user_id IS NOT NULL` 的去重用户数。

### 4.3 Node 内部回写

Track 在心跳上线、显式离线、超时离线时调用：

`POST {NODE_INTERNAL_BASE_URL}/api/internal/users/presence`

请求体与鉴权见 `接口文档.md` §6.1。失败入重试队列，保证业务表最终正确。同一用户 30s 内重复回写可合并。

### 4.4 配置

必填环境变量语义见 `技术选型.md` §8；缺关键配置进程拒绝启动。密钥不进仓库。

## 5. 业务流程

### 5.1 上报

```text
App JWT → 限流 / Body 限制 → 整包校验
  → 入写队列（满则 503）
  → 单条校验（失败计入 rejected，其余继续）
  → UNIQUE(event_id) 冲突计 duplicated
  → 写 events；heartbeat 可 5 分钟/用户采样落事件
  → upsert user_presence；触发 Node 回写（可 30s 合并）
```

`user_id` 一律取自 JWT `uid`，忽略客户端伪造。

### 5.2 离线与超时

```text
显式离线 ──┐
超时扫描 ──┼─→ Track presence=0 ──→ Node presence is_online=0
心跳/上报 ─┘                         （失败重试）
```

### 5.3 查询

- 历史日：读 `daily_metrics` / `daily_dims`。
- 「今天」且日聚合未完成：允许对 `events` 实时近似（须限流）。
- `online` 不由 Track 对公网权威提供；overview 可省略该字段。

## 6. 验收标准与测试方案

以后端单测 + 本地 HTTP 冒烟为主（无 UI）。

| #   | 验收项                                                                  | 方式                 |
| --- | ----------------------------------------------------------------------- | -------------------- |
| 1   | 合法批量上报返回 `accepted/duplicated/rejected`；重复 `event_id` 不报错 | `go test` + curl     |
| 2   | 无 JWT / 坏 JWT → 401；坏 Internal Token → 403                          | 单测中间件           |
| 3   | 超 100 条/批 → 400；超 Body → 413                                       | 单测                 |
| 4   | 写队列满 → 503                                                          | 单测（缩小队列容量） |
| 5   | overview / trend / dims / crashes 在 Internal Token 下可读              | 单测 + curl          |
| 6   | aggregate / purge 幂等且 purge 不删未到期数据                           | 单测                 |
| 7   | 心跳 / 离线 / 超时触发 Node 回写                                        | 单测 mock HTTP       |
| 8   | `GET /health`：SQLite ping 失败返回 503                                 | 单测                 |
| 9   | 交叉编译 `linux/amd64` `CGO_ENABLED=0` 成功                             | 本机 `go build`      |

客户端断网 MMKV 重试、管理端大屏拼装：**不在本期验收**。
