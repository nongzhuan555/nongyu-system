## 2. 实施步骤

### 2.1 工程骨架

目录按 `技术选型.md` §2.1：

```text
apps/nongyu-go-track-server/
  cmd/track-server/main.go
  internal/{config,httpapi,ingest,store/sqlite,aggregate,presence,auth/jwt,usersync}
  migrations/001_init.sql          # 与技术方案 §8.7 一致
  go.mod
```

- Go 版本：写入 `go.mod`，要求 **≥ 1.22**（本机已安装版本对齐）。
- 依赖：`chi/v5`、`modernc.org/sqlite`、`golang-jwt/jwt/v5`；无 CGO、无 ORM。
- 配置：启动时校验必填 env；缺则 fatal。
- 日志：`log/slog` JSON；中间件生成 `request_id`。
- 优雅退出：停收请求 → 排空写队列 → 关 DB。

### 2.2 存储

- 写连接 1 条；查询可用 `mode=ro`。
- PRAGMA 按选型 §3.1。
- 迁移：embed `001_init.sql`，启动执行；后续增量编号。
- 测试用临时文件 SQLite（WAL 行为不用纯 `:memory:` 若测 WAL）。

### 2.3 上报与鉴权

实现锁定（接口文档曾留「实现选定」的项）：

| 项             | 锁定值                                                                   |
| -------------- | ------------------------------------------------------------------------ |
| JWT            | HS256；验 `alg`/`exp`/`typ=="app"`/`uid` 为数字；**不验** `tokenVersion` |
| Internal Token | 常量时间比较 `X-Internal-Token`                                          |
| 单用户限流     | 120 req/min                                                              |
| 单 IP 限流     | **300 req/min**                                                          |
| Body           | 1MB；超限 413                                                            |
| 写队列         | 容量 **128** 个批次；满 503 `QUEUE_FULL`                                 |
| props 截断     | 序列化 >4KB 截断，并在 JSON 内标记 `"_truncated": true`（不加新列）      |
| `/health`      | SQLite ping 失败 → **503** + `ok:false`；成功 200                        |
| trend 缺日     | **省略无数据日**                                                         |

`user_id` 只来自 JWT。`heartbeat`：每次更新 presence；`events` 每用户每 5 分钟最多 1 条。`app_open`/已鉴权事件同样 upsert 在线并触发 Node 回写（30s 合并）。

回写 Node 必须用 **独立于请求 ctx 的 context**（`context.WithoutCancel` + 超时），避免客户端断开导致在线态丢失。

### 2.4 Node 内部接口（同期最小）

1. env 增加必填 `INTERNAL_TOKEN`（与 Track 的 `NODE_INTERNAL_TOKEN` 部署时对齐）。
2. `POST /api/internal/users/presence`：校验 Token → 更新 `is_online`、`last_active_at`。
3. 用户不存在：返回 404 业务错误（Track 记日志，不阻塞上报成功）。
4. 同步 `接口文档概览.md`：内部接口纳入；§1.3 删除「心跳 / 在线态刷新接口本期不做」。
5. 单测覆盖鉴权失败与字段更新。

不在本期做 Admin BFF 代理。

### 2.5 Admin 与任务

- overview：优先 `daily_metrics`；`date=今天` 且无聚合则实时近似。
- 聚合指标键按技术方案 §8.4 / §8.5（含 `online_peak` 定时采样）。
- 定时：进程内 ticker，时区 `Asia/Shanghai`（不依赖宿主机 TZ）。
- `meta_jobs` 记录成功/失败；手动 aggregate 幂等重跑指定日。

### 2.6 测试与本地跑

```text

DB_PATH=<本机临时路径>/track.db
JWT_SECRET=<与 Node 相同>
```

单测优先：ingest 校验/幂等、JWT 中间件、聚合幂等、presence 超时、usersync mock。

本机：`go test ./...`、`gofmt`；Go 不走根目录 `pnpm lint`。Node 改动仍走该包既有测试。

### 2.7 部署

- 启用 `scripts/deploy-nongyu-track.ps1` 的 `go build`（`./cmd/track-server`）。
- 仓库内补一份可提交的 systemd unit **示例**（无密钥）。
- **实际上传到 Track 机**：计划确认并完成本地单测后，再单独问你是否发布（口令/密钥只读本机敏感文件）。

## 3. 注意事项

- SQL 全部参数化；props / 学号写入日志时脱敏。
- 禁止把 Track Admin 绑到 `0.0.0.0` 公网。
- 2G 机：RSS 目标 < 200MB；不在高峰 VACUUM。
- 代码：Go 命名与错误处理按 `golang-*` Skills；必要中文注释写 Why/约束。
- 基建允许在 `main` 直接改（协作规范）。
- 若实现中发现契约缺口：先改 `接口文档.md` / 技术方案，再改代码。
