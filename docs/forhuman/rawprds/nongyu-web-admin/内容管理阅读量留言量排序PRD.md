# 内容管理阅读量 / 留言量排序 PRD

> 来源：2026-09-06 需求对齐。业务需求。  
> 状态：已实现。

## 背景

内容管理列表已展示阅读量与回复/留言信息，但仅能按发布时间倒序浏览。管理员需要快速找出高阅读、高互动内容。

## 目标

在内容管理三个 Tab（公告 / 反馈 / 建议）中，支持按**阅读量**、**留言（回复）量**对列表做服务端升/降序；默认仍按发布时间降序。

## 非目标

- 不按覆盖率、独立读者数等其它字段排序
- 不改阅读量/留言量统计口径
- 不改 App 端广场列表排序
- 不做导出、不做智慧助手专用排序工具

## Grill 共识

| 项       | 结论                                                                                      |
| -------- | ----------------------------------------------------------------------------------------- |
| 分类     | 业务需求                                                                                  |
| 范围     | 公告 / 反馈 / 建议三个 Tab 均支持                                                         |
| 字段     | `viewCount`（阅读量）；`replyCount`（反馈≈是否有管理员回复；大院=留言条数；列表既有字段） |
| 交互     | 表格列头 sorter；同时仅一个排序字段；默认 `publishedAt` 降序                              |
| 分页正确 | 必须服务端排序（禁止只排当前页）                                                          |
