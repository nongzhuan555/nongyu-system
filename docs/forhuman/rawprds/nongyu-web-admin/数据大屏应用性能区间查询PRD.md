# 数据大屏：应用性能区间查询 PRD

### 需求背景

管理端数据大屏「应用性能」当前只展示业务日当天的 `perf` 分位（p50 / p95），无法查看近几天汇总后的课表首屏等指标，不利于判断性能是偶发还是持续问题。

### 需求类型

业务需求（管理端大屏增强；Track dims 需支持区间内原始样本重算分位）。

### 已确认口径（方案 C）

- **范围**：仅「应用性能」卡（`chart-perf`）；页面次数 / 停留 / 按钮 / Web Vitals / KPI / 崩溃表不变。
- **交互**：卡片内区间选择，非大屏全局时间筛选。
- **选项**：`今天` / `近 7 天` / `近 30 天`（受原始事件约 30 天保留约束，不做近 90 天）。
- **聚合**：区间内全部原始 `perf` 样本按 `event_name` 统一重算 p50 / p95；禁止对多天日聚合分位再平均 / 再合并。
- **默认**：打开大屏默认 `今天`；所选区间写入 dashboard prefs（localStorage），刷新后仍记住。
- **近 N 天**：含今天，共 N 个业务日（例：近 7 天 = 今天往前共 7 天）。
- **接口**：现有 Track/BFF `dims` 增加可选区间参数；仅 `perf_p50` / `perf_p95` 允许跨日；单日兼容不变。
- **加载**：切换区间只重拉应用性能两路 dims，该卡单独 loading。
- **触达**：本次只改 Node Track + Node BFF + Web Admin；Go 埋点服务不同步。
- **prefs**：`DashboardPrefsV1` 增补可选 `perfRange`（`1d` | `7d` | `30d`），缺省/非法回退 `1d`；旧 prefs 不整份回退。
- **控件**：卡头小 Select（今天 / 近 7 天 / 近 30 天），与增长趋势卡一致，放在排序控件旁。

### 目标

1. 管理员可在「应用性能」卡切换上述区间，图表展示该区间内各性能事件的 p50 / p95（毫秒）。
2. 「今天」行为与现网一致（业务日当日、排除 web 平台的 App 性能口径不变）。
3. 无样本时卡片空态清晰（如「暂无性能样本」）。

### 非目标

- 不做按日趋势折线（方案 B）。
- 不改 Web Vitals、行为维度图、崩溃表的时间范围。
- 不延长原始事件保留天数。
- 不在前端写死事件名白名单（仍有什么展示什么，最多 20 条）。
