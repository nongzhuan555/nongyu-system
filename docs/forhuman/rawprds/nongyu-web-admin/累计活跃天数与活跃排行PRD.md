# 累计活跃天数与活跃排行 PRD

> 来源：2026-09-06 需求对齐（Grill 两轮确认）。业务需求。  
> 状态：已实现。

## 背景

管理端需要看用户「累计活跃了多少天」，并在数据大屏做活跃排行；当前仅有 `last_active_at`（最近一次）与「今日活跃」筛选，无法累计、无法排行。

## 目标

1. **从功能上线起**按业务日累计活跃天数（不做历史回填）。
2. 用户管理列表展示该字段，并支持按该字段服务端排序。
3. 用户详情展示该字段。
4. 数据大屏新增「用户活跃排行」柱状图：默认 Top50、可切换更多档位与升降序。

## 口径（Grill 共识）

| 项           | 结论                                                                 |
| ------------ | -------------------------------------------------------------------- |
| +1 触发      | 与 `last_active_at` / presence 回写一致；`BUSINESS_TZ` 业务日最多 +1 |
| 历史         | 不上线前回填；存量用户从 0 起算                                      |
| 列表排序     | 表格列可点升/降序，服务端排序+分页；默认仍 `id DESC`                 |
| 大屏排序默认 | **降序**（高→低）；可切升序                                          |
| Top 档       | 50 / 100 / 200，默认 50                                              |
| 轴标签       | `姓名（学号）`                                                       |
| 排行范围     | 仅 `status=正常`；含管理员；**排除** `active_days=0`                 |
| 并列次序     | 天数相同再按 `id` 升序                                               |
| 详情         | 抽屉展示累计活跃天数                                                 |
| 卡片位置     | 默认布局靠近用户增长趋势；可拖拽                                     |

## 非目标

- 与 Track DAU / `app_open` 去重日活完全一致
- 历史事件回填
- 按活跃天数区间筛选（仅排序，非 range filter）
- 云端同步大屏 Top/排序偏好（与现有图一致：会话内或可跟布局 prefs，实现阶段定）
