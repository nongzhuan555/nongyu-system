# 埋点采样率远程配置 PRD

### 需求背景

RN 客户端埋点 SDK 当前为全量采集上报。用户量上来后需要能在后台下调采样率以控制上报量与存储/查询压力，且配置要能热更新到客户端（下次进入 App 生效），避免发版。

同时现有 `users.role` 仅 `0/1`，超级管理员靠环境变量学号判断，不利于权限扩展。本需求一并扩展角色枚举，使超管能力（采样率配置、提权管理员等）以 `role=2` 为准。

### 需求类型

基建

### 涉及端

- `nongyu-web-admin`：超级管理员配置入口；角色展示与提权 UI
- `nongyu-node-server`：角色枚举扩展、权限中间件、配置读写 API + MySQL 持久化
- `nongyu-rn-app`：启动时拉取采样率并按规则决定是否入队；session role 类型扩展

### 目标

1. 扩展 `users.role`：`0` 普通用户 / `1` 管理员 / `2` 超级管理员。
2. 超级管理员可在 Web 管理端「数据大屏」页顶部低调配置埋点采样率（0–100 整数百分比）。
3. 配置落在 Node 业务库，不放 Go Track。
4. App 用户进入（Telemetry 初始化 / 冷启动拉配置）时向 Node 请求当前采样率；成功则按 session 采样；**任意失败则本进程降级为 100% 采样**。
5. `crash`、`heartbeat` 始终 100% 上报，不受采样率影响。

### 详细需求

##### 角色枚举扩展（先决）

| 值  | 含义       |
| --- | ---------- |
| `0` | 普通用户   |
| `1` | 管理员     |
| `2` | 超级管理员 |

规则：

1. **超管身份以 `role=2` 为唯一业务真相**；`SUPER_ADMIN_STUDENT_NO` 仅保留出厂引导 / bootstrap / 默认密码用途，**不再单独作为业务权限判断**。
2. 上线迁移：若存在 `student_no = SUPER_ADMIN_STUDENT_NO` 的用户行，将其 `role` 更新为 `2`；该学号后续登录保持/强制为 `2`（不再写成 `1`）。
3. `role=2` 拥有全部 `role=1` 的管理能力，并额外拥有超管专属能力（见下）。
4. 鉴权中「是否管理员」（可进管理端 / Admin JWT）改为 `role IN (1, 2)`（或等价 `role >= 1`）。
5. Admin JWT 的 `role` 字段改为真实库值 `1` 或 `2`；校验允许 `1|2`。
6. **不能**通过管理端把任意用户直接设为 `2`；`2` 仅能由超管学号登录/迁移产生。
7. **提权限制（产品确认）**：
   - 仅 `role=2` 可将用户在 `0 ↔ 1` 间切换（设为管理员 / 取消管理员）。
   - `role=1` 普通管理员：**可以**管理用户（查询、禁用/启用等既有用户管理能力，以现网为准），**不可以**修改他人 `role`（含设管理员、取消管理员）；接口与 UI 均需拦截。
8. DB：`CHECK (role IN (0, 1, 2))`；文档与类型 `0 | 1 | 2` 同步。

##### 管理端 · 采样率

- 位置：数据大屏页面上方，一行低调控件（文案「埋点采样率」+ 数字输入 0–100 +「保存」）。
- 权限：**仅 `role=2`** 可查看并修改；`role=1` 不展示该控件。
- 保存成功/失败有轻量提示；不打断下方大屏刷新与图表。
- 默认值：从未配置时视为 **100**。

##### 管理端 · 用户角色操作

- 用户详情中「设为管理员 / 取消管理员」仅对 `role=2` 可见可点。
- `role=1` 进入用户管理仍可做非角色类操作；尝试改 role 的 API 返回 403。

##### Node / 数据库 · 采样率

- 新建单行全局配置表（建议名 `app_runtime_config`），至少含：
  - `track_sample_rate`：TINYINT/INT，范围 0–100，默认 100
  - `updated_at`（可选 `updated_by`）
- Admin：
  - 读/写采样率接口（写接口仅 `role=2`；读可仅超管，与 UI 一致）
  - 建议路径：`GET/PUT /api/admin/dashboard/track-sample-rate`
- App：
  - 只读：`GET /api/app/track/sample-rate`（需 App JWT）
  - 响应含当前 `sampleRate`（0–100 整数）

##### RN 客户端 SDK

- 时机：用户进入 App、Telemetry 初始化时请求一次采样率（本进程内不因回前台重复拉）。
- 鉴权：需已登录（有 App JWT）；与现有「无 JWT 不上报」一致。
- 失败降级：网络错误、超时、非 2xx、解析失败、无 JWT 等 → **本进程按 100% 采样**，不使用本地历史缓存值。
- 采样粒度：按 **session**（本 JS 运行时一次判定）。
  - 拉取成功后：以 `random() * 100 < sampleRate`（或等价）决定本 session 是否采集行为类事件。
  - `sampleRate === 100` → 全采；`0` → 行为类全不采。
- 采样作用范围（对齐现有 `TRACK_EVENT_TYPES`）：
  - **受采样约束**：`app_open`、`screen_view`、`button_click`、`perf`
  - **始终上报**：`crash`、`heartbeat`
- 请求进行中的事件策略（产品确认）：
  - 采样率请求尚未返回时：**全部事件照常入队**（等价临时全量）。
  - 拿到采样率后：**不对已入队事件做回滚/剔除**；仅对**后续**事件按采样判定决定是否入队。
- 事件上报通道不变：仍直连 Go Track；Node 只负责下发采样率配置。

### 非目标

- 不做按用户/设备稳定哈希采样（本版按 session 随机）。
- 不做回前台强制重拉采样率。
- 不做失败时回退到上次成功缓存。
- 不改 Go Track 入库/聚合逻辑；不在 Track 侧再做一层采样。
- 不在管理端做采样率历史审计页（表可留 `updated_at`，无独立审计 UI）。
- 不调整大屏图表因采样导致的统计口径说明（可后续另开需求）。
- 不支持管理端创建/任命多个 `role=2`（超管唯一来源仍为 env 学号 + 迁移）。
- 不在本需求内重构全部历史文档里的 `role === 1` 表述（以实现与 Spec 为准，文档随改随更）。

### 验收要点

1. DB/类型支持 `role IN (0,1,2)`；超管学号用户迁移后为 `2`；Admin JWT `role` 为真实值。
2. `role=2` 可设/取消他人管理员；`role=1` 不可改他人 `role`（UI 隐藏 + API 403）。
3. 超级管理员在数据大屏顶部可改采样率为例如 10 并保存；刷新后仍为 10。
4. 普通管理员登录管理端看不到采样率控件；直接调写接口被拒绝。
5. App 冷启动能拉到配置；将采样率设为 0 后，新 session 不再上报行为类事件，但仍上报 `crash`/`heartbeat`。
6. 故意让采样率接口失败（断网/关 Node）时，App 行为类事件仍全量入队上报。
7. 采样率请求未返回前产生的行为事件会入队；返回后若判定本 session 不采样，这些已入队事件仍可被 flush，后续行为事件不再入队。
