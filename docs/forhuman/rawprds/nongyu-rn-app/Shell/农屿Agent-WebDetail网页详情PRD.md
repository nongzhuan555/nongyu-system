# PRD：农屿 Agent WebDetail（网页详情抓取）

> 来源：2026-08-17 需求对齐（聊天 Grill）；需求类型：**基建**  
> 涉及：`nongyu-agent-sdk`（增强内置抓取工具）+ `nongyu-rn-app`（Agent 注册与 systemPrompt）

## 背景

用户在对话中常需要「打开/查看某个 URL 的详细内容」。SDK 已有 `web_fetch`，可按 URL 拉取 HTML 并处理编码，但：

1. RN 农屿 Agent **未注册**该工具（仅自有 Key 时挂了 `web_search`）。
2. 返回整页 raw HTML，易撑爆上下文，对模型也不友好。
3. 鉴权页 / 登录墙 / 空壳页没有统一「无权限」提示，模型容易瞎编。

## 目标

1. Agent 在用户要求查看某网页详情时，可传入 URL 抓取并解码页面内容。
2. 向模型返回**可读正文**（去标签后的纯文本）及元信息（url、encoding、title），而非整页 HTML。
3. 若内容无意义（疑似鉴权/登录墙/空壳），返回结构化失败结果，由 Agent 提示用户「无此权限查看该页面内容」。
4. 与 `web_search` 一致：仅自有 API Key 通道注入该工具。

## 范围外

- 携带用户 Cookie / 登录态抓取校内需鉴权系统
- SSR/CSR 完整渲染（无头浏览器）
- Generative UI 专用卡片（本期纯工具结果 + 口述）
- 平台代理通道注入外网抓取
- 任意写操作（POST 表单等）

## 关键约定（Grill 共识）

| 项           | 约定                                                                                                      |
| ------------ | --------------------------------------------------------------------------------------------------------- |
| 归类         | 基建                                                                                                      |
| 与现有关系   | **增强现有 `web_fetch` 实现**（可读正文 + 鉴权判定），对外工具名见 Spec 锁死；App 注册并更新 systemPrompt |
| 返回形态     | `{ ok, url, encoding, title?, text?, reason?, message? }` 一类结构化结果；成功为可读正文，失败为无权限等  |
| 无权限判定   | HTTP 401/403；跳转/正文含登录墙关键词；可读正文过短/无意义 → `ok: false` + 统一文案                       |
| 可用性       | 仅 `config.source === "user"`（自有 Key）时注入，与 `web_search` 同级                                     |
| 技术方案文档 | 倾向跳过（简单增强 + 注册）                                                                               |

## 验收（草稿）

1. 自有 Key：用户说「帮我看看这个链接的内容」+ 公开页 URL → 调用工具并基于正文作答。
2. 平台代理：不出现该工具。
3. 401/403 或登录墙页 → Agent 明确告知无权限，不编造正文。
4. GBK 等非 UTF-8 公共页解码正常、可读。
5. 超长正文截断，不拖垮上下文。
