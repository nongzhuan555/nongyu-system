# 农屿 Agent 会话管理 PRD

> 来源：2026-08-15 需求对齐会话。基建需求。  
> 状态：已对齐，待据此编写 Spec。

## 背景

当前农屿 AI 页对话仅存在内存中，离开页面或杀进程即丢失；无法在多段对话间切换续聊。需要在本机提供轻量会话管理，对齐 ChatGPT / Cursor 等常见 Agent 产品心智。

## 目标

- 用户与农屿 Agent 的对话可按「会话」本地保存，并可续聊
- Agent 页顶部提供侧边栏入口，用于查看、切换、删除、清空会话
- 数据仅存本机，不上传远程；登出 / 本地鉴权失效时全部清除
- 交互与信息架构贴近业内常见做法（抽屉列表 + 新对话 + 时间分组）

## 非目标

- 不做云端同步、多设备互通
- 不做 AI 自动起标题、会话重命名、会话搜索、会话置顶（可后续）
- 不改模型上下文压缩 / 远端历史回灌策略（仅本地 UI 层消息持久化）
- 不在本期为大改 `nongyu-agent-sdk` 的 AgentLoop / 模型适配（续聊以 remount/`initialMessages` 为主）

## 需求类型

基建（Agent 页壳层 + 本地持久化能力）

## 核心概念

| 概念     | 说明                                                                  |
| -------- | --------------------------------------------------------------------- |
| 会话     | 一组有序 `ChatMessage`（含 toolCalls 等可序列化字段）+ 元数据         |
| 当前会话 | 用户正在查看/续聊的会话；新对话后进入「未落盘草稿」直至首条用户消息   |
| 落盘时机 | 用户发出第一条有效消息时创建会话；之后每轮对话结束（或 stop）增量保存 |
| 标题     | 默认取首条用户消息截断（约 20 字），本期不可编辑                      |
| 配额     | 每学号最多 **10** 条已落盘会话；超出按 **LRU** 淘汰                   |

## 功能需求

### 1. 本地持久化

- 存储介质：本机 MMKV（与现有业务偏好一致）
- 按学号 `studentId` 分桶；同机不同账号互不可见
- 不上传服务端
- 主动登出、Token 失效本地清会话时，必须同步清空该用户（及约定范围内）全部 Agent 会话数据
- 上限 10；LRU：`lastUsedAt` 在「打开会话」或「在该会话成功发出用户消息」时更新（创建时写入）

### 2. Agent 页顶栏

- 左侧：打开会话侧边栏（左侧抽屉）
- 中间：固定文案「农屿 AI」
- 右侧：「新对话」
- 未配置模型时：顶栏可展示；侧边栏可浏览/删除已有会话；发消息仍受模型配置限制（与现页一致）

### 3. 会话侧边栏（左侧抽屉）

- 顶部：「新对话」
- 列表：按时间分组（今天 / 昨天 / 更早），展示标题 + 时间
- 点击某会话：关闭抽屉并进入该会话续聊（完整恢复消息，含工具卡片所需的 toolCalls 数据）
- 删除：单条（左滑或长按）；「清空全部」需二次确认
- 空态：引导开始新对话

### 4. 新对话

- 顶栏或侧边栏触发后：进入空白草稿（展示欢迎语）
- 草稿不落盘、不占 10 条配额
- 发出首条用户消息后正式创建并计入配额；若已满 10 条，先按 LRU 淘汰 1 条再写入

### 5. 续聊与页面恢复

- 恢复完整 `messages`（含 `toolCalls` 等），用户可继续追问
- 离开 `/ai` 再进入：恢复**上次活跃会话**；若已被删除/LRU 淘汰则开新草稿
- 流式生成中切换会话或点「新对话」：先 `stop()`，将已生成部分落盘，再切换

## 验收

1. 对话后杀进程再进 AI 页，侧边栏可见会话并可续聊，工具卡片仍可渲染
2. 最多保留 10 条；第 11 条创建时按 LRU 丢掉 `lastUsedAt` 最旧的会话
3. 删除单条 / 清空全部后，列表与本地数据一致
4. 主动登出或 Token 失效后，本地无该用户 Agent 会话残留
5. 顶栏可打开左侧抽屉；新对话可从顶栏与抽屉发起
6. 仅有欢迎语的草稿杀进程后不出现在列表中
7. 重回 AI 页默认打开上次活跃会话（仍存在时）
