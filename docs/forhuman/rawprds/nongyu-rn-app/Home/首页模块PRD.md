# 首页模块骨架 PRD（草稿）

> 来源：2026-08-12 对齐。业务需求。参照 `old-code/nongyu/src/modules/Home`。

## 背景

在新 RN App（`apps/nongyu-rn-app`）落地首页模块骨架，信息架构与交互对齐旧版首页，但不接 AI 问候、不接真实教务/二课业务；通知接口未就绪时写死数据，仍按「会请求」处理并展示骨架屏。

## 目标

- 首页主界面具备：时段问候（打字机）、通知栏、常用网站、教务/二课入口、公众号与 QQ 复制
- 组件尽量细拆，便于后续接真实数据
- 凡「将来会网络请求」的区块，加载期有骨架屏；本次通知栏用固定数据 + 模拟加载演示骨架
- 入口子页（除网站外）仅占位；网站完整迁移并外开浏览器

## 非目标

- 不接入 AI 问候 / 天气拼进问候
- 问候暂不含用户姓名
- 不实现教务/二课真实能力与登录探针
- 不实现网站打开方式配置（固定外开）
- 不接真实通知 API（写死固定文案，保留请求形态与骨架）
- 不做 WeatherProbe 调试面板
- 跳过独立技术方案文档

## 首页结构（自上而下）

1. 背景渐变
2. 问候语（按时段本地文案 + 打字机；预留固定高度）
3. 通知栏（骨架 → 固定通知；点击进占位页）
4. 常用网站（搜索 + 栅格列表；点击系统浏览器打开）
5. 教务系统 / 二课系统入口（点击进占位页）
6. 微信公众号 / QQ 群复制行

## 验收要点（草稿）

1. 不同时段问候文案不同；打字机播放；区域高度不因文案长短剧烈跳动
2. 通知栏先骨架后出现固定文案；可点进占位
3. 常用网站列表与搜索行为对齐旧版；外开成功
4. 教务/二课/通知详情为占位页
5. 复制公众号/QQ 有成功反馈
