# PRD：平台 LLM 代理失败埋点

| 项       | 内容                                                           |
| -------- | -------------------------------------------------------------- |
| 日期     | 2026-08-15                                                     |
| 需求类型 | 基建                                                           |
| 涉及     | `nongyu-node-server`（上报）、`nongyu-go-track-server`（存储） |
| 状态     | 草案（Grill 已锁定推荐方案）                                   |

## 背景

平台 Key 池已能通，但尚未有真实大量用户验证失败分布。需要在「用户经 Node 后端调模型失败」时留下可追溯埋点，便于后续看繁忙/日限/上游失败等占比。

## 目标

1. 每次平台 LLM 代理业务失败，异步写入 Go Track（SQLite），**不**写入 Node/MySQL。
2. 埋点失败不影响用户收到的 LLM 错误响应。
3. 明细足够排查（错误码、文案摘要、50210 时的 attempts 等），不含明文 API Key。

## 非目标

- 本期不做管理端大屏/列表页。
- 不埋成功调用；不埋用户自有 Key 直连失败。
- 不改 DAU / 既有日聚合口径。

## Grill 锁定

| 决策     | 结论                                                   |
| -------- | ------------------------------------------------------ |
| 上报方   | Node 异步上报                                          |
| 失败范围 | `50210` / `50311` / `50310` / `42910` / `42911`        |
| 写入鉴权 | Track 新增 Internal Token 写入接口                     |
| 事件模型 | `event_type=llm_proxy_fail`，`event_name=错误码字符串` |
| 管理端   | MVP 只落库                                             |

## 验收直觉

人为触发各类失败后，Track SQLite `events` 表能查到对应 `llm_proxy_fail` 行；LLM 错误响应时延不明显变差；MySQL 无新埋点表。
