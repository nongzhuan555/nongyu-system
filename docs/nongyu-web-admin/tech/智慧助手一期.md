## 1. 技术选型

| 领域          | 选型                                                                   | 理由                                                            |
| ------------- | ---------------------------------------------------------------------- | --------------------------------------------------------------- |
| Agent 引擎    | 工作区 `nongyu-agent-sdk`（`workspace:*`）                             | 与 RN 同一 Loop / Tool / 流式 / `tool.render`                   |
| 对话 Hook     | SDK `useAgentChat`                                                     | Spec 不做离页保活，不必移植 RN 模块级 `AgentChatRunner`         |
| 会话存储      | `localStorage`，key 带版本前缀                                         | 对齐管理端会话 `nongyu-admin:v1:*`                              |
| 模型设置      | 同前缀 localStorage；明文 JSON（Web 无 SecureStore）                   | Spec 允许；登出删除                                             |
| HTTP          | 现有 axios `adminApi` + Agent 工具内 `fetch` 带 Admin JWT              | 工具跑在浏览器，须带登录态                                      |
| LLM 平台代理  | 复用 `handleChatCompletions`，鉴权改为已建档 Admin                     | 与 App 同池、同错误码、同 SSE                                   |
| Track SQL     | Go 读连接 + `sqlguard` 校验；Node `POST /api/admin/track/query` 转发   | 读库已是 `mode=ro`；再加语句闸门                                |
| A2UI          | 工具名 → 组件注册表（抄 RN `agent-ui/registry.ts` 到 Web）             | SDK 只声明字符串；DOM 端自己注册                                |
| 图表          | 已有 `echarts` + `echarts-for-react` + `EchartsBlock`                  | 零新图表库                                                      |
| Markdown 辅文 | `react-markdown` + `remark-gfm`（catalog）                             | RN/GUI 同思路；消毒即可                                         |
| UI 壳         | 现有 Ant Design `Drawer` `AssistantPanel`                              | 不引入 `nongyu-agent-gui`（与管理端设计系统、会话/A2UI 不匹配） |
| SQL 解析      | 自研 `sqlguard`（去注释 + 单语句 + 关键字黑名单 + FROM/JOIN 表白名单） | 不引 Vitess 等重解析器；用单测钉死绕过用例                      |

**不引入**：服务端跑 Agent、WebSocket、Redis 会话、新 ORM、浏览器直连 Track。

**不改**：`nongyu-agent-sdk` 协议。教务/二课工具已从主入口拆到子路径 `nongyu-agent-sdk/jiaowu`、`nongyu-agent-sdk/second`（见「管理端首屏 Bundle 优化」），管理端只依赖主入口。

## 3. Node

### 3.1 Admin LLM 代理

新增 `src/modules/llm-pool/routes.admin-proxy.ts`（或与 app 路由同文件抽公共）：

```text
app.use("/api/admin/llm/v1", requireProvisionedAdminAuth, adminLlmChatRouter)
POST /chat/completions
```

**HOW 复用 proxy：**

`handleChatCompletions` 今日只读 `req.appAuth?.uid`。改为：

```ts
const userId = req.appAuth?.uid ?? req.adminAuth?.uid;
```

日限、并发租约、串行换 Key、SSE 透传、失败埋点 **全部共用**。管理员与学生若 `uid` 相同则共享 `llm_user_usage_daily`（同一用户行），可接受。

挂载注意：现有 `app.use("/api/admin/llm/keys", …)` 与新前缀 `/api/admin/llm/v1` 不冲突。

测试：把 `tests/llmPoolAdmin.test.ts` 中 App Token 调 completions 的用例扩一条 **Admin JWT** 成功流式/非流式；bootstrap 票 40302。

### 3.2 Track SQL BFF

`trackClient.ts` 增加 `trackAdminPost(path, json)`：超时建议 **10s**（比 GET 指标 5s 宽，给分析查询留余量）；header 仍 `X-Internal-Token`；错误映射沿用 `50301` / `50201`。

非法 SQL：Go 返回 400 + `{ ok:false, error:{ code:"INVALID_SQL", message } }` 时，Node 转为 `40001`，**不要**当成 502。

`routes.ts`：

```text
POST /query
requireProvisionedAdminAuth
body: { sql: string }  // Zod：非空、max 8000 字符
```

对外 `data` camelCase：

```ts
{
  sql: string;          // 实际执行（可能被改写 LIMIT）
  columns: string[];
  rows: Record<string, unknown>[];
  truncated: boolean;
  rowCount: number;
}
```

`chartType` **不进 Node/Go**：由 Agent 工具入参保留，前端按入参选图。

## 4. Go Track

### 4.1 路由

`internal/httpapi/router.go` 在已有 `/v1/admin`（Internal Token）下增加：

```text
POST /sql/query
```

Body：`{ "sql": "..." }`。

### 4.2 sqlguard（必须先于 Query）

文件建议：`internal/sqlguard/sqlguard.go`。

流水线：

1. 拒绝空串、过长（与 Node 8000 对齐）。
2. 去掉 `--` 行注释与 `/* */`。
3. trim；去掉末尾单个 `;`；若仍含 `;` → 拒绝（多语句）。
4. 首个关键字必须是 `SELECT` 或 `WITH`（大小写不敏感）。
5. 整词黑名单：`INSERT` `UPDATE` `DELETE` `REPLACE` `ALTER` `DROP` `CREATE` `ATTACH` `DETACH` `VACUUM` `REINDEX` `PRAGMA` `INTO`（防 `SELECT … INTO`）等。
6. 抽取 `FROM` / `JOIN` 后的表名（含 `` `name` ``）；去掉允许的别名；每个物理表必须 ∈ `{events, daily_metrics, daily_dims, user_presence}`。
7. 子查询里的表同样要过白名单（递归扫 FROM/JOIN）。

**执行层双保险：** 只用 `Store.read`（DSN 已 `mode=ro`），`QueryContext`，超时 **8s**。禁止 `Exec`。

**LIMIT：** 解析到用户 LIMIT 则 `min(n, 500)`；没有则包一层：

```sql
SELECT * FROM ( <validated> ) AS _ny_q LIMIT 501
```

取 501 行：若 =501 则 `truncated=true` 并只返回前 500。

列名用 `rows.Columns()`；值 `[]byte`/Null 转 JSON 友好类型（时间戳保持数字）。

单测（`sqlguard` + handler）：合法聚合、WITH、JOIN 白名单表；拒绝 DELETE、`events; DROP`、`ATTACH`、`meta_jobs`、注释夹写。

## 5. Web 管理端

### 5.1 依赖

`apps/nongyu-web-admin/package.json`：

- `nongyu-agent-sdk`: `workspace:*`
- `zod`（与 SDK tool 定义一致）
- `react-markdown` / `remark-gfm`（catalog）

Vite 需能解析 workspace 包；SDK 入口走 `dist`（与 RN 相同，先 `pnpm --filter nongyu-agent-sdk build`）。

### 5.2 目录

```text
src/assistant/

  types.ts                    # 可保留/收缩；运行时以 SDK ChatMessage 为准
  agent.ts                    # getOrCreateAdminAgent / invalidate
  resolveProvider.ts          # user | platform

  tools/
    users.ts

    ToolCallView.tsx
    SessionList.tsx

```

入口：`AdminShell` 仍只挂 `AssistantPanel`。设置做在面板内，不新开侧栏路由。

### 5.3 模型解析

```ts
// 自有：localStorage nongyu-admin:v1:agent-config { baseURL, apiKey, model }
// 平台：baseURL = `${VITE_API_BASE}/api/admin/llm/v1`，apiKey = Admin JWT
//       model = 与 RN 相同的平台占位名（请求会被 Node 忽略）
```

`OpenAIProvider` 与 RN 一样对平台把 JWT 当 Bearer。Token 刷新：管理端 JWT 无 RN 那种刷新链路，401 走现有 `unauthorizedHandler`；**不要**在 401 里删助手 localStorage。

配置变更 / 主动登出：`invalidateAdminAgent()` 并 `agent.stop()`。

### 5.4 工具 HOW

全部 `tool()` + Zod；`execute` 调现有 `adminApi` 或新增 `queryTrackSql`。JWT 从 `useAuthStore.getState().token` 读取（tool 闭包每次 execute 现取，避免过期闭包）。

`render.component` 可与 toolName 相同，注册表按 **toolName** 查找（与 RN `registerToolUI(toolName, …)` 一致，不强制用 component 字符串分发）。

| toolName                      | execute                   | 注册 UI                |
| ----------------------------- | ------------------------- | ---------------------- |
| `admin_users_list`            | GET users                 | UserListCard           |
| `admin_user_detail`           | GET users/:id             | UserDetailCard         |
| `admin_dashboard_overview`    | GET dashboard/overview    | KpiGroup               |
| `admin_user_growth`           | GET user-growth           | Chart line             |
| `admin_user_distribution`     | GET user-distribution     | Chart pie/bar          |
| `admin_settings_distribution` | GET settings-distribution | Chart pie              |
| `admin_track_overview`        | GET track/overview        | KpiGroup               |
| `admin_track_trend`           | GET track/trend           | Chart line             |
| `admin_track_dims`            | GET track/dims            | Chart bar/pie          |
| `admin_track_crashes`         | GET track/crashes         | DataTable              |
| `admin_track_sql`             | POST track/query          | SqlBlock + Chart/Table |

`admin_track_sql` 的 `execute` 返回 `{ sql, columns, rows, truncated, chartType }`。图表组件：`chartType` 与列形态不匹配时 **降级 table**。

systemPrompt：强制「专用 GET 优先于 SQL」；列出表白名单与常用 metric 枚举，减少胡写 SQL。

### 5.5 A2UI 与图表

`ToolCallView`：`getToolUI(tc.toolName)` → `ToolRenderProps`（status / args / output / error）。

`AdminChart`：把 rows 编成 `EChartsOption`，复用 `EchartsBlock`。色板跟大屏（主色 `#10B981`）。抽屉宽度有限：图表 `minHeight: 200`，`width: 100%`。

用户卡：只读字段，不放编辑按钮；可选 `onAction("查看用户 id=… 详情")` 回流（一期可不做，列表卡点选非必须）。

### 5.6 会话 HOW

移植 RN `session/repository.ts` 语义：

- key：`nongyu-admin:v1:assistant-sessions:{adminUserId}`
- LRU 10、标题 20 字、sanitize 无 user 不落盘
- `upsert` 在 `useAgentChat` 一轮 `done` / `stop` 后
- 面板用 `key={sessionId ?? "draft"}` remount，把 `initialMessages` 和 compact 字段喂给 hook

上下文压缩：调用 `agent.stream` / hook 时传入会话上的 `llmSummary`、`llmCompactedUntilId`；若 SDK hook 已支持则直接用；与 RN 同一套 SDK 默认窗口。Web 可不做 compact Toast（非验收项）。

### 5.7 交互 HOW

- `isLoading`：Input disabled；Stop 调 `stop()`。
- 重试/重新生成：对齐 RN（去掉末条 assistant 再 `regenerate`）。
- 建议问题（空态）：「今天日活多少」「近 7 日新增用户」「查一下学号 …」——点选即 send。
- 主动 `logout()`：`clearAssistantLocal(adminUserId)` 后 `message.info("对话记录与本地模型密钥已清除")`。`clearAuth`（401）**不**调此清理。

### 5.8 设置表单

面板齿轮：Base URL / API Key / model；预设列表可从 RN `agentProviderPresets` 拷一份到 web-admin（不要跨包依赖 RN）。保存写入 localStorage 并 `invalidateAdminAgent`。清除配置后走平台代理。

连通性探测：可选 `POST` 一条非流式「ping」；失败不覆盖旧配置。列为建议实现，不挡主验收。

## 8. 注意事项

- **安全**：SQL 闸门失败应 4xx；切勿「执行失败当 0 行」。Internal Token 永不下发浏览器。
- **包体**：SQL 500 行进 tool 结果会进下一轮模型上下文，易爆窗口。工具 `execute` 可对模型只返回 **列名 + 前 30 行摘要 + truncated**，完整 rows 放在 output 的 `ui` 字段并在 `chatMessagesToModelMessages` 前剥离——若 SDK 当前会把完整 output 送模型，则 **execute 返回瘦身副本**，完整数据放模块级 `Map<callId, rows>` 供卡片读取（推荐本期用此法，避免改 SDK）。
- **性能**：同一抽屉内 echarts `notMerge`；切会话销毁实例。
- **并发**：单 Agent 单例，生成中禁止第二条 send（锁输入已覆盖）。
- **SDK 体积**：构建失败再拆包，默认不改 SDK。

## 9. 风险

| 风险               | 缓解                                                   |
