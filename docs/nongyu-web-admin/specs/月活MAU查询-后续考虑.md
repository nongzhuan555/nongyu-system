# 月活（MAU）查询（后续考虑）

| 项       | 内容                                                                    |
| -------- | ----------------------------------------------------------------------- |
| 应用     | Track（现行 `nongyu-node-track-server`）+ Node BFF + `nongyu-web-admin` |
| 需求类型 | **业务**（数据大屏 / 问数指标）                                         |
| 状态     | **搁置 / 未排期**                                                       |
| 关联     | 日活 DAU、`daily_metrics`、`events` 保留策略；大屏 Spec                 |

---

## 1. 背景

2026-09-01 评估管理端是否可做「月活」查询后决定：**本期不做**，仅备案，避免需求丢失。

现状摘要：

- 已有 **日活 DAU**（当日 `app_open` 且 `user_id` 非空去重）及日趋势；**无 MAU 指标 / Admin API / 大屏卡片**。
- `daily_metrics` 按日存 `dau`，**不能**把当月每日 DAU 相加当作月活。
- 正确 MAU 需对自然月（或滚动窗）内 `app_open` 做 `COUNT(DISTINCT user_id)`；原始 `events` 默认约 **30 天** purge，历史完整自然月明细不可靠。
- 业务库 `users.last_login_at` / `last_active_at` 可近似「近期有活跃」，口径与 DAU/`app_open` **不一致**，不宜直接冒充产品月活。

## 2. 意向（将来若做）

建议优先对齐日活口径（`app_open` 去重），并明确窗口：

- **自然月 MAU**，和/或 **近 30 天滚动 MAU**。

可能落地路径（重启时再选型）：

1. Track 日聚合任务顺带写入月桶（如 `monthly_metrics` / `metric_key=mau`），或延长可支撑去重的中间态；
2. Node BFF 暴露 overview/trend 类接口；
3. 管理端大屏 KPI / 趋势 +（可选）助手专用工具。

近 30 天内临时用 SQL 对 `events` 去重仅作运维/问数兜底，**不算**正式产品能力。
