## 1. 背景

**Why**：管理端已有顶栏智慧助手抽屉，但只有占位文案。管理员需要用自然语言查用户、看增长/分布、问日活与埋点趋势，而不是自己拼筛选器和 SQL。  
**What**：在现有壳上接入与 RN 农屿 Agent **同一套** `nongyu-agent-sdk` 引擎与会话思路，做成 **只读问数助手**：用户管理走 Node GET；常用指标走已有 dashboard/track GET；非常规分析由模型生成 SQL，经 Node 代理到 Go Track 只读执行，结果用 A2UI（用户卡片 + echarts）嵌在对话里。

产品定位与 RN **农小屿**不同：本助手面向管理员，不提供教务/课表/二课/广场等校园工具。

---

## 2. 目标

1. 顶栏入口打开助手后可真实多轮对话（流式、Stop、重试/重新生成、生成中锁输入）。
2. 自有 OpenAI 兼容 Key 优先（localStorage）；否则用 Admin JWT 走 Node 平台 LLM 调度。
3. 多会话本地持久化（按管理员 id 分桶，最多 10 条 LRU）；主动退出登录时清理会话与自有 Key，并明确告知。
4. 工具结果不以纯 Markdown 作为主展示：用户列表/详情用原生卡片；指标与 SQL 结果用 KPI / 折线 / 柱状 / 饼图 / 明细表。
5. 一期全部只读；写操作（改角色、设密、发帖、Key 池变更、非 SELECT）一律不进入工具集，后端 SQL 接口亦拒绝写入。

---

## 3. 边界（非目标）

- 任何写操作：用户 PATCH、管理员密码、内容发帖/编辑/删除、LLM Key CRUD、SQL INSERT/UPDATE/DELETE/DDL。
- 教务、二课、课表、广场、常用网站、web_search、语音输入。
- 浏览器直连 Go Track 或直连上游模型（平台模式）。
- SQL 打业务 MySQL；SQL 可查表不含 `meta_jobs`。
- 云端会话同步、多设备互通、会话重命名/搜索/置顶。
- RN 式「离页保活」：关闭标签页或刷新可中断生成。
- Declarative JSON UI 树；模型不得生成任意 HTML/JSX。
- 散点、热力、双轴等图表；一期仅折线 / 柱状 / 饼图 / 表。
- 修改 `nongyu-agent-sdk` 协议（仅复用现有 `createAgent` / `stream` / `tool.render` / `ChatMessage.toolCalls`）。若发现必须改 SDK，另开切片，不塞进本期默认范围。

## 5. 详细需求

### 5.1 入口与布局

沿用 `内容管理与智慧助手预留`：

- 顶栏机器人按钮开关；默认关闭；开闭不必跨刷新持久化。
- PC（≥992px）右侧抽屉约 380–420px；窄屏全屏。
- 标题改为体现产品名（如「智慧助手」），副文案可说明「只读问数」。
- 面板内：会话列表入口、新对话、模型设置、消息列表、输入区。不新开独立聊天路由。

占位 `AssistantChatAdapter` 可保留类型文件，但面板必须改为真实 SDK 运行时，不再走「暂未接入」Toast。

### 5.2 Agent 组装

| 项              | 约定                                                     |
| --------------- | -------------------------------------------------------- |
| 名称            | 如 `nongyu-admin-assistant`                              |
| 人设            | 农屿管理端只读问数助手；禁止编造数字；能调工具必须调工具 |
| 引擎            | `createAgent` + `OpenAIProvider`                         |
| `maxSteps`      | 与 RN 同量级（建议 12）                                  |
| `needsApproval` | 一期全部只读，默认不弹审批                               |

**模型解析（对齐 RN `resolveAgentProviderConfig`）**

1. localStorage 中 baseURL + apiKey 完整 → `source=user`，直连兼容接口。
2. 否则若有 Admin JWT → `source=platform`，`baseURL` 为 Node `/api/admin/llm/v1`，`apiKey` 为 JWT，模型名与平台默认一致（当前 RN/Node 默认 `glm-4.7-flash`，以 Node 环境为准）。
3. 两者都无 → 空态引导去登录或配置 Key，禁止 mock 模型。

自有 Key **不**注入 `web_search`（与产品定位无关）。

### 5.3 模型设置 UI

助手面板内提供设置（抽屉/页内表单即可，不强制新侧栏菜单）：

- Base URL、API Key、模型名；服务商预设可复用 RN 列表思路。
- 显式保存；建议保存前做一次连通性探测（与 RN 一致则更好，非强制验收）。
- 清除本地配置后回落到平台代理（仍须已登录）。
- Key 仅存本机 localStorage，禁止提交到仓库或业务后端。

### 5.4 会话管理

数据模型对齐 RN `AgentChatSession`（含 `messages`、`toolCalls`、可选 `llmSummary` / `llmCompactedUntilId`）。

| 规则         | 行为                                                                          |
| ------------ | ----------------------------------------------------------------------------- |
| 分桶         | `assistant:sessions:{adminUserId}`                                            |
| 配额         | 最多 10；超限按 `lastUsedAt` LRU 淘汰                                         |
| 标题         | 首条用户消息截断约 20 字                                                      |
| 落盘         | 首条有效用户消息创建；每轮结束或 Stop 后保存                                  |
| 草稿         | 无用户消息不占配额                                                            |
| 续聊         | 完整恢复 `messages`（含 toolCalls，A2UI 可再绘）                              |
| 回开面板     | 恢复上次活跃会话；已删/淘汰则新草稿                                           |
| 生成中切会话 | 不强制后台跑完；可 Stop 当前轮再切；不做 RN 离页保活                          |
| 清空全部     | 二次确认                                                                      |
| 主动登出     | 删除该管理员会话桶 + 自有模型配置；Toast 明确「对话记录与本地模型密钥已清除」 |
| 401          | 仅清登录会话 Token；助手 localStorage **保留**                                |

### 5.5 对话交互

- 流式展示 assistant 文本。
- 生成中：禁用输入；提供 Stop。
- 最近一条失败/空回复：重试；正常完成：可重新生成（去掉末条 assistant，用上一 user 再跑）。
- 工具调用中展示过程（工具名 + 进行中/成功/失败），结果区渲染 A2UI。
- Markdown 仅作辅文（解释口径、注意点），**数字结论以卡片/图表为准**。

### 5.6 工具集（只读）

#### A. 用户管理（Node）

| 工具名（逻辑名）    | 后端                       | A2UI 组件（逻辑名） |
| ------------------- | -------------------------- | ------------------- |
| `admin_users_list`  | `GET /api/admin/users`     | 用户列表卡片        |
| `admin_user_detail` | `GET /api/admin/users/:id` | 用户详情卡片        |

- 列表入参对齐现有 query：`keyword` / `role` / `status` / `page` / `pageSize`。
- 卡片展示学号、姓名、学院、年级、角色、状态、在线等已有字段；详情可含设置摘要。
- **禁止**包装 PATCH / 设密。

#### B. 专用问数（Node 已有 GET）

能回答「总用户/在线/今日新增」「用户增长趋势」「性别/学院/校区分布」「设置分布」「今日 DAU/打开/浏览/崩溃」「某指标趋势」「崩溃列表」时必须走下列工具，禁止用 SQL 代替。

| 工具名（逻辑名）              | 后端                                             | 默认可视化 |
| ----------------------------- | ------------------------------------------------ | ---------- |
| `admin_dashboard_overview`    | `GET /api/admin/dashboard/overview`              | KPI 卡片组 |
| `admin_user_growth`           | `GET /api/admin/dashboard/user-growth`           | 折线       |
| `admin_user_distribution`     | `GET /api/admin/dashboard/user-distribution`     | 饼或柱     |
| `admin_settings_distribution` | `GET /api/admin/dashboard/settings-distribution` | 饼         |
| `admin_track_overview`        | `GET /api/admin/track/overview`                  | KPI 卡片组 |
| `admin_track_trend`           | `GET /api/admin/track/trend`                     | 折线       |
| `admin_track_dims`            | `GET /api/admin/track/dims`                      | 柱或饼     |
| `admin_track_crashes`         | `GET /api/admin/track/crashes`                   | 明细表     |

`llm-proxy-fails` 一期可不进助手（非问数主路径）；需要时用 SQL 兜底。

#### C. SQL 兜底（Go Track，经 Node）

| 工具名（逻辑名）  | 后端（新增）                          | 可视化                                   |
| ----------------- | ------------------------------------- | ---------------------------------------- |
| `admin_track_sql` | `POST /api/admin/track/query`（建议） | 按 `chartType`：line / bar / pie / table |

**入参（逻辑）**

- `sql`：模型生成的 SELECT。
- `chartType`：`line` \| `bar` \| `pie` \| `table`。
- 趋势 → line；比例/构成 → pie；对比分类 → bar；明细/无法识别 → table。

**出参（逻辑）**

- 回显 `sql`。
- `columns` + `rows`（行数受 LIMIT 截断时标记 `truncated`）。
- 前端用已有 echarts 能力渲染，嵌在该条 assistant 的 tool 段，不是跳转大屏页。

### 5.7 A2UI（Controlled）

复用 SDK：`ToolDefinition.render.component` 字符串 + Web 端 `ToolUIRegistry` 映射到 DOM 组件。

| 组件逻辑名        | 用途                         |
| ----------------- | ---------------------------- |
| `AdminUserList`   | 用户列表                     |
| `AdminUserDetail` | 用户详情                     |
| `AdminKpiGroup`   | 概览数字                     |
| `AdminChart`      | echarts 折线/柱/饼           |
| `AdminDataTable`  | 崩溃列表、SQL 明细           |
| `AdminSqlBlock`   | 只读展示已执行 SQL（可折叠） |

- 禁止把原始超大 `rows` 再抄进 Markdown。
- 加载/失败三态与 RN 工具卡一致。
- 图表依赖已有 `echarts` / `echarts-for-react`，不新开大屏路由。

### 5.8 后端契约（本期新增）

#### 5.8.1 Admin 平台 LLM 代理

新增与 App 对齐的 OpenAI Chat Completions 兼容接口：

- `POST /api/admin/llm/v1/chat/completions`
- 鉴权：已建档管理员 JWT（禁止 bootstrap 票调业务，与其它 `/api/admin/**` 一致）
- 行为对齐 `POST /api/app/llm/v1/chat/completions`：流式、忽略客户端 `model` 用池内调度、串行换 Key、同一套业务错误码（`42910` 等）
- 管理端浏览器：`Authorization: Bearer <adminJwt>`，`baseURL` 指向该前缀

Key 池 CRUD 仍只给「LLM 密钥池」页，**不**给助手写 tool。

#### 5.8.2 Track 只读 SQL

**管理端浏览器禁止直连 Track。**

建议：

1. Go：Internal Token 保护的只读查询（如 `POST /v1/internal/sql/query`），body `{ sql }`。
2. Node：`POST /api/admin/track/query`，Admin JWT → 转发 Go；对外 `{ code, message, data }` + camelCase。

**Go 必须执行的闸门（验收项）**

| 规则     | 要求                                                                                                           |
| -------- | -------------------------------------------------------------------------------------------------------------- |
| 语句     | 仅一条 `SELECT`（可用 CTE/`WITH` 若实现允许，但最终仍为只读查询）                                              |
| 禁止     | `INSERT`/`UPDATE`/`DELETE`/`REPLACE`/`ALTER`/`DROP`/`ATTACH`/`PRAGMA` 改状态、多语句 `;`、注释绕过需被解析拒绝 |
| 表白名单 | `events`、`daily_metrics`、`daily_dims`、`user_presence`                                                       |
| 禁止表   | `meta_jobs` 及其它未列出对象                                                                                   |
| LIMIT    | 若 SQL 无 LIMIT 或 LIMIT 过大，服务端强制上限（建议 500）                                                      |
| 超时     | 查询超时失败，不得拖死进程                                                                                     |
| 响应     | 列名 + 行数据；超限 `truncated: true`                                                                          |

错误：非法 SQL → 4xx，助手展示失败态，不假装查到 0 行。

Track 不可达：沿用现有代理 `50201` / `50301` 语义。

### 5.9 鉴权与安全

- 所有 Node 工具请求带 Admin JWT。
- 自有 Key 只在浏览器发往用户填写的 baseURL。
- SQL 与用户数据仅管理员可见；不在前端日志打印完整 Key。
- 主动登出必须清助手存储（见 5.4）。

### 5.10 响应式

继续预留 Spec：窄屏全屏助手、热区 ≥44px、不依赖 hover。图表在窄屏可横向滚动或自适应宽度，不得撑破抽屉。

## 6. 业务流程

```
打开助手
  → 解析模型配置（自有 Key / 平台代理 / 空态）
  → 恢复活跃会话或草稿

用户发送自然语言
  → 流式 AgentLoop
  → 用户/名单/档案类 → admin_users_*
  → 标准指标 → dashboard_* / track_* GET
  → 非常规 Track 分析 → 生成 SELECT → admin_track_sql
  → A2UI 渲染卡片或 echarts
  → 落盘会话

主动退出登录
  → 清 Admin 登录态
  → 清该管理员会话桶与本地模型配置
  → 告知用户
```

## 7. 验收标准

### 7.1 对话与模型

- [ ] 已登录未配 Key：可走平台代理完成一轮问数（Node 池可用时）。
- [ ] 配好自有 Key：走用户 baseURL，不经过平台 completions。
- [ ] 未登录且无 Key：不能 mock 出答案。
- [ ] 流式、Stop、重试/重新生成、生成中无法再发。

### 7.2 会话

- [ ] 刷新页面后能打开上次会话（含图表/用户卡所需 toolCalls）。
- [ ] 最多 10 条；第 11 条创建淘汰最久未用。
- [ ] 主动登出后会话与 Key 消失，并有明确提示。
- [ ] 仅 401 掉登录再登回同一管理员：会话仍在。

### 7.3 只读与问数

- [ ] 「查学号/姓名」出用户列表卡，不是纯表 Markdown。
- [ ] 「今天日活」走 track overview（或等价专用 tool），KPI 展示。
- [ ] 「近 7 日新增用户」走 user-growth，折线。
- [ ] 非常规 Track 问题走 SQL；气泡可见 SQL + 图表或表。
- [ ] 尝试让模型改用户状态 / 执行 DELETE：无对应 tool，且 SQL 接口拒绝写语句。

### 7.4 工程

- [ ] 管理端不出现 Track 内网地址与 Internal Token。
- [ ] `pnpm --filter nongyu-web-admin type-check` 通过。
- [ ] Node / Go 新增接口有单测覆盖闸门与鉴权（Tech/计划阶段列出用例）。

### 7.5 UI

- [ ] PC 抽屉 / 窄屏全屏仍符合预留 Spec。
- [ ] 符合 MASTER（主色 `#10B981`、大圆角卡片）。
