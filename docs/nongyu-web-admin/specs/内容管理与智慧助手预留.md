## 1. 背景

对照管理端 PRD，在排除数据大屏后，仍缺：**官方发帖**、**反馈/建议管理**、**智慧助手**。  
发帖与用户帖后端已齐；智慧助手无问数契约且大屏本轮不做，故只做**可开关 UI + 接入契约**，方便后续接 Agent。全站须满足响应式（手机 / 平板 / PC，含 WebView）。

---

## 2. 目标

1. 侧栏增加「内容管理」：Tab **公告 / 反馈 / 建议**，对接 `/api/admin/posts*`。
2. 公告：列表（含阅读量、覆盖率）、发布、编辑、软删。
3. 反馈（`feedback`）、建议（`courtyard`）：列表、详情、软删；不代发、不编辑正文（后端也不允许编辑非公告）。
4. 智慧助手：顶栏/壳层入口，默认关闭；PC 右侧抽屉、移动全屏；导出清晰接入接口，本刀不接模型/不问数。
5. 列表、表单、助手面板在窄屏可用；触摸热区 ≥44px；禁止仅 hover 才能完成的操作。

---

## 3. 边界（非目标）

- 数据大屏及一切图表指标页。
- 智慧助手真实对话、工具调用、会话持久化、问数。
- App 版本管理（PRD 未要求）。
- 富文本编辑器 / 图片上传（公告 `content` 按纯文本或多行文本提交；若内容含 HTML 则详情区安全展示为文本或消毒后只读，本刀不引入新编辑器依赖）。
- 恢复已软删帖（无后端恢复接口）；可选「含已删除」只读查看。
- 独立技术方案文档（默认跳过 Tech，审查后若需要再补）。

---

## 4. 详细需求

### 4.1 信息架构与路由

| 路由 / 入口      | 说明                                                                                  |
| ---------------- | ------------------------------------------------------------------------------------- |
| `/content`       | 内容管理页；Query `?tab=announcement\|feedback\|suggestion` 可选，默认 `announcement` |
| 侧栏「内容管理」 | 插在「用户管理」之后；顺序：工作台 → 数据大屏 → 用户管理 → **内容管理**               |
| 智慧助手入口     | 壳层顶栏按钮（如机器人图标）；**不**进侧栏菜单；默认不打开面板                        |

工作台可增加一张 Bento 卡链到 `/content`（可选，推荐做）。

### 4.2 类型映射

| UI Tab | `postType`     | 管理能力                                |
| ------ | -------------- | --------------------------------------- |
| 公告   | `announcement` | 列表、发布、编辑、软删、看阅读量/覆盖率 |
| 反馈   | `feedback`     | 列表、详情、软删                        |
| 建议   | `courtyard`    | 列表、详情、软删                        |

### 4.3 列表（三 Tab 共用模式）

**筛选**

- 关键词 `keyword`（防抖 ~300ms）
- 公告 Tab：可选 `subtype` 精确筛选（输入框，可空）
- 「含已删除」开关 → `includeDeleted`（默认关）
- 分页：`page` 从 1，`pageSize` 默认 20；改筛选重置页码

**列**

| 列                  | 公告                         | 反馈/建议      |
| ------------------- | ---------------------------- | -------------- |
| 标题                | ✓                            | ✓              |
| 子类型 subtype      | ✓                            | ✓              |
| 作者                | ✓                            | ✓（学号+姓名） |
| 发布时间            | ✓                            | ✓              |
| 阅读量 viewCount    | ✓                            | 可显示         |
| 覆盖率 coverageRate | ✓（百分比，保留 1 位小数）   | 可显示         |
| 状态                | 已删除 Tag（若 `deletedAt`） | 同左           |

- 点击行：公告/反馈/建议均打开**详情抽屉**（窄屏可用全屏 Drawer）。
- 公告 Tab 工具栏：「发布公告」主按钮。
- 已软删行：不可编辑；可仍打开详情只读。

### 4.4 公告发布 / 编辑

- 抽屉或 Modal 表单（窄屏优先全宽抽屉）：`subtype`、`title`、`content`（TextArea）、可选 `publishedAt`（不选则服务端默认现在）。
- 校验：subtype 1–32；title 1–200；content 非空。
- 创建 → `POST /api/admin/posts`；编辑 → `PATCH /api/admin/posts/:id`（仅未删除公告）。
- 成功 Toast + 关闭 + 刷新列表。

### 4.5 详情与删除

- 详情展示全文、作者、时间、阅读量、覆盖率、删除态。
- 软删：确认「删除后用户端不可见，确定继续？」→ `DELETE /api/admin/posts/:id`。
- 反馈/建议无「编辑」按钮。

### 4.6 智慧助手预留

**交互**

- 入口在顶栏；点击切换开/关。
- **PC（≥992px）**：右侧抽屉宽度约 380–420px，盖住内容区右侧，可关闭。
- **窄屏**：全屏面板（或高度近全屏的 Drawer），带关闭按钮。
- 默认关闭；刷新后默认仍关闭（不必持久化开闭，若实现简单可用 `sessionStorage` 亦可，非必须）。

**本刀 UI 内容**

- 标题「智慧助手」
- 空态：「问数能力即将接入，可先从这里打开面板。」
- 禁用的输入框 + 发送按钮（或发送直接 Toast「暂未接入」），表明交互位已留好。

**接入契约（代码层，必须落地）**

在 `src/assistant/`（或等价目录）提供稳定类型与插槽，后续只替换实现、不改壳：

```ts
/** 后续 Agent 接入时实现此契约 */
export type AssistantMessage = {
  id: string;
  role: "user" | "assistant" | "system";
  content: string;
  createdAt: string; // ISO
};

export type AssistantChatAdapter = {
  /** 发送用户消息；实现方可流式回调 */
  send: (text: string) => Promise<void> | void;
  /** 当前消息列表（由实现方或容器持有） */
  getMessages?: () => AssistantMessage[];
};

export type AssistantPanelProps = {
  open: boolean;
  onClose: () => void;
  /** 未传则使用内置占位适配器 */
  adapter?: AssistantChatAdapter;
};
```

- `AssistantPanel` 消费 `adapter`；占位适配器的 `send` 仅提示未接入。
- 禁止本刀引入模型密钥到前端仓库；不接 `nongyu-agent-sdk` 真实运行（可在注释中标明后续依赖方向）。

### 4.7 响应式（强制验收）

| 断点      | 要求                                                                             |
| --------- | -------------------------------------------------------------------------------- |
| &lt;992px | 侧栏改汉堡；内容管理筛选控件可折行；表格 `scroll.x`；详情/发帖用大抽屉；助手全屏 |
| ≥992px    | 常驻侧栏；助手右侧抽屉                                                           |
| 通用      | 主按钮/图标按钮热区 ≥44×44；不依赖 hover；`prefers-reduced-motion` 不强动画      |

视觉继续 MASTER：大圆角卡片、主色 `#10B981`。

### 4.8 后端对接

| 方法   | 路径                   | 用途                                            |
| ------ | ---------------------- | ----------------------------------------------- |
| GET    | `/api/admin/posts`     | 列表                                            |
| GET    | `/api/admin/posts/:id` | 详情（可选，列表项已含 content 时可用列表数据） |
| POST   | `/api/admin/posts`     | 发公告                                          |
| PATCH  | `/api/admin/posts/:id` | 编辑公告                                        |
| DELETE | `/api/admin/posts/:id` | 软删                                            |

鉴权：已建档 Admin JWT（非 bootstrap）；403 提示与用户管理一致。

---

## 5. 业务流程

```
内容管理
  → 选 Tab → GET posts?postType&...
  → 公告：发布/编辑表单 → POST/PATCH → 刷新
  → 任一行：详情 → 可选 DELETE 软删

智慧助手
  → 点入口 → open=true → 渲染 AssistantPanel(占位 adapter)
  → 后续：传入真实 adapter 即可，不改壳布局
```

## 6. 验收标准

### 6.1 内容管理

- [ ] `/content` 三 Tab 可切换；URL tab 与 UI 同步（推荐）。
- [ ] 公告可发布、编辑、软删；列表可见阅读量与覆盖率。
- [ ] 反馈/建议可浏览与软删，无编辑/发布。
- [ ] 关键词与「含已删除」生效。
- [ ] 窄屏表格可横滑，发帖/详情可完成全流程。

### 6.2 智慧助手预留

- [ ] 默认不展示面板；入口可打开/关闭。
- [ ] PC 右侧、移动全屏形态符合 §4.6。
- [ ] 存在可编译的 `AssistantChatAdapter` / `AssistantPanelProps`；占位 send 不调用后端。
- [ ] 无模型密钥、无真实问数。

### 6.3 响应式与工程

- [ ] 符合 MASTER 与 §4.7。
- [ ] `pnpm --filter nongyu-web-admin type-check` 与本包 oxlint 通过。
