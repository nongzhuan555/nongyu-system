## 1. 背景

管理端「内容管理」已有全站帖子列表（公告 / 反馈 / 大院，含实名作者）与公告 CRUD。本期补齐：

- 反馈墙帖子的**单条管理员回复**增删改（各管理员权限平等，无操作留痕）。
- 大院留言的**单独删除**（不删帖）。
- 帖子详情展示**实名留言 / 回复信息**。
- 删帖连带删回复（后端级联，前端仅感知最终状态）。

管理端对留言 / 回复作者**实名**展示（学号 + 姓名），与既有帖子作者展示一致。

## 2. 目标

1. 反馈墙帖子详情：展示已有管理员回复（含回复时间），支持创建 / 编辑 / 删除该单条回复。
2. 大院帖子详情：展示留言列表（实名），支持单独删除任意留言。
3. 帖子列表：展示回复 / 留言数量角标（可选，便于筛选）。
4. 复用既有 `adminApi` / Antd Drawer / Modal.confirm / message 体系。

## 3. 边界（非目标）

- 不做管理员回复操作留痕 UI（不展示「由谁修改 / 修改时间」）。
- 不做嵌套回复 UI。
- 不做公告墙回复 / 留言 UI（公告无回复）。
- 不做留言 / 回复的点赞、举报、富文本、图片。
- 不做管理员回复的批量操作。
- 不引入新 UI 组件库；继续 Antd + Tailwind 既有体系。

## 4. 数据模型与 API 封装

### 4.1 类型扩展（`src/types/posts.ts`）

```ts
export type AdminPostReply = {
  id: number;
  content: string;
  publishedAt: string;
  updatedAt: string;
  authorUserId: number;
  authorStudentNo: string;
  authorName: string;
};

export type AdminPostComment = {
  id: number;
  content: string;
  publishedAt: string;
  authorUserId: number;
  authorStudentNo: string;
  authorName: string;
};

export type AdminPostItem = {
  // ...既有字段
  /** 未软删回复总数（含 admin_reply 与 comment） */
  replyCount?: number;
  /** 反馈墙：已有管理员回复（详情用，列表可不返回） */
  adminReply?: AdminPostReply | null;
  /** 大院：留言列表（详情用，列表可不返回） */
  comments?: AdminPostComment[];
};
```

### 4.2 新增 API（`src/lib/adminApi.ts`）

```ts
/** POST /api/admin/posts/:id/reply —— 创建反馈墙管理员回复 */
export async function createAdminPostReply(
  postId: number,
  body: { content: string },
): Promise<{ id: number; content: string; publishedAt: string }>;

/** PATCH /api/admin/posts/:id/reply —— 更新反馈墙管理员回复 */
export async function patchAdminPostReply(
  postId: number,
  body: { content: string },
): Promise<{ id: number; content: string; publishedAt: string }>;

/** DELETE /api/admin/posts/:id/reply —— 删除反馈墙管理员回复 */
export async function deleteAdminPostReply(postId: number): Promise<void>;

/** DELETE /api/admin/posts/:id/comments/:commentId —— 删除大院留言 */
export async function deleteAdminPostComment(postId: number, commentId: number): Promise<void>;
```

鉴权、错误处理复用既有 `adminApi` 模式（`AdminApiError`、统一 envelope 解析）。

## 5. 详细需求

### 5.1 帖子详情抽屉（`PostDetailDrawer` 扩展）

#### 5.1.1 反馈墙详情

- 在正文下方新增「管理员回复」区块：
  - 若已有回复（`adminReply` 非空）：
    - 展示回复内容 + 回复时间（`formatAdminDateTime(publishedAt)`）+ 回复作者实名（`authorName（authorStudentNo）`）。
    - 操作按钮：「编辑」（打开内联编辑或 Modal）、「删除」（`Modal.confirm` 二次确认）。
  - 若无回复：
    - 展示「暂无回复」+「添加回复」按钮。
- 「添加回复」/「编辑」：使用 `Modal` + `Input.TextArea`（ maxLength 2000，showCount），提交调用 `createAdminPostReply` / `patchAdminPostReply`。
- 创建遇 409（已有回复）：message 提示「该帖已有回复，已为你刷新」，刷新详情后切换为编辑态。
- 成功后刷新详情（重新拉取 `GET /api/admin/posts/:id`）。
- **不展示**回复的 `updatedAt` / 修改人（无操作留痕）。

#### 5.1.2 大院详情

- 在正文下方新增「留言」区块：
  - 标题行「留言 · N」。
  - 留言列表：每条展示内容 + 时间 + 作者实名（`authorName（authorStudentNo）`）+「删除」按钮（`Modal.confirm` 二次确认，调用 `deleteAdminPostComment`）。
  - 排序：服务端 `created_at ASC`。
  - 空态：「暂无留言」。
- 删除成功后刷新详情。

#### 5.1.3 公告详情

- 不渲染回复 / 留言区块（保持现状）。

#### 5.1.4 已删除帖

- 帖子 `deletedAt` 非空时：回复 / 留言区块不展示操作按钮（只读或隐藏）；因后端级联软删，正常情况下已删除帖的回复也均为软删，列表为空。

### 5.2 帖子列表（`PostListPanel` 扩展，可选）

- 列表新增「回复」列（或合并到既有列）：
  - 展示 `replyCount`（未软删回复总数）。
  - feedback 帖：`replyCount > 0` 时 Tag `success`「已回复」，否则 Tag `default`「未回复」。
  - courtyard 帖：展示「N 条留言」。
  - announcement 帖：展示「—」或不展示该列。
- 便于管理员快速识别待回复的反馈帖。
- 该列依赖后端 `GET /api/admin/posts` 返回 `replyCount`（见 Node Spec §5.2.7）。

### 5.3 删帖连带

- 既有 `deleteAdminPost` 流程不变；后端级联软删回复，前端删除成功后刷新列表即可，无需额外处理留言。

## 6. 业务流程

### 6.1 反馈墙管理员回复

```
管理端内容管理 → 选反馈帖 → 打开详情抽屉
  → 无回复：点「添加回复」→ Modal 输入 → POST reply → 201 → 刷新详情
  → 有回复：点「编辑」→ Modal 输入 → PATCH reply → 200 → 刷新详情
  → 有回复：点「删除」→ Modal.confirm → DELETE reply → 200 → 刷新详情
  → 创建遇 409：message 提示 + 刷新详情切编辑态
```

### 6.2 大院留言审核

```
管理端内容管理 → 选大院帖 → 打开详情抽屉
  → 留言列表（实名）→ 点某条「删除」→ Modal.confirm → DELETE comment → 200 → 刷新详情
```

### 6.3 删帖

```
管理端列表 / 详情 → 删帖 → 后端级联软删回复 → 刷新列表
```

## 7. 验收标准与测试方案

### 7.1 UI / 交互验收

| #   | 场景         | 期望                                                             |
| --- | ------------ | ---------------------------------------------------------------- |
| 1   | 反馈帖无回复 | 详情见「暂无回复」+「添加回复」按钮                              |
| 2   | 添加回复     | Modal 输入 → 提交 → 详情见回复内容 + 时间 + 作者实名             |
| 3   | 编辑回复     | Modal 回填内容 → 修改 → 提交 → 详情更新；无修改人 / 修改时间展示 |
| 4   | 删除回复     | Modal.confirm → 删除 → 详情回到「暂无回复」                      |
| 5   | 创建遇 409   | message 提示「已有回复」+ 刷新详情切编辑态                       |
| 6   | 大院帖有留言 | 详情见留言列表（内容 + 时间 + 实名 + 删除按钮）                  |
| 7   | 删除单条留言 | Modal.confirm → 删除 → 列表移除；帖子仍在                        |
| 8   | 公告详情     | 不渲染回复 / 留言区块                                            |
| 9   | 已删除帖     | 回复 / 留言区块无操作按钮                                        |
| 10  | 列表回复列   | feedback 已/未回复 Tag；courtyard N 条留言；announcement 「—」   |
| 11  | 内容长度边界 | 超过 2000 字拦截 + 提示                                          |

### 7.2 非功能

- `pnpm lint` / `type-check` / `format` 通过。
- 复用既有 `adminApi` 错误处理；409 / 404 等业务码有可读提示。
