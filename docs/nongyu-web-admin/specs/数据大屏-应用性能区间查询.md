# Spec：数据大屏 · 应用性能区间查询

| 项        | 内容                                                                                                   |
| --------- | ------------------------------------------------------------------------------------------------------ |
| 应用      | `apps/nongyu-web-admin`（BFF：`nongyu-node-server`；Track：`nongyu-node-track-server`）                |
| 需求类型  | **业务**                                                                                               |
| PRD       | `docs/forhuman/rawprds/nongyu-web-admin/数据大屏应用性能区间查询PRD.md`                                |
| 上游 Spec | `数据大屏.md`；`管理端Track指标代理.md`；`docs/nongyu-node-track-server/specs/应用性能dims区间分位.md` |
| 状态      | **已实现**                                                                                             |

---

## 1. 背景

「应用性能」卡仅展示业务日当天的 `perf` p50/p95，无法判断课表首屏等指标在近几天是否持续偏慢。需支持在卡片内切换区间，对区间内原始样本重算分位（方案 C）。

---

## 2. 目标

1. `chart-perf` 卡头可选：`今天` / `近 7 天` / `近 30 天`；默认今天。
2. 所选区间写入 `DashboardPrefsV1.perfRange`，刷新后仍生效。
3. 切换区间只重拉 `perf_p50` + `perf_p95`，该卡单独 loading；其它 Track 卡不动。
4. 区间内分位与 Track 契约一致：全样本重算，排除 web（与现网 App 性能卡一致）。

---

## 3. 边界（非目标）

- 不改页面次数 / 停留 / 按钮 / Web Vitals / KPI / 崩溃表时间范围。
- 不做按日趋势折线。
- 不延长原始事件保留；不做近 90 天。
- 不 bump prefs `version`（仍为 1）。
- 不写独立技术方案文档（除非评审时另行要求）。
- 不同步 Go Track。

---

## 4. 详细需求

### 4.1 区间枚举

| `perfRange` | UI 文案  | 业务日闭区间                           |
| ----------- | -------- | -------------------------------------- |
| `1d`        | 今天     | `[today, today]`                       |
| `7d`        | 近 7 天  | `[today-6d, today]`（含今天共 7 天）   |
| `30d`       | 近 30 天 | `[today-29d, today]`（含今天共 30 天） |

`today` = 与 BFF 其它 Track 接口相同的业务日（`BUSINESS_TZ`）。日期加减按日历日。

### 4.2 Prefs

- `DashboardPrefsV1` 增加可选字段 `perfRange?: "1d" | "7d" | "30d"`。
- `readDashboardPrefs`：缺省或非法值 → `1d`；`version !== 1` 仍整份回退；**仅缺 `perfRange` 不整份回退**。
- `defaultDashboardPrefs` / 「恢复默认布局」：`perfRange = "1d"`。
- 切换区间：更新内存 prefs 并 `writeDashboardPrefs`（与 `growthRange` 同策略）。

### 4.3 UI

- 控件：卡头 **小 Select**，选项同上表；位置在排序 Segmented 旁（布局与「用户增长趋势」的 range Select 同风格）。
- 切换后该卡 loading，成功则刷新柱状图；失败 toast 或卡内错误文案（与现 Track 错误隔离策略一致，不拖垮其它卡）。
- 空数据：仍「暂无性能样本」。
- 图表形态不变：分组柱 p50/p95，最多 20 条，排序逻辑不变。

### 4.4 数据请求

- 初始进入大屏：`loadTrack` 时按当前 `perfRange` 请求两路 perf dims（可与其它 Track 并行）。
- 仅切换 `perfRange`：只请求：

| 调用                            | 参数                                                                         |
| ------------------------------- | ---------------------------------------------------------------------------- |
| `fetchTrackDims("perf_p50", …)` | `from`/`to` 由 `perfRange` 映射；`1d` 可只传 `date=today` 或 `from=to=today` |
| `fetchTrackDims("perf_p95", …)` | 同上                                                                         |

- **不得**带 `platform=web` / `namePrefix=cwv_`（仍走 App 性能过滤，由 Track 默认排除 web）。
- 全量手动刷新工具栏：按当前 `perfRange` 重拉（与其它 Track 一起即可）。

### 4.5 Admin API 客户端

- `fetchTrackDims` 增加可选 `from` / `to`（`YYYY-MM-DD`），透传 Query。
- 与既有 `date`、`platform`、`namePrefix`、`limit` 兼容。

### 4.6 BFF / Track

见配套 Spec：

- `docs/nongyu-node-server/specs/管理端Track指标代理.md` §4.5 增量
- `docs/nongyu-node-track-server/specs/应用性能dims区间分位.md`

---

## 5. 业务流程

```
打开 /dashboard
  → read prefs.perfRange（默认 1d）
  → loadTrack：perf 按 from/to 拉 p50+p95
用户改 Select
  → write prefs.perfRange
  → 仅重拉 perf p50+p95 → 更新 chart-perf
```

---

## 6. 验收标准

| #   | 标准                                                                                     |
| --- | ---------------------------------------------------------------------------------------- |
| 1   | 默认「今天」与改前当日数据一致（同业务日、同过滤口径）。                                 |
| 2   | 切「近 7 天 / 近 30 天」后柱状值变化符合区间样本（有数据环境可人工核对）；无样本时空态。 |
| 3   | 刷新页面后仍记住所选区间。                                                               |
| 4   | 切换区间时其它 Track 卡无闪烁重载。                                                      |
| 5   | 恢复默认布局后 `perfRange` 回到「今天」。                                                |
| 6   | Web Vitals 卡不受影响。                                                                  |

**测试**：管理端手测为主；Track 区间分位依赖 Node Track 单测（见 Track Spec）。
