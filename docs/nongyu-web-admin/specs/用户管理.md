## 1. 背景

管理端壳、登录与超管引导已落地，`/users` 仍为占位页。PRD「用户管理」含用户信息、官方发帖、反馈/建议三块；本刀只把**用户信息管理**调通，对接已有 Admin 用户接口，让管理员能查人、看详情、改角色，并在升权后设置农屿管理员密码。

**增量（2026-09-04）**：去掉管理端「禁用 / 启用」操作入口；修复详情抽屉内「设为管理员 / 取消管理员」确认框被 Drawer 遮罩挡住导致点击无反应的问题。

---

## 2. 目标

1. `/users` 展示可分页、可筛选的用户列表（对接 `GET /api/admin/users`）。
2. 点击行打开抽屉：只读档案/设备/设置摘要 + 可改 `role`（对接 `GET/PATCH /api/admin/users/:id`）；**不再提供前端改 `status` 的入口**。
3. 升为管理员后可设/重置管理员密码（对接 `PUT /api/admin/users/:id/admin-password`，≥8 位）。
4. 禁止当前登录管理员对自己降权；危险操作有确认；确认框须叠在详情抽屉之上、可正常交互。
5. 不改后端契约；不实现发帖、反馈、建议。

---

## 3. 边界（非目标）

- 官方发帖、反馈墙、建议管理（PRD 另两块）。
- 编辑姓名/学院等档案字段（后端本接口不支持）。
- 独立详情路由 `/users/:id`。
- 独立技术方案 / 实施计划文档（已约定跳过 Tech / Plan）。
- bootstrap 超管会话的业务写操作（沿用壳层提示；接口会 403，前端列表可加载失败时给出可行动提示）。
- 批量操作、导出、删除用户。
- 修改**自己**的管理员密码（已有顶栏「修改密码」）。
- **移除后端 `PATCH status` 能力**（契约保留；仅去掉管理端 UI 入口）。
- **去掉列表「状态」筛选 / 列 / 详情状态只读展示**（仍保留，便于排查历史禁用账号）。

---

## 4. 详细需求

### 4.1 路由与入口

| 路由     | 行为                       |
| -------- | -------------------------- |
| `/users` | 用户管理页（替换原占位页） |

- 侧栏「用户管理」不变；工作台 Bento「用户管理」卡片仍链到 `/users`。
- 需已登录；鉴权守卫沿用现有壳。

### 4.2 列表

**筛选（与 Query 对齐）**

| 控件     | 参数          | 说明                                                                              |
| -------- | ------------- | --------------------------------------------------------------------------------- |
| 关键词   | `keyword`     | 学号/姓名模糊；输入后防抖约 300ms 再请求                                          |
| 角色     | `role`        | 全部 / 普通用户(`0`) / 管理员(`1`)                                                |
| 状态     | `status`      | 全部 / 正常(`1`) / 禁用(`0`)                                                      |
| 在线     | `isOnline`    | 全部（不传）/ 仅当前在线（`1`）；口径见在线筛选 Spec                              |
| 今日活跃 | `activeToday` | 全部（不传）/ 仅今日活跃（`1`）；按 `last_active_at` 业务日，**近似活跃，非 DAU** |

**分页**

- `page` 从 1；默认 `pageSize = 20`（不超过后端上限 100）。
- 展示总数；切换筛选时重置到第 1 页。

**列（桌面）**

| 列       | 来源                                   |
| -------- | -------------------------------------- |
| 学号     | `studentNo`                            |
| 姓名     | `name`                                 |
| 学院     | `college`                              |
| 年级     | `grade`                                |
| 角色     | `role` 标签                            |
| 状态     | `status` 标签                          |
| 在线     | `isOnline`                             |
| 最近登录 | `lastLoginAt`（本地化展示；空则「—」） |
| 注册时间 | `createdAt`                            |

- **校区**：列表响应字段 `campus` **仍可存在（先获取）**，列 **暂不展示**（见 `隐藏校区与移动端布局优化.md`）。
- **≥992px**：Table；点击行打开详情抽屉；行内不必再放「编辑」按钮。
- **&lt;992px**：卡片列表（姓名、学号、角色、状态）；点击卡片打开抽屉；筛选与分页仍可用。
- 加载中：表格/卡片 Skeleton/Spin；失败：错误提示 + 重试；空列表：空态文案「暂无用户」。

### 4.3 详情抽屉

打开时请求 `GET /api/admin/users/:id`。

**只读区**

1. 基本：学号、姓名、角色、状态、在线、最近活跃、最近登录、注册时间
2. 档案：专业、学院、班级、年级、性别、家乡、QQ（空显示「—」）。字段 `campus` 若返回则 **暂不展示**
3. 设备：品牌、型号、系统、`currentDeviceId`
4. 设置摘要：`theme`、`homeIsTimetable`、`openWebInApp`、`agentEnabled`、`highlightTodayColumn`、`courseCardColorMode` 等（按返回字段展示，只读）

**操作区**

| 操作           | 条件 / 行为                                                                                 |
| -------------- | ------------------------------------------------------------------------------------------- |
| 设为管理员     | 仅超管可见；目标 `role===0`；确认后 `PATCH { role: 1 }`；成功后打开设密弹窗                 |
| 取消管理员     | 仅超管可见；目标 `role===1` 且非本人；确认文案须说明会清空其管理员密码；`PATCH { role: 0 }` |
| 设置管理员密码 | 目标 `role===1` 或 `2`；弹窗输入新密码（≥8）与确认密码一致后 `PUT .../admin-password`       |

- **不再提供**「禁用」「启用」按钮；前端不得再对用户发起 `PATCH { status }`。
- 抽屉内确认框（升权 / 降权）**必须叠在 Drawer 之上**（提高 zIndex / 挂载到 body），避免被抽屉遮罩挡住表现为「点击无反应」。

**对自己**

- 目标 `id` 等于当前会话 `user.id` 时：「取消管理员」禁用并 Tooltip「不能对自己执行此操作」。
- 「设置管理员密码」对自己仍可用（与顶栏改密等价入口，允许）。

### 4.4 设密弹窗

- 字段：新密码、确认密码；均可显隐。
- 校验：长度 ≥8；两次一致；失败不发请求。
- 成功：Toast「管理员密码已更新」；关闭弹窗。
- 密码不入 `localStorage`、不打日志。

### 4.5 文案与反馈

| 场景             | 文案                                                                           |
| ---------------- | ------------------------------------------------------------------------------ |
| 列表加载失败     | 优先展示后端 `message`；网络失败「网络异常，请稍后重试」                       |
| bootstrap 无权限 | 若返回需建档/无权限类错误，提示先在 App 用该学号登录建档（与壳层横幅语义一致） |
| PATCH/设密成功   | Toast 成功；刷新当前抽屉数据与列表对应行                                       |
| 确认降权         | 「取消管理员后将清空其管理员密码，确定继续？」                                 |

### 4.6 后端对接

| 方法  | 路径                                  | 用途                 |
| ----- | ------------------------------------- | -------------------- |
| GET   | `/api/admin/users`                    | 列表                 |
| GET   | `/api/admin/users/:id`                | 详情                 |
| PATCH | `/api/admin/users/:id`                | `{ role?, status? }` |
| PUT   | `/api/admin/users/:id/admin-password` | `{ adminPassword }`  |

- 鉴权：Admin JWT；须非 bootstrap（`requireProvisionedAdminAuth`）。
- 统一响应包与现有 `adminApi` 拦截器一致；`401*` 仍走全局登出。

### 4.7 视觉

- 沿用壳层：内容区大圆角白卡片、主色 `#10B981`、圆角 16。
- 使用 Ant Design `Table` / `Drawer` / `Select` / `Input` / `Modal` / `Tag`；不引入 ProComponents。
- 角色：管理员=主色 Tag；普通=默认。状态：正常=成功色；禁用=默认/警告。

---

## 5. 业务流程

```
进入 /users
  → GET /users?page&pageSize&keyword&role&status
  → 点行 → GET /users/:id → 抽屉
改角色
  → Confirm（须叠在抽屉之上）→ PATCH { role }
  → 若升为管理员 → 设密弹窗 → PUT admin-password
  → 刷新详情与列表
```

## 6. 验收标准

### 6.1 UI

- [ ] `/users` 不再是「即将开放」占位。
- [ ] 列表 + 筛选项 + 分页完整；窄屏可用。
- [ ] 抽屉分区清晰：档案 / 设备 / 设置 / 操作；操作区**无**「禁用 / 启用」。

### 6.2 功能

- [ ] 关键词、角色、状态筛选与分页正确请求后端。
- [ ] 打开详情字段与接口一致；空值显示「—」。
- [ ] 升权 → 确认框可见可点 → 设密（≥8）成功后可用该学号+新密码登录管理端（非本人账号验证即可）。
- [ ] 降权有确认；对自己降权不可点。
- [ ] 详情抽屉内点击「设为管理员 / 取消管理员」立刻弹出确认框（不被 Drawer 挡住）。
- [ ] 未登录访问 `/users` 仍进登录；bootstrap 会话写操作失败有明确提示。

### 6.3 非功能

- [ ] 不扩后端；不存明文密码；不删除后端 `status` 相关契约。
- [ ] `pnpm --filter nongyu-web-admin type-check` 与本包 oxlint 通过。
