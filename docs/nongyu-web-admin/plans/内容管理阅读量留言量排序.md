# 实施计划：内容管理阅读量 / 留言量排序

| 项   | 内容                                                      |
| ---- | --------------------------------------------------------- |
| Spec | `docs/nongyu-web-admin/specs/内容管理阅读量留言量排序.md` |
| Tech | **跳过**（已约定）                                        |
| 状态 | **已实现**                                                |

## 步骤

1. **Node · `listPosts` 排序**
   - `repo.listPosts` 增加可选 `sortBy: "viewCount" | "replyCount"`、`sortOrder: "asc" | "desc"`
   - 默认：`ORDER BY p.published_at DESC, p.id DESC`
   - `viewCount`：`ORDER BY p.view_count {ASC|DESC}, p.published_at DESC, p.id DESC`
   - `replyCount`：`LEFT JOIN`（或相关子查询）`post_replies`（`deleted_at IS NULL`）按 `post_id` 聚合 `COUNT`，再按该计数排序；并列次序同上
   - 排序在 `LIMIT/OFFSET` 之前完成；列表响应仍用现有 `countRepliesForPosts` 填 `replyCount`（与 JOIN 口径一致）

2. **Node · 路由校验**
   - `GET /api/admin/posts` zod：`sortBy` enum 可选；`sortOrder` 可选；无 `sortBy` 仅有 `sortOrder` → 400（对齐用户列表文案）
   - 有 `sortBy` 时 `sortOrder` 默认 `desc`

3. **Node · 单测**
   - 覆盖：默认时间序、`viewCount` 升/降、`replyCount` 降序分页衔接、非法参数、仅 `sortOrder`
   - 可新建 `tests/adminPostsSort.test.ts` 或并入既有 posts 测试

4. **文档**
   - 更新 `docs/nongyu-node-server/接口文档概览.md`：`GET /api/admin/posts` Query 增加 `sortBy` / `sortOrder`

5. **Web · 类型与请求**
   - `AdminPostListQuery` 增加 `sortBy?` / `sortOrder?`
   - `listAdminPosts` 透传 query（已有 params，一般无需改签名逻辑）

6. **Web · `PostListPanel`**
   - 参照 `UsersPage` 活跃天数：受控 `sortBy`/`sortOrder` state + 列 `sorter: true` + `onChange` 解析
   - 「阅读量」「回复」两列可排序；改排序时 `setPage(1)`
   - `useEffect` 依赖补上排序字段；取消排序清空 `sortBy`

7. **收尾**
   - Spec / PRD / 本计划状态改为已实现
   - `pnpm lint` / `type-check` / 相关测试通过

## 风险

| 风险                               | 处理                                                          |
| ---------------------------------- | ------------------------------------------------------------- |
| `replyCount` JOIN 与列表口径不一致 | JOIN 条件与 `countRepliesForPosts` 相同：`deleted_at IS NULL` |
| 公告列无回复仍可点排序             | Spec 允许；结果多为 0，可接受                                 |
| 窄屏隐藏阅读量列                   | Spec 可接受；不另做工具栏下拉                                 |

## 注意

- 禁止当前页客户端排序。
- 不改统计口径、不改 App 列表。
- 编码使用 `backend-engineer` + `frontend-engineer`（或等价分工）按步骤落地。
