## 0. 阅读前提

SDD 步骤 4。Spec / Tech 已确认。本计划只排落地顺序、文件落点与每阶段退出标准，不改 WHAT。

编码时：Go 遵循 `golang-*` skills；Node 遵循 `nodejs-backend-patterns`；Web 遵循 `vercel-react-best-practices` 与 `design-system/web-admin/MASTER.md`。禁止改 `nongyu-agent-sdk` 协议（除非构建阻断，另开切片）。

## 1. 基线决策（与 Tech 对齐，实施时勿再分叉）

| #   | 事项       | 采用                                                                          |
| --- | ---------- | ----------------------------------------------------------------------------- |
| 1   | 对话运行时 | SDK `useAgentChat`，无 RN `AgentChatRunner`                                   |
| 2   | UI 壳      | 现有 `AssistantPanel` Drawer；不用 `nongyu-agent-gui`                         |
| 3   | Admin LLM  | `handleChatCompletions` 读 `appAuth.uid ?? adminAuth.uid`                     |
| 4   | SQL        | Go `sqlguard` + 只读连接；Node `POST /api/admin/track/query`                  |
| 5   | 图表类型   | 仅工具入参 `chartType`，不进 Go                                               |
| 6   | 大结果     | execute 瘦身给模型；完整 rows 用模块级 `Map<callId, rows>` 给卡片             |
| 7   | 登出       | 仅 `authStore.logout` 清助手数据并 Toast；401 `clearAuth` 不清                |
| 8   | 文档       | 实现时同步 `接口文档概览.md`；Go 无独立接口册则在 Track 相关 spec/tech 补一行 |

## 2. 范围

### 2.1 交付

1. Go：`POST /v1/admin/sql/query` + `sqlguard` + 单测
2. Node：Admin `chat/completions` + Track SQL 代理 + 单测 + 接口概览
3. Web：依赖 SDK、Agent 组装、会话、A2UI、设置、登出告知、改造抽屉

### 2.2 不做

- 写操作 tool、web_search、校园工具、离页保活、SDK 分包（除非 Vite 失败）
- 会话云同步、连通性探测非阻断验收

---

## 3. 实施阶段

一人顺序交付；**S1 → S2 → S3**，前一阶段退出标准未满足不进入下一阶段 UI 联调。S1/S2 可在同一提交前完成，但测试必须先绿。

### S1 · Go 只读 SQL

| 任务                                                                       | 路径                                             |
| -------------------------------------------------------------------------- | ------------------------------------------------ |
| `sqlguard`：去注释、单 SELECT/WITH、黑名单、FROM/JOIN 表白名单             | `apps/nongyu-go-track-server/internal/sqlguard/` |
| `Store` 增加带 timeout 的只读 `Query`（或 handler 内 `read.QueryContext`） | `internal/store/sqlite/` 或 handler              |
| `POST /v1/admin/sql/query`，Internal Token（挂在现有 `/v1/admin`）         | `internal/httpapi/router.go` + 新 handler        |
| LIMIT 改写 / 501 截断 / `truncated`                                        | handler                                          |
| 单测：合法查询、注入与写语句、禁表 `meta_jobs`                             | `sqlguard/*_test.go`、`httpapi` 测试             |

**退出**：`go test ./...` 在 track 模块通过；用 Internal Token 手工 POST 一条 `SELECT metric_key, metric_value FROM daily_metrics LIMIT 1` 返回列与行。

### S2 · Node 代理

| 任务                                                                      | 路径                                                          |
| ------------------------------------------------------------------------- | ------------------------------------------------------------- |
| `handleChatCompletions` uid 兼容 Admin                                    | `src/modules/llm-pool/proxy.ts`                               |
| `POST /api/admin/llm/v1/chat/completions` + `requireProvisionedAdminAuth` | `routes.admin-proxy.ts`；`app.ts` 挂载                        |
| `trackAdminPost`；INVALID_SQL → 40001                                     | `track/trackClient.ts`                                        |
| `POST /api/admin/track/query` body `{ sql }` max 8000                     | `track/routes.ts` + service                                   |
| 测试：Admin JWT completions；bootstrap 403；query 转发与非法 SQL          | `tests/llmPoolAdmin.test.ts` 扩展；`tests/adminTrack.test.ts` |
| 接口概览 §6.6 / LLM 节补两行                                              | `docs/nongyu-node-server/接口文档概览.md`                     |

**退出**：Node 测试绿；Admin Token 可打 completions（池可用时）；query 打到 mock/真实 Track 行为符合 Tech。

## 4. 风险与缓解

| 风险                             | 阶段 | 缓解                                                                         |
| -------------------------------- | ---- | ---------------------------------------------------------------------------- |
| Vite 打 SDK（jiaowu/second）失败 | S3   | 先 `pnpm --filter nongyu-agent-sdk build`；仍失败则停下来改 SDK 分包，不硬塞 |
| sqlguard 漏表名                  | S1   | 单测 + `mode=ro`                                                             |
| 平台日限与学生抢额度             | S5   | 空态/错误文案引导配 Key                                                      |
| 工具完整 rows 撑爆上下文         | S4   | 必须先做瘦身 Map，禁止把 500 行当模型 output                                 |
| 一人跨三端                       | 全程 | 严格 S1→S2→S5，避免前端先 mock 一套再对不齐契约                              |

---

## 5. 注意事项

- 工具 `execute` 每次现取 JWT，不闭包登录瞬间的 token。
- 中文注释：模块入口、sqlguard 规则、登出与 401 差异。
- 禁止 barrel `index.ts` 再导出一堆 UI（tools 的 `index` 仅合并 tools 对象可例外，与 RN `agent.ts` 导入方式对齐即可）。
- 不把 Track URL / Internal Token 写进前端。
- Bug 修复才写 `BugLog.md`；本期新功能不预写。
