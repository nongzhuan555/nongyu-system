## 1. 实施计划

一人交付；编码走 frontend-engineer（Ant Design + ECharts + 网格拖拽，对齐 `vercel-react-best-practices` 与 `design-system/web-admin/MASTER.md`）。**依赖** Node Track 代理已可联调（或先接 dashboard，Track 卡走错误隔离）。

| 步骤 | 内容                                                 | 风险 / 缓解                              |
| ---- | ---------------------------------------------------- | ---------------------------------------- |
| 1    | 类型、路径常量、`adminApi` 封装                      | 直接 import，禁止 barrel                 |
| 2    | localStorage prefs 读写 + 默认布局                   | try/catch；缺卡补默认                    |
| 3    | 网格页 + KPI / ECharts / 崩溃表                      | `react-grid-layout`；拖手柄在标题条      |
| 4    | 并行拉数、失败隔离、手动刷新、range 持久化           | `Promise.all` 分组，不用一条失败打挂整页 |
| 5    | 替换占位路由；工作台文案；lint / type-check / format | 删除或停用 Placeholder                   |
| 6    | Spec / 本计划状态改为已完成                          | 无                                       |

**改动面**：`apps/nongyu-web-admin/**` + 本计划与 Spec。图表不新增第二套可视化库。网格库仅 `react-grid-layout`（及 `@types/react-grid-layout`）。

**不写**：使用时间分布、dataZoom、按账号同步布局、工作台内嵌图表、调用 `/track/trend`。

## 2. 实施步骤

### 2.1 依赖

在 `apps/nongyu-web-admin` 增加：

- `react-grid-layout`
- `@types/react-grid-layout`（dev）

遵守仓库 pnpm workspace：只改该 app 的 `package.json`，在仓库根执行 `pnpm install`。引入库自带 CSS（`react-grid-layout/css/styles.css` 与 `react-resizable/css/styles.css`），可在大屏页或 `main.tsx` 按需 import，避免污染登录页可接受（管理端已登录壳内）。

### 2.2 类型与 API

```text
src/types/dashboard.ts
src/lib/dashboardPrefs.ts      # 读/写/校验 localStorage
src/lib/dashboardLayout.ts     # 默认 layouts、WIDGET_IDS、min 约束
```

`constants.ts`：

- `ADMIN_DASHBOARD_OVERVIEW_PATH` 等四条 dashboard
- `ADMIN_TRACK_OVERVIEW_PATH` 等四条 track（trend 可声明但不调用）
- `STORAGE_DASHBOARD_PREFS_KEY = "nongyu.admin.dashboard.layout.v1"`
- `AUTH_ERROR_CODES` 可增加 50201/50301 供文案判断（可选）

`adminApi.ts` 继续同一 axios 实例：

- `fetchDashboardOverview`
- `fetchUserGrowth(range)`
- `fetchUserDistribution`
- `fetchSettingsDistribution`
- `fetchTrackOverview`
- `fetchTrackDims({ metric, limit? })`
- `fetchTrackCrashes({ page, pageSize })`

### 2.3 页面结构（禁止在父组件内定义子组件）

```text
src/pages/DashboardPage.tsx
src/components/dashboard/DashboardGrid.tsx
src/components/dashboard/KpiCard.tsx
src/components/dashboard/ChartCard.tsx      # 标题条拖拽柄 + 错误/空/加载
src/components/dashboard/EchartsBlock.tsx   # 主题色、resize
src/components/dashboard/CrashesTable.tsx
src/components/dashboard/dashboardCharts.ts # option 工厂，非组件
```

- `AppRouter`：`DashboardPage` 替换 `DashboardPlaceholderPage`，删除占位页文件。
- `WorkspacePage`：副文案改为「查看运行指标与用户行为」，不再「即将开放」。

### 2.4 网格与 prefs

- `Responsive` + `WidthProvider`；breakpoints 与 Spec：lg 12 / md 8 / xs 4。
- `onLayoutChange` 防抖写入（仅 drag/resize stop 后写，避免拖拽中刷盘）。
- `draggableHandle` 指向标题条 class。
- `resize` 后对 ECharts `resize()`。
- 恢复默认：清 key，range=`7d`，套用默认 layouts，并重拉 growth。

校验逻辑按 Spec §4.4：非法 JSON / `version!==1` → 默认；未知 `i` 丢弃；缺失 id 补默认几何。

### 2.5 数据与交互

`DashboardPage` 进入时 `Promise.all` 分组：

- 组 A 本库：overview + distribution + settings + growth
- 组 B Track：track overview + screen_views + perf_p50 + perf_p95 + crashes

组内用 `allSettled` 或分请求 catch，使单接口失败只打对应卡。顶栏刷新重跑两组。增长 Select 只打 `user-growth`。崩溃分页只打 crashes。

ECharts 色板与 smooth 按设计准则。学院/页面横向柱 `dataZoom` **内部刷选不做**；项过多用 `grid` 留白 + 截断 Top 20（dims 已 limit）。

崩溃表：`pageSize=10`；时间用现有 format 工具（上海可读）。`props` 展示 message/stack 截断。

### 2.6 样式

卡片：`rounded-3xl bg-white shadow-card p-4 md:p-6`。KPI 主数字 `text-2xl font-semibold text-ink`，辅文 `text-muted`。窄屏内容区自然增高滚动。

### 2.7 验收命令

仓库根：`pnpm lint`、`pnpm type-check`、`pnpm format`（或按 husky 等价脚本）。手工：Spec §6 清单。

---

## 3. 注意事项

- 并行独立请求，避免 waterfall（组 A/B 同时启动）。
- 不把完整用户对象/崩溃 props 以外的敏感字段塞进图表 option。
- localStorage 失败不得白屏。
- 登录页不要被网格 CSS 明显破坏（若有，改为仅 DashboardPage import CSS）。
