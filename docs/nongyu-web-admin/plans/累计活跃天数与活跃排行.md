## 步骤

1. **Node · 迁移**
   - 新增 `users.active_days`、`users.active_day_bucket` + 索引
   - 同步 `数据库设计文档.md`

2. **Node · 累计逻辑**
   - 改造 `updateUserPresence`（及登录刷新 `last_active_at` 的路径，若独立存在）
   - 按 `BUSINESS_TZ` + `businessDayUtcRange().dateKey` 同日去重 +1
   - 单测：同日多次 / 跨日 / 用户不存在

3. **Node · 列表/详情**
   - `USER_COLS` / mapper 透出 `activeDays`
   - `listUsersAdmin` 支持 `sortBy=activeDays` + `sortOrder`，并列 `id ASC`
   - 路由 zod 校验；单测排序+分页

4. **Node · 排行 API**
   - `GET /api/admin/dashboard/active-days-ranking?limit=&order=`
   - 过滤 `status=1` 且 `active_days>0`
   - 写入 `接口文档概览.md`；单测 limit/order/过滤

5. **Web · 用户管理**
   - types / `listAdminUsers` query
   - UsersPage 列 + 服务端 sorter；窄屏次要信息；页头说明
   - UserDetailDrawer 展示 `activeDays`
   - 助手 list 透出字段（易改则加 sort 参数）

6. **Web · 数据大屏**
   - `chart-active-days-ranking` 加入 `WIDGET_IDS` + 默认布局（靠增长趋势）
   - adminApi + DashboardPage 拉数（失败隔离）
   - 柱状图 + Top 50/100/200 + 升降序（默认 desc）
   - 空态文案

7. **收尾**
   - Spec 状态改为已实现；必要处更新 `用户管理.md` / `数据大屏.md` 交叉引用
   - 自测验收清单勾选
