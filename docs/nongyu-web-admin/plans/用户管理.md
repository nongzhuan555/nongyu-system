## 2. 实施步骤

### 2.1 类型与 API

1. 新增 `src/types/users.ts`：`AdminUserListItem`、`AdminUserDetail`、列表 Query、`PageResult`（或与文档一致的内联类型）。
2. `src/lib/constants.ts`：补路径常量
   - `/api/admin/users`
   - `/api/admin/users/:id`
   - `/api/admin/users/:id/admin-password`
3. `src/lib/adminApi.ts` 增加：
   - `listAdminUsers(query)`
   - `fetchAdminUser(id)`
   - `patchAdminUser(id, { role?, status? })`
   - `setAdminUserPassword(id, adminPassword)`  
     继续走现有 `unwrapData` / 拦截器；禁止新建 axios 实例。
4. 小工具：`formatAdminDateTime(iso)`（空 → `—`）；性别枚举文案。

### 2.2 页面结构（禁止 barrel）

```text
src/pages/UsersPage.tsx                 # 列表 + 筛选项 + 打开抽屉
src/components/users/UserDetailDrawer.tsx
src/components/users/SetAdminPasswordModal.tsx
```

- 删除或停用 `UsersPlaceholderPage`：`AppRouter` 改为渲染 `UsersPage`。
- `ChangePasswordModal` 不硬改成通用组件；设密给他人用独立 Modal，避免混入「出厂默认密码仍可登录」文案。

### 2.3 列表页行为

- 状态：`keyword` / `role` / `status` / `page` / `pageSize=20` / `list` / `total` / `loading` / `error`。
- 关键词 `Input.Search` 或普通 Input + **300ms 防抖**；角色/状态 `Select` 立即请求。
- 任一筛选变化 → `page = 1` 再拉列表。
- `Table`：`rowKey=id`；`onRow` 点击打开抽屉；`pagination` 受控。
- 窄屏：`scroll={{ x: true }}` 或列 `responsive`，保证学号/姓名/角色/状态可见。
- bootstrap：若列表 403，展示 Spec 文案（先 App 建档），不白屏。

### 2.4 抽屉与写操作

- 打开时 `fetchAdminUser`；loading / error / 内容三态。
- 操作按钮按 Spec §4.3；`isSelf = detail.id === authUser.id`（`authUser.id === 0` 时无人可匹配为「自己」的真实用户，仅禁用逻辑按 id 相等）。
- 降权/禁用：`Modal.confirm` 文案按 Spec。
- 升权成功：刷新详情 → 打开 `SetAdminPasswordModal`。
- 任意写成功：Toast + 刷新详情 + 刷新列表（或乐观更新对应行）。

### 2.5 设密弹窗

- 校验 ≥8、两次一致；调用 `setAdminUserPassword`。
- 成功 Toast「管理员密码已更新」；不写存储、不 `console.log` 密码。

### 2.6 验证

- `pnpm --filter nongyu-web-admin type-check`
- `pnpm exec oxlint apps/nongyu-web-admin`
- 仅格式化本应用相关文件（勿全仓 `pnpm fmt` 误伤）
- 手工：筛选/分页、详情、升权设密、对自己降权禁用不可点、启用他人

### 2.7 文档

- Spec 状态 → **已实现**
- 本计划状态 → **已完成**
