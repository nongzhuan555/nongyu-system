## 1. 实施计划

一人交付。编码顺序：**Node Track → Node BFF → Web Admin**。分别用对应专家 subagent。跳过独立 Tech。

| 步骤 | 内容                                                                                                       | 风险 / 缓解                       |
| ---- | ---------------------------------------------------------------------------------------------------------- | --------------------------------- |
| 1    | Track：`perfDurations` 支持 `[from,to]`；`liveDims`/`dims` 路由接受 `from`/`to`；校验跨日仅 perf、跨度 ≤30 | 单测钉死「区间重算 ≠ 日分位均值」 |
| 2    | Track：单日回归保持；响应补 `from`/`to`                                                                    | 兼容只读 `items` 的旧调用方       |
| 3    | BFF：`dims` 透传 `from`/`to`；预校验；`mapDims` 映射 `from`/`to`                                           | 非法组合 400，可不打 Track        |
| 4    | Web：`perfRange` prefs；Select；按区间只重拉 perf                                                          | 与 growth Select 同风格；失败隔离 |
| 5    | lint / type-check / format；Track 单测；Spec/计划标完成                                                    | 无                                |

**改动面（预期）**

- `apps/nongyu-node-track-server/src/store/sqlite/metrics.ts`（区间样本 + 分位）
- `apps/nongyu-node-track-server/src/http/routes.ts`（dims Query）
- `apps/nongyu-node-track-server` 单测（新建或补齐）
- `apps/nongyu-node-server/src/modules/track/{routes,service,map}.ts`
- `apps/nongyu-web-admin/src/{types,lib/dashboardPrefs,lib/adminApi,pages/DashboardPage,components/dashboard/*}`

**不写**：Go Track、Web Vitals 区间、其它 dims 跨日、延长 purge、趋势折线。

## 2. 实施步骤

### 2.1 Node Track

1. 扩展 `perfDurations(store, from, to, filter)`（或新增 range 版）：`stat_date>=? AND stat_date<=?`。
2. `liveDims` / 路由：解析 `from`/`to`/`date`，按 Spec 校验；跨日仅 `perf_p50`/`perf_p95`。
3. 响应写入 `from`/`to`（单日二者相等）；`date` 单日保留。
4. 单测：多日样本 → 区间分位正确；非法参数 → 400。

### 2.2 Node BFF

1. `routes.ts`：`from`/`to` optional；成对与跨度、metric 校验。
2. `service.getTrackDims`：Query 转发。
3. `mapDims`：可选映射 `from`/`to`；`date` 仍可读。

### 2.3 Web Admin

1. 类型：`PerfRange = "1d" | "7d" | "30d"`；`DashboardPrefsV1.perfRange`。
2. `dashboardPrefs`：读写默认 `1d`。
3. `fetchTrackDims`：支持 `from`/`to`。
4. 工具函数：`perfRange → { from, to }`（业务日、含今天）。
5. `DashboardPage`：初始按 prefs 拉 perf；`onPerfRangeChange` 只重拉 perf + 写 prefs。
6. `DashboardGrid` / `chart-perf`：卡头 Select + 可选独立 `perfLoading`。

### 2.4 收尾

- `pnpm lint` / `type-check` / `format`
- Track 单测通过
- Spec + 本计划状态改为已完成

## 3. 注意事项

- 分位必须对原始样本重算，禁止合并日聚合 `daily_dims`。
- App 性能默认排除 `platform=web`，与现网一致。
- 原始事件约 30 天；UI 不提供超过 30 天的选项。
- 分支：按协作规范在对应项目分支开发（涉及 Track/Node/Admin 三端时按团队习惯拆 PR 或同功能一并合入主分支前自检）。
