# 代码检索策略（CodeGraph + Cursor 内置检索）

本规则约束 Agent 在本仓库中如何发现代码。目标：少工具调用、少无效读文件、结构问题优先走图。

## 可用能力

| 能力                                               | 来源                                                  | 擅长                                                     |
| -------------------------------------------------- | ----------------------------------------------------- | -------------------------------------------------------- |
| **CodeGraph MCP**（通常为 `codegraph_explore` 等） | `@colbymchenry/codegraph` 本地图索引（`.codegraph/`） | 符号关系、调用链、影响面、「X 如何工作」、跨文件结构     |
| **Grep / Instant Grep**                            | Cursor 内置                                           | 精确字符串、正则、错误文案、配置键、已知符号名的文本命中 |
| **Glob**                                           | Cursor 内置                                           | 按路径/文件名模式找文件                                  |
| **Read**                                           | Cursor 内置                                           | 在已定位文件后精读实现细节                               |

MySQL MCP 仅用于数据库探查，**不是**代码检索工具。

## 决策顺序（必须遵守）

1. **先判断问题类型**，再选工具；禁止一上来无目标地广撒 Grep/Read。
2. **结构 / 关系 / 影响面 → 优先 CodeGraph**（若 MCP 可用且仓库已有 `.codegraph/` 索引）：
   - 「谁调用 / 谁依赖 / 改这里影响哪」
   - 「这个模块/函数流程怎么串起来的」
   - 跨 `apps/*`、`packages/*` 的引用与 blast radius
   - CR / 重构前的影响分析
3. **精确文本 / 已知字面量 → Grep**：
   - 完整符号名、路由 path、env 键、中文/英文文案、错误码、特征字符串
   - CodeGraph 未命中或明显是「搜字符串」时
4. **找文件布局 → Glob**，再 **Read** 已锁定的少量文件。
5. **CodeGraph 不可用时**（MCP 未加载、索引缺失、工具报错）：退回 Grep + Glob + Read，并在回复中简短说明「未使用 CodeGraph，原因：…」。

## 反模式（禁止）

- 已用 CodeGraph 得到符号与源码片段后，再用 Grep「复查同一事实」刷屏。
- 为回答「谁调用 X」而逐个打开半个 monorepo。
- 同时开一堆探索子 Agent 做纯结构追问（应先 CodeGraph 一次）。
- 把 CodeGraph 用于纯格式/文案替换类任务（直接 Grep/编辑即可）。

## 与写码流程的关系

- 实现功能前：对涉及的核心符号/入口，优先 CodeGraph 摸清调用关系，再改代码。
- `code-reviewer`：涉及跨文件行为或 API 签名变更时，可用 CodeGraph 辅助影响面；仍以 Skills + `BUGBOT.md` 为审查标准。

## 索引维护（人类 / 安装后）

- 项目根执行：`pnpm exec codegraph init`（或文档指定的等价命令）生成 `.codegraph/`。
- `.codegraph/` 不入库（见 `.gitignore`）；本机索引，勿在 Win/WSL 间共用同一库目录。
- 大改目录结构或感觉结果陈旧时：重新 `init` / 按官方文档 sync。
